# 가화만사성 컴포넌트 라이브러리 v3 (2026-11-17)

작성: 컴포넌트 디자이너. 상태: **제안**(리드가 렌더링으로 확인 전). 토큰은 `design-system/tokens-v3.json`, 시트는 캔버스 `bumo-ds/project/components/` 아래 `.dc.html`.
단 하나의 기준은 DESIGN-SYSTEM-PLAN §0: 이 사람이 이 순간 무엇을 하려 하고, 무엇이 불안하고, 어떻게 느끼는가. 컴포넌트마다 아래 6가지를 같은 순서로 쓴다: (a) 용도·쓰지 말아야 할 때 (b) 상태 (c) 크기·간격 (d) 접근성 (e) 텍스트 규칙 (f) 앱 컴포넌트 대응.

가정: 화면 390x844, 단위 px = RN dp. 어르신 글자 20 이상, 자녀 16 이상. 시스템 글자 확대 150%를 모든 컴포넌트가 견뎌야 하므로 **고정 height 금지, minHeight만** 쓴다. 대비는 WCAG 상대휘도로 직접 계산. 아이콘·해님·도장·테이프는 슬롯(`[아이콘: 이름]` `[해님: 표정]`)으로만 표시하고 직접 그리지 않았다.

## 0. 공통 규칙 (모든 컴포넌트)
1. **한국어 텍스트**: 루트에 `word-break: keep-all`, `overflow-wrap: break-word`, `text-wrap: pretty`(제목·말풍선은 `balance`). 마지막 두 어절은 NBSP로 묶어 한 글자 orphan 방지. 앱(RN)은 CSS가 없으니 문구 데이터에서 처리(copy.ts에 `nbsp()` 제안).
2. **상태 7개**: 기본 / 눌림 / 비활성 / 로딩 / 오류 / 선택됨 / 확대150%. 해당 없는 상태는 해당 없다고 적는다. 추가로 **포커스**(스위치·키보드·보이스오버).
3. **색만으로 구분 금지**: 상태는 색 + 글자 + 아이콘·모양 중 둘 이상. 특히 주 버튼(갈색)과 위험(빨강)은 명도 대비 1.21로 거의 같다.
4. **눌림**: 색만 바뀜(움직임 없음, 100ms 이하). **비활성**: 이유를 글자로 한 줄 알림. **오류**: 흔들지 않음, 누구 잘못도 아닌 말투 + 다음에 할 일 1개.
5. **터치**: 어르신 64 이상(큰 버튼 72, 번호 칸 68), 서로 간격 12 이상. 자녀 48 이상(권장 56). 시각 크기보다 눌리는 영역(hitSlop)이 크다.
6. **모션**: 어르신 화면은 번쩍이거나 빠른 애니메이션 금지, 움직임은 300ms 이상. "동작 줄이기"에서는 움직임 제거(페이드만).
7. **슬롯 규칙**: 슬롯은 최종 에셋과 같은 크기(교체 때 레이아웃 불변). 라벨 글자 7~12px는 개발용이며 출시 빌드에 없음. 해님 88/72/56/40, 아이콘 32(버튼 안)/28(행 안)/40(박스 안)/26(탭)/64·48(뒤로)/48(닫기).

## 15. 레이아웃: 표준 화면 틀 `layout/CMP_screen_frame`, `CMP_coursehome_standard`, `CMP_coursehome_zoom150`
**구조** TopSafe(고정, 52 이상) → TopBar(선택, 고정) → **Body(스크롤, flex:1, minHeight:0)** → **BottomDock(고정)**. Body와 Dock은 겹치지 않는 형제(absolute 겹침 금지). Body 패딩 위 4 / 좌우 24 / 아래 24, 형제 간격 16. Dock 패딩 위 12 / 좌우 24 / 아래 max(28, insets.bottom), 주 버튼 1 + 보조 최대 1, 높이는 화면의 40% 이하. 확대 150%에서는 Body만 스크롤, Body 아래에 28 높이 페이드로 "더 있음"을 보여 줌.
**한 화면 한 일을 레이아웃으로** 주 행동 = Dock의 큰 버튼 1개. 보조 행동은 (1) 그 내용에 붙여 작게(읽어 주세요 = 말풍선 오른쪽 아래 64x64), (2) 본문 끝의 작은 링크(64 터치), (3) 꼭 필요하면 Dock 보조 버튼 1개. 큰 요소는 주 버튼 1 + 강조 카드 1(지금 할 것), 나머지 정보는 compact 한 줄. 박스류 1개.
**결함 해결 (코스 홈 증명 아트보드)**
| 결함 | 해결 |
|---|---|
| F1 단어 중간 줄바꿈 | 루트 keep-all + 상태 글자를 제목 위·아래 줄로(제목이 전체 폭) + 제목 balance + 마지막 두 어절 NBSP |
| F2 고정 버튼에 가려진 카드 | Body·Dock 분리(구조적으로 겹칠 수 없음). 100%에서는 내용 약 670 < Body 680(계산, 여유 10 미만 → 렌더링 확인 필요), 150%에서는 Body 스크롤 + 아래 페이드 |
| F4 밀도(큰 카드 3 + 큰 버튼 2 + 링크) | 큰 카드 1(지금) + compact 2, 큰 버튼 1(주), "읽어 주세요" 보조 버튼은 해님 말풍선 쪽으로, "내 기록 지우기" 링크는 본문 끝으로 |
**위험(명시): 코스 홈 표준(100%)의 본문 여유는 8px(본문 680, 내용 672 측정). 문구가 한 줄 늘면 스크롤이 생김. 그대로 둠.**
**코스 홈 계산(390x844)** 844 - TopSafe 52 - Dock(12+72+28=112) = Body 680. 내용: 4 + 날짜 32 + 말풍선 약 93 + 도장 카드 약 144 + 단계 목록 약 245(60+약 100+60+간격 24) + 링크 64 + 간격 4x16 + 아래 24 ≈ 670. 150%에서 Body 약 678(Dock 약 114)에 내용 약 1000 → 스크롤. **겉보기(줄바꿈·겹침·잘림)는 렌더링 미확인.**
**앱** `Screen({children})`(ScrollView 한 겹) → `Screen({top?, bottom?, children, scrollEnabled?})`로 교체: top·bottom 고정, children은 ScrollView 안. 기본 패딩 위 4 / 좌우 24 / 아래 24. 키보드가 올라오면 bottom이 따라 올라옴.
