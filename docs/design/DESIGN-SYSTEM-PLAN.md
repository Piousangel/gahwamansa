# 부모자식 디자인 시스템 계획 (2026-11-17)

사용자 지시: ① v3 색 방향 승인, ② **"우리만의 개성"**, ③ 아이콘·에셋·재사용 컴포넌트를 **'부모자식 팀'이 직접 만든다**(기성품이나 대충 그린 그림 금지), ④ **기획·UI·UX·글자 하나하나가 전부이고, 모든 판단은 사용자 관점**.

## 0. 단 하나의 기준: 사용자 관점
모든 결정은 "그 사람이 이 순간 무엇을 하려 하고, 무엇이 불안하고, 어떻게 느끼는가"로 답한다. 두 사용자를 구분한다.
- **어르신(60~80대)**: 앱을 잘 몰라도 혼자 끝낼 수 있어야 한다. 실수해도 혼나지 않는다. 한 화면에 한 가지 일. 작은 글씨·작은 버튼·빠른 애니메이션·낯선 영어/한자어가 장벽이다. 틀리면 "내가 뭘 잘못했나"로 느낀다.
- **자녀(30~50대)**: 바쁘다. 부모 상태를 3초 안에 알고, 죄책감 없이 한마디 건네고 싶다. 감시처럼 느껴지면 부모도 자녀도 쓰지 않는다.
- 모든 화면은 아래 질문에 답할 수 있어야 통과한다: ① 이 화면의 **단 하나의 일**은? ② 사용자가 방금 **무엇을 느끼는가**? ③ 다음에 **무엇을 눌러야 하는지** 1초 안에 보이는가? ④ 실패했을 때 **내 잘못처럼 읽히지 않는가**? ⑤ 글자·버튼을 못 보는 사람(확대 150%, 노안)에게도 되는가?

## 1. 글자 하나하나 (UX 라이팅 규칙)
- **단어 중간 줄바꿈 금지**(`word-break: keep-all`), 한 글자만 다음 줄에 남지 않게 한다(orphan 금지). 문장은 의미 단위로 줄을 나눈다.
- 어르신 문장은 한 문장 20자 안팎, 한 문장에 한 가지 일. 한자어·영어·약어(예: 로그인, 서버, 동의 → 쉬운 말)는 쓰지 않거나 풀어쓴다.
- 버튼은 **동사 하나**(예: "다 봤어요", "이걸로 정했어요"). 두 가지 의미("확인/취소")를 한 화면에 섞지 않는다.
- 오류 문구는 **누구 잘못도 아닌 말투** + **다음에 할 일 한 가지**. 기술 용어·코드명(rate_limited 등) 노출 금지.
- 숫자는 크게, 단위를 붙이고(5일 연속), 기호(·, /)는 최소화한다. 조사는 받침에 맞춰 바뀐다("나무가/나무를" 처럼). 템플릿 문구는 조사를 처리한다.
- 높임말 일관(해요체), 같은 개념은 같은 단어(예: "번호"로 통일, "코드" 혼용 금지 — 현재 어르신 문구는 "번호", 자녀 화면에서는 확인 필요).
- 라벨·자리표시(`[문구 확정 필요]` 등)는 시안 전용이며 출시 빌드에 남지 않는다.

## 2. "우리만의 개성" 정의 (탐색 시작점)
컨셉은 "해님이 안내하는 우리 집 앨범"이다. 지금 화면은 카드와 알약 버튼뿐이라 **앨범이 느껴지지 않는다.** 개성은 장식이 아니라 **반복되는 시그니처**로 만든다. 후보(디자인팀이 검증·취사선택):
1. **사진 모서리 꽂이·마스킹테이프**: 모든 사진·카드 모서리에 앨범 부착 요소.
2. **스티치 물결선**: 로바 가이드의 물결 구분선을 앨범 스티치로 해석한 구분선(섹션 구분, 로딩 진행 표시).
3. **해님 스티커 도장**: 연속일을 앨범 페이지에 붙이는 스티커로(일차마다 약간씩 다른 기울기).
4. **손글씨 메모**: 날짜·사진 제목·응원 한마디만 손글씨(읽기용 본문은 절대 아님).
5. **종이 결과 책등**: 화면 가장자리의 종이 질감/앨범 책등 느낌(성능·가독성 해치지 않는 범위).
6. **해님의 행동**: 말풍선만이 아니라 상태(기다림, 칭찬, 걱정)를 표정과 자세로 표현.
탐색 결과는 반드시 **실제 렌더링 시안**으로 비교하고, 가독성(대비·글자 크기)이 개성보다 우선한다.

## 4. 작업 순서와 검토 루프
```
[아이콘 문법·캐릭터 방향 확정] → [제작] → [리드가 실제 렌더링으로 확인] → [사용자 검토] → [재작업]
         ↑ 개성 후보 실험(렌더링 비교)                                              ↓
[컴포넌트(자리표시 슬롯로 병행)] → [에셋 연결] → [116개 시안 재작업] → [UX 감사 재검] → [개발 반영]
```
- **리드는 에이전트 결과를 실제 렌더링(Chrome으로 캔버스 열기)으로 확인한다.** 에이전트는 렌더링을 못 하므로 겉보기 결함(잘림, 줄바꿈, 겹침)은 리드 확인에서 잡는다.
- 에셋은 `design-system/assets/`(SVG 원본), 컴포넌트·시트는 새 캔버스 "부모자식 디자인 시스템"이 단일 원본이다.
- 앱 반영: SVG는 `react-native-svg`(+변환 도구)로 컴포넌트화하는 것을 제안하며 라이브러리 호환·번들 크기는 앱 개발이 검증한다(미확인).
