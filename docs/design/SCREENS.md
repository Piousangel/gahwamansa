# 화면 인벤토리 (디자인팀 전달용) · 2026-11-17

목적: "놓치는 화면 없이" 디자인하기 위한 단일 기준 문서. 출처는 앱 코드의 라우트(`app/src/app/*.tsx`), 서버 RPC(`supabase/migrations`), SPEC 완료 조건, 문구(`docs/team/copy.ko.json`)다.
상태 표기: **구현** 앱에 화면이 있음 / **서버만** 서버 함수는 있고 앱 화면이 없음 / **SPEC** 요구는 있고 서버·앱 모두 없음 / **미정** 결정 대기.
시안 표기: ✅ 확정 컨셉(M_) 시안 있음 / 🟡 구형 시안만(임시 해님 등, 재작업 필요) / ❌ 시안 없음.

## 0. 공통 규칙 (모든 화면)
- 확정 컨셉 "해님이 안내하는 우리 집 앨범". 토큰·컴포넌트·접근성은 `docs/team/designer.md`, 코드는 `app/src/ui/tokens.ts`.
- 어르신 화면: 본문 20 이상, 주요 버튼 높이 64 이상, 화면당 주요 버튼 3개 이하, 대비 4.5:1 이상. 자녀 화면: 본문 16 이상(미결정, 디자이너 제안값).
- **아이콘·캐릭터·그래픽은 전문 에셋 디자이너 산출물을 쓴다.** 에셋이 오기 전 시안은 `[해님]`, `[아이콘: 이름]` 라벨 자리표시를 쓴다.
- 문구는 `copy.ko.json`의 확정 문구를 쓴다. 없는 문구는 시안에 임시로 쓰되 "라이터 확정 필요"로 표시한다. "치매 예방/치료" 효과 표현 금지.
- 모든 화면은 아래 **상태**(기본 외 오류·로딩·빈·오프라인·확대 글자)를 각각 시안으로 만든다. 상태 누락이 가장 흔한 누락이다.
- 글자 크기 150%(시스템 설정 확대)에서도 버튼이 가려지거나 잘리지 않는 레이아웃을 한 화면 이상 샘플로 보여 준다(QA 기준).

## 4. 흐름(플로우) 시안 요구
디자인팀은 화면 낱장뿐 아니라 아래 **흐름 4개**를 연결해서 보여 준다.
1. 어르신 첫 연결: P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P3
2. 자녀 첫 사용: C0 → C1 → C2(코드 공유) → C3(대기) → C4(어르신이 연결되면)
3. 폰 교체 재연결: C7 → C2(재연결 코드) → 새 폰 P1 → P3(기록 유지)
4. 삭제: (어르신) P3 → P9 → P10, (자녀) C7 → C8 → C9
