## 화면별 설계 의도
- C0 로고 자리 + 카카오 버튼 자리 하나만. 어르신 진입 링크("번호 입력하기")를 둬서 어르신이 자녀 로그인 화면에 갇히지 않게 함.
- C1 3단계 안내로 "가족 만들기 → 번호 알림 → 어르신 입력"을 미리 보여 줌. 무료 기간 한 줄.
- C2 번호를 큰 6칸(Jua 44)으로, 공유가 주 버튼, 복사는 보조. 재연결은 NOTICE 배경+주황 테두리로 가입 코드와 시각 구분, 남은 24시간 명시, "새로 만들면 이전 번호는 사라져요"(서버: 대상당 활성 1개). 여러 개는 최신 1개 크게 + 나머지 4개 목록(서버: 가입 코드 5개 초과 시 가장 오래된 것 교체).
- C3 대기는 진행 단계 3줄(완료/진행 중/대기, 색+글자). 완료는 doneSoft 카드와 확정 문구 "연결됐어요! 이제 함께해요".
- C4 한눈에: 참여 완료 여부 → 연속일 → 오늘 고른 답(대화 소재) → 응원. 응원은 문구 2개 상시 + 8개 시트(정해진 문구만 선택, 자유 입력 없음). 거부 상태는 참여·연속일은 그대로 보이고 답 카드만 거부 문구. 연속이 끊겨도 "끊겼어요" 금지 → "어제까지 5일 연속".
- C5 사실(최근 선택) → 대화 제안 순서. "곧 유료" 카드는 NOTICE+actionDark 테두리, "지금은 무료로 볼 수 있어요" 병기. 하단에 로그아웃·계정 삭제 작은 링크(48 높이).
- C8 범위별로 위험 신호를 높임: child는 보통 카드, family는 4px 빨간 테두리 박스+'삭제' 입력, 사전 조회 실패는 family보다 더 강한 문구+"다시 확인하기"를 먼저 제안. 삭제 중엔 모든 버튼 비활성(취소 불가 가정).
- C9 해님 없음(삭제 화면 해님 금지 규칙과 일관). child는 "기록은 남아 있어요", family는 "엄마 기록도 지워졌어요"로 결과가 다름을 분명히.

## 사용자 결정·가정 (미결정)
1. 문구 충돌: 지시문은 거부 상태를 "답을 남기지 않기로 하셨어요", copy.ko.json은 "어르신이 답을 남기지 않기로 했어요", writer.md는 "어르신이 아직 준비 중이에요"(압박 완화). BRIEF 규칙에 따라 json 문구를 씀. 확정 필요.
2. 호칭: 화면은 "엄마"로 예시({호칭} 변수). 자녀가 호칭을 정하는 기능 유무 미결정(writer 미결 3번). 확정 문구 warm_day도 "엄마 덕분에"가 박혀 있어 변수화 필요.
3. 설정 탭(C7) 미결정: 리포트 하단 작은 링크 2개(로그아웃, 계정 삭제)로 진입. 로그아웃 화면·재연결 진입점(C2 reconnect 진입 위치)은 C7과 함께 결정. 시안 C2_reconnect는 홈 외 진입 가정으로 "뒤로" 버튼을 둠.
4. 어르신 진입 링크(C0 "어르신이세요?")와 P0 시작 화면의 분기가 중복될 수 있음. 그룹 A의 P0와 맞춰 하나만 남길지 결정.
5. 가족 삭제 후 어르신 폰에서 일어나는 일(연결 끊김 후 P1로 이동 여부)은 서버·앱 계약에 없음. C8·C9 문구 "엄마 폰은 다시 연결해야 해요/연결이 끊겨요"는 서버 cascade(profiles 삭제)에서 추론한 임시 문구, 사실 확인 필요.
6. 삭제 후 보관(카카오 식별자 30일 내 삭제 등 policy.md), 인증 계정이 서버에 남는 점은 시안에 쓰지 않음. 법적 고지 문구 확정 필요.
7. 응원 보내기: 하루 횟수 제한, 같은 문구 반복 허용, 보낸 뒤 사라지는지 미정. 시안은 "보냈어요" 완료 표시 후 같은 화면 유지.
8. 연결 감지 방식(푸시/폴링)과 C3 자동 전환 타이밍 미정. 시안은 "입력하면 화면이 바뀌어요"로만 안내.
9. 어르신 여러 명 연결 시 홈·리포트 구조(dev-app-notes 6e)와 형제 초대(C10)는 범위 밖, 시안 없음.
10. "곧 유료" 카드 탭 동작(C6 가격 시트)은 빌드 2라서 비활성 표현만 있음.
