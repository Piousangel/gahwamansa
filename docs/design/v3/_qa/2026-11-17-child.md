# 자녀 화면 디자인 품질 관문 (2026-11-17)

대상: `docs/design/v3/screens/child/` 13파일, 아트보드 45장(C2_codes 3장은 빌드 1 제외지만 함께 점검).
방법: 헤드리스 Chrome. 아트보드를 기기 폭·높이로 바꿔(320x640, 360x780, 390x844, 412x915, 430x932) 글자 100·150·200%로 다시 생성해 측정하고 스크린샷을 찍었다. 측정 항목은 가로 넘침(왼쪽·오른쪽), 하단 고정 영역(버튼·탭) 잘림, 본문 높이 60px 미만, 시트 위쪽 잘림. 단어 쪼개짐·과부·위계는 스크린샷을 눈으로 봤다.
스크립트: 세션 scratchpad `childgen/qa.py`(생성기 `screens.py`·`lib.py`). 저장소에는 넣지 않았다.

## 결과 (최종 회차)
칸 값: 문제 수 / 본문이 스크롤되는 아트보드 수(45장 중). 스크롤은 실패가 아니라 "본문만 스크롤"이 맞게 동작한다는 뜻이다. 주 버튼은 모든 칸에서 화면 안에 있다.

| 폭 \ 글자 | 100% | 150% | 200% |
|---|---|---|---|
| 320 x 640 | 0 / 25 | 0 / 40 | 0 / 43 |
| 360 x 780 | 0 / 5 | 0 / 26 | 0 / 33 |
| 390 x 844 | 0 / 1 | 0 / 16 | 0 / 28 |
| 412 x 915 | 0 / 0 | 0 / 11 | 0 / 26 |
| 430 x 932 | 0 / 0 | 0 / 4 | 0 / 23 |

## 눈으로 본 스크린샷
- 원본 크기 390 x 844(100%·대표 150%): 13파일 전부(C0, C1, C2_code, C2_codes, C3, C4_home, C4_home_states, C5, C6, C7, C8_child, C8_family, C9).
- 매트릭스 축소 시트(아트보드 45장씩): 200%x320, 100%x320, 150%x390, 100%x430은 최종 회차에서 봤다. 나머지 11칸(360·412 전부, 150%x320·430, 200%x390·430, 100%x390)은 최종 회차에서 측정만 했고 다시 보지 않았다(미확인).

## 남은 한계
- 320 x 640에 200%면 하단 버튼 영역이 화면의 약 45%(기준 40%)를 차지하는 화면이 있다(C2 버튼 2개+링크, C8 버튼 2개+이유 줄). 본문은 스크롤되고 주 버튼은 보인다.
- 버튼 등 화면 틀 글자의 1.5배 상한은 앱 설정(maxFontSizeMultiplier)이 있어야 성립한다(tokens에서 제안 상태, 결정 필요).
- NBSP 묶음은 앱(RN)에서 문구 데이터로 처리해야 한다. 폭이 모자라면 일반 공백으로 바꾸는 규칙이 필요하다.
- 폰트는 Google Fonts(Jua·Noto Sans KR)로 렌더했다. 앱 번들 폰트가 바뀌면 다시 찍어야 한다. 실제 폰 확인은 앱 단계 QA 게이트에서 한다.
- C2_codes(빌드 1 제외)는 150%·200%에서 번호가 두 줄로 나뉜다. 빌드 1 밖이라 고치지 않았다.
