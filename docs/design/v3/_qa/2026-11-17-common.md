# 공통 화면 품질 관문 결과 (2026-11-17, 3차)

대상: `docs/design/v3/screens/common/` 6파일(S1_error, S1_error_z150, S2_loading, S2_empty, P14_disconnected, flows). 기준: `docs/team/OPERATING.md` "디자인 품질 관문".

## 방법
- 헤드리스 Chrome으로 화면 10종(어르신 5·자녀 5)을 폭 5종(320x640, 360x740, 390x844, 412x915, 430x932)과 글자 100·150%(어르신은 200%까지)로 렌더. 아트보드 125개.
- 자동 측정: 아트보드 밖으로 나간 요소 수(가로 넘침), 잘린 요소(overflow 안 scrollWidth 초과), 버튼이 아트보드 안에 있는지, 하단 고정 영역 높이 비율, 본문 스크롤 발생 여부, 아트보드 안 20px 미만 글자 수.
- 눈 확인: 위 125개 아트보드 렌더(확대별 합본을 잘라서)와 게시 파일 6개 스크린샷을 모두 직접 봄. 본 파일: S1_error, S1_error_z150, S2_loading, S2_empty, P14_disconnected, flows + 확대별 합본 qa z1·z1.5·z2.

## 요약
- 125개 모두 통과(가로 넘침 0, 잘림 0, 버튼 화면 안). 아트보드 안 20px 미만 글자 0개. 하단 고정 영역 최대 32%(40% 이하).
- 본문 스크롤은 320·360 폭의 150·200%와 P14 어르신(2버튼)에서 생김. 320x640 100%의 P14 어르신은 마지막 안내 줄이 흐림 아래로 이어짐(스크롤로 봄).
## 고친 것(이번 라운드)
- 200%에서 P14 어르신 320 폭 하단 영역이 59%까지 커짐 → 버튼 글자 확대 상한을 150%로 둠(버튼 글자 48/39 유지). 수정 후 32%.
- 본문이 버튼 뒤로 잘려 보임 → 하단 고정 영역 위 28px 흐림 추가(컴포넌트 규격 15절 "더 있음" 페이드).
- P14 안내 "코스는 볼 수 있어요. 고른 답은 저장되지 않아요"가 문장 중간에서 줄이 갈림 → 두 문장을 줄바꿈으로 나눔.
- 머리말 서비스명 "부모와 자식" → "가화만사성"(생성기 원본도 수정). flows에서 C2_codes 칸 제거, 화면 이름을 확정 용어(사진 보기·둘 중 고르기·글씨 쓰기)로 통일.
## 남은 것
- 실제 폰·RN 렌더는 앱 단계 QA 게이트에서. Google Fonts 로드 기준이라 글꼴 번들 시 폭이 달라질 수 있음.
- 320x640에서 어르신 상태 그림(240x180)이 화면의 약 30%를 차지. 작은 화면에서 그림을 줄일지는 해님·상태 그림 담당 결정(이번 지시로 손대지 않음).
