# 첫 화면 개선안 D·E·F 품질 관문 (2026-11-17)

대상: `docs/design/v3/first-screen/FS_D.dc.html`(앨범 펼침, 추천), `FS_E.dc.html`(하루 코스 잇기), `FS_F.dc.html`(하늘 창).
방법: Playwright(Chromium)로 렌더. 폭 320x640, 360x780(갤럭시 S25), 390x844, 412x915, 430x932 x 글자 100/150/200% = 안마다 15개, 총 45개 아트보드. 모두 직접 봤다(`first-screen/_render/qa_*.png` 9장).
모션은 시간을 멈춘 프레임(0/300/650/1100/2000ms)으로, 동작 줄이기는 0/150/300ms로 봤다(`_render/motion_*.png` 4장).
확대 규칙은 현 앱과 같게 했다: 본문 상한 2.0, 28 이상 글자·버튼 상한 1.5, 130% 이상 사진 숨김, 150% 이상 항목 숨김, 하단 고정 영역 최대 60%(넘치면 그 안에서 스크롤).

## 눈으로 확인하고 고친 것
1. 360x780에서 처음에 사진이 숨었다(영역 112 < 기준 128). 아이콘 원 40→36, 행 간격·제목 위 여백을 줄이고 틀 아래 띠를 36→30으로 줄여 영역 144가 되어 사진이 나온다(D).
2. 150%·200%에서 제목이 "하루 한 장, 우리 집 / 앨범"으로 한 단어만 넘어갔다 → "우리 집 앨범"을 NBSP로 묶어 "하루 한 장, / 우리 집 앨범".
3. E에서 사진이 숨을 때 해 원만 떠 있었다 → 해 원을 사진 묶음 안에 넣어 같이 숨김.
4. F 360에서 사진 영역이 빈 칸으로 남았다 → 사진은 숨기고 하늘 판(해·언덕)은 남김. 그래도 실기기 폭에서 사진이 안 나와 F는 추천하지 않는다.

## 남은 문제 (이번 개선 범위 밖, 현 앱에도 있음)
- **150%·200%에서 둘째 버튼이 하단 영역(60% 상한) 안에서 잘려 스크롤해야 보인다**(360·390·412). 이때 본문은 제목만 남아 위가 비어 있다. 제안: 글자 130% 이상(사진·항목을 숨긴 상태)에서는 하단 영역 상한을 풀거나 80%로 올린다.
- 320x640 100%에서 버튼 제목이 "부모님 / 휴대폰이에요"로 두 줄이 되어 하단 영역이 60%를 채우고 본문이 스크롤된다.
- 웹 글꼴(Noto Sans KR)이 기기 글꼴보다 넓어, 360에서 "옛날 사진 / 보며 추억을 떠올려요"로 두 줄이 된다. 실기기 15-first.png에서는 한 줄(약 249dp, 원 36+간격 10을 더해도 폭 266 안). 실기기 확인 필요.
