# 첫 화면 시안 3안 품질 관문 (2026-11-17)

대상: `docs/design/v3/first-screen/FS_A.dc.html`(누구 폰, 카카오), `FS_B.dc.html`(행동, 토스), `FS_C.dc.html`(브랜드, 배민), 심볼 `design-system/assets/symbol-sun-polaroid.svg`.
문구는 패널 제안을 그대로 썼고, 라이터 확정 전이다(각 파일 상단 주석에 적어 둠).

## 방법
- 헤드리스 Chrome으로 렌더했다. 화면 크기는 360x740, 390x844, 430x932이고, 글자는 100%와 150%(글자 크기 곱하기)다. 3안 x 3크기 x 2배율 = 아트보드 18개.
- 자동 측정 항목: 가로 넘침(아트보드 밖으로 나간 요소), 잘림(scrollWidth 초과), 20px 미만 글자, 본문 스크롤 여부, 하단 고정 영역(dock)의 높이와 비율, 버튼 높이.
- 눈 확인: 18개 아트보드 합본 2장(100%, 150%)과 심볼 5크기(192/64/48/32/24)를 직접 봤다.
- 하단 여백은 64로 잡았다(16 + 안드로이드 3버튼 내비게이션 바 48, 가정).

## 렌더로 발견해 고친 것
1. **C 360x740 100%**: "가족에게 번호를 보낼게요"가 두 줄로 넘어가 dock이 42%가 됐고, 질문 "어떻게 시작할까요?"가 흐림 아래로 가려졌다. 폴라로이드를 228에서 204로 줄이고 버튼 좌우 여백을 20에서 14로 줄여 해결했다.
2. **150%에서 dock이 최대 71%**(버튼 높이 221)였다. 버튼 글자 확대 상한을 제목 1.3배, 둘째 줄 1.25배로 두고 버튼 위아래 여백을 8로 줄였다. 확대 후에도 글자는 각각 39·25px라 100%보다 크다.
3. **150%에서 A·C의 핵심 질문이 본문 스크롤 아래로 숨었다**(A 360 "누구 거예요?"가 반쯤 잘림). "본문이 넘치면 ① 한 줄 설명 → ② 폴라로이드 순으로 숨긴다"는 규칙을 넣어 질문이 항상 보이게 했다. 카카오 패널의 "스크롤 대신 상단 문구가 줄어들도록"과 같은 방향이다. 앱에서는 onLayout 측정으로 같은 순서를 적용하자고 제안한다. 시안의 숨김 조건은 이 세 크기에 맞춘 값이다.
4. A 360 100%에서 "가족 사진을 같이 모아 / 보는 앨범이에요"처럼 줄이 의미 단위 밖에서 갈렸다. "모아 보는"을 붙여(NBSP) 고쳤다.
5. 심볼은 24~32px에서 해가 너무 작았다. 사진 창과 해를 키우고(해 반지름 7→8.5, 광선 굵기 3.2→3.6) 다시 봤다. 32px에서는 해로 읽히고, 24px에서는 겨우 읽힌다.

## 남은 문제 (결정 필요)
- **150%에서 dock이 40%를 넘는다**(A·C 360 55%, B 360 49%, B 390 43%, C 390 44%). 원인은 버튼 2개가 각각 두 줄 이상이라서다. components/README §15의 "dock 40% 이하"와 충돌하므로 둘 중 하나를 정해야 한다. ① 첫 화면은 예외로 인정하고 위쪽 문구를 숨긴다(지금 시안). ② 150%에서 둘째 줄의 확대 상한을 더 낮춘다.
- 150%, 360 폭에서 버튼 제목이 "부모님 / 휴대폰이에요"처럼 줄바꿈된다(의미 단위라 허용했다).
- C의 사진은 base64로 넣었다(480px로 줄인 사본, 약 86KB). 앱에서는 서버 사진을 써야 한다. "AI가 만든 그림"은 사진 아래 20px #85592F(종이 위 5.47)로 표기했다.
- 카카오가 제안한 버튼 왼쪽 얼굴 실루엣 아이콘은 아이콘 담당 몫이라 넣지 않았다.
- C의 주 버튼 제목은 SYNTHESIS 표를 따랐다(배민 원문은 "받은 번호가 있어요"). 보조 버튼 둘째 줄은 배민 원문에 없어 토스 문구를 빌렸다.
