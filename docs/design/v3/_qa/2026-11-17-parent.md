# 어르신 화면 품질 관문 · 2026-11-17 (3차 수정)

범위: docs/design/v3/screens/parent/ 12개 파일(P0~P10, P13), 아트보드 전부.
방법: 헤드리스 Chrome으로 측정. 각 파일의 모든 보드를 확대 배율(100·150·200%)로 강제 생성한 뒤 폭 320·360·390·412·430에서 쟀다(12파일 × 3배율 × 5폭 = 180회, 실패 0회).
- 넘침: 보드 밖으로 나간 요소(장식 SVG 안쪽 경로 제외)
- 잘림: 버튼·키 글자가 버튼 밖으로 나감(scroll > client)
- 쪼개짐: 한 단어가 두 줄에 걸침(단어별 Range 측정)
- 과부: 마지막 줄이 1글자
- 하단: 하단 고정 영역이 화면 높이의 40% 초과, 또는 주 버튼이 화면 밖
- 본문 세로 스크롤은 150·200%에서 설계상 허용한다(본문만 스크롤하고 아래쪽은 페이드로 이어짐을 알림). 주 버튼은 모든 조합에서 화면 안에 있다.

눈으로 본 것: 12개 파일의 모든 아트보드(86장, 100·150·200% 보드 포함)를 폭 390·320·430 세 폭으로 렌더해 행별로 직접 봤다(4차). 측정에서 실패가 났던 조합인 P3 150·200% × 폭 320·360도 따로 찍어 봤다. 폭 360·412는 측정만 했다(320·430 극단 폭 사이 값).

## 남은 문제
1. (해결, 4차) P3 3/3 말풍선 "여기까지예요." 쪼개짐: 말풍선이 가장 긴 어절보다 좁아지면 해님 아래 줄로 내려가게 바꿨다(해님 그림·말투 그대로). 150·200% × 320·360 재측정 통과, 눈으로 확인.
2. 가정: 24px 이상 큰 글자(제목·버튼)는 200%에서 1.5배까지만 커지는 것으로 그렸다(안드로이드 14 비선형 글자 확대 방식). 본문 20~22px는 그대로 2배. iOS·토스 웹뷰의 실제 배율은 실기기에서 확인 필요(QA 게이트).
3. 200%에서 P4 회상 질문, P5 선택 카드, P2 동의 셋째 줄은 첫 화면에 안 보이고 본문을 스크롤해야 보인다(페이드로 단서만 줌). 어르신이 스크롤을 알아차리는지 미확인.
4. 확인 상자 보드(P9 2단계, P13 2장)는 뒤 화면 버튼까지 세면 주요 버튼 4개(실제 누를 수 있는 것은 2개).
5. 폭 360·412는 측정만 했다.

## 5차: P1 보정(리드 결정 ①)과 상단 "이전" 바
- P1: 상단 "이전" 바(README §19(c)), 하단 고정 영역 = 이유 줄 + 주 "다음" + 링크 줄("번호가 없어요"·"코스 보기"), 번호 칸·키패드 §19(a) 규격. 확대 시 이유 줄은 본문 끝으로 옮겨 하단 높이 40% 이하 유지.
- 모든 단계·설정 화면(P4·P5·P6·P9·P13) 상단 바의 뒤로를 아이콘 단독에서 "아이콘 + 이전"으로(§19(c) "아이콘만 단독 금지").
- 재측정 180조합 통과. P1·P4·P5·P6·P9·P13을 폭 320·390·430으로 다시 찍어 눈으로 확인. P3 시안은 제목 없이 유지(QA-P3 결정 참고), 변경 없음.
- 남은 문제: P1 폭 320·100%에서 키패드 마지막 줄 일부가 본문 스크롤 아래(높이 844 가정). P5·P6 150% 이상에서 "2 / 3"이 제목 아래 줄로 감(의도된 줄바꿈).
