# 10. 마스터 계획 v2: 화면군별 디자인 확정 → 개발 → 승인 (PM, 2026-11-17)

## 1. 순서 원칙
1. **디자인·기획 확정**: 아티팩트에 군의 전 화면·전 상태(기본·로딩·빈·오류·오프라인·150·200%·읽기 순서·모션·햅틱·소리)+확정 문구. 임시 문구 0
2. **독립 리뷰**: UX 감사관(놓침·어색함·우아함) + 라이터 + 정책, "빼도 되는 것" 포함 → 통과 시 **디자인 동결**(새 아이디어는 다음 군·빌드2 큐)
3. **개발(TDD)**: 테스트 먼저, 서버 pgTAP, tsc·lint·jest·통합 + 코드 리뷰. RPC는 하위 호환 유지, 깨지면 새 이름(테스트 중 옛 빌드 보호)
4. **캡처**: 실기기 = 전 화면 360·100% + 최악 조합 320·200% + TalkBack. 나머지 폭·배율은 에뮬레이터. 다크(라이트 고정)는 각 QA 표의 한 칸
   - **실기기 캡처일 = 평일 월·수·금 묶음**(사용자 폰 USB 연결 가능 시간 가정, **평일 가능 시간 사용자 확인 필요**). 주말은 에뮬 캡처로 1차 판정만
5. **디자인 QA 승인**: 시안 담당이 `device-review/QA-<화면>.md`에 "승인"
