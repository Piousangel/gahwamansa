# 11. 운영 백오피스 기획 (PM, 2026-11-17 · 기획만, 구현은 앱 완성 후)
근거: 사용자 원문 "앱 완성도 있게 만든 다음에는 운영 백오피스도", DECISIONS 11-17(환경 분리·백오피스·AI 표기), 10 마스터 ⑦, 09 환경, migrations 0001~0018, scripts/photos, growth.md §3. 숫자는 모두 **추정(가정)**.

## 0. 현재 구조에서 나온 사실 (기획 전제)
- 콘텐츠 = `content_photos`(사진·caption·**keyword=낱말**·recall_questions) + `content_questions`(prompt·A/B), `day_index` 1~30 고정 상한, 지금 14일분. 날짜 발행이 아니라 **어르신별 순환**: `mod(오늘 - course_start_date, n) + 1`
- 따라서 **"예약 발행"을 날짜로 하면 안 된다**: 15일차를 추가하는 순간 n이 14→15로 바뀌어 15일 이상 쓴 어르신의 "오늘" 순번이 한꺼번에 밀린다(같은 사진 재등장·건너뜀). 콘텐츠 추가 전 순번 계산 변경이 선행 조건(§4)
- 사진: Gemini 생성(`gen-photo.mjs` → `content/photos-raw`) → 사람 검수 → `content/photos/day-NN.jpg` → `upload-photos.mjs`(service role 키, 공개 버킷 `content-photos`, 2MB·jpeg) → `image_url` 갱신. 검수 기록·AI 고지 체크가 파일 밖에 없음
- 사용자 글은 없음: 응원은 정해진 문구 키(`message_key`), 자유 입력은 호칭 20자뿐. → 신고·차단은 **빌드1 불필요**, 호칭 이상 시 수동 처리로 충분
- 삭제: 앱 안 `delete_my_account`(본인·마지막 자녀=가족 전체)가 있음. Play "웹 삭제 요청 URL"로 들어오는 요청은 처리할 곳이 없음
- 지표: `events` 테이블은 0022 예정(퍼널 8단계, 글 내용 금지). 푸시 발송 기록은 0024~0025 설계에 포함 필요. 공지 테이블 없음

## 2. 개인정보 원칙
- **답 원문 기본 비노출**: 운영 화면은 집계만(문항별 A/B 비율은 응답 20명 이상일 때만). 가족·어르신 단위 답·응원 목록 화면은 만들지 않는다
- 개별 가족 조회는 삭제·문의 처리에 한정, 이메일 일부 가림, 조회 사유 입력 필수 → **접근 기록**(`admin_audit`: 누가·언제·무엇을·사유), 기록은 운영자도 삭제 불가
- **2단계 인증**: Supabase Auth MFA(TOTP), 관리자 함수는 `aal2` 세션에서만 실행
- **권한 분리**: owner(삭제 실행·권한 부여) / editor(콘텐츠) / viewer(지표). service role 키는 서버(또는 사용자 맥 스크립트)에만, 브라우저 금지
- production 데이터는 staging으로 복사 금지(09 §5). 관리자 계정은 앱 사용자 계정과 분리(같은 이메일로 가족 가입 금지)

## 3. 기술 선택지 (가격·정책은 가정, 확인 필요)
| | A. Next.js 관리자 웹 + Supabase(관리자 RPC, service role은 서버만) | B. Supabase Studio 직접 + SQL 스니펫·스크립트 | C. Retool류 |
|---|---|---|---|
| 비용 | 0~월 $20(Vercel Hobby는 상업용 금지로 알려짐 → Pro 또는 **사용자 맥 로컬 실행**이면 0) | 0(Pro 요금에 포함) | 무료 5명 안팎, 이후 사용자당 과금(가정) |
| 보안 | 화면별 최소 권한·MFA·접근 기록 강제 가능 | 전 테이블 원문 열람 가능(원칙 2와 충돌), 접근 기록·권한 분리 약함 | 데이터가 제3자 경유 → 방침에 위탁 추가, DB 접속 정보 보관 |
| 속도 | 첫 화면 3개 12~18h(사용자 Next.js 숙련) | 즉시, 스니펫 2~3h | 4~8h, 커스텀 로직은 결국 RPC 필요 |
- **추천: 단계형.** 빌드1(출시 전)은 **B + 스크립트**(새 화면 0, 위험 최소, prod 접속은 사용자 1인이라 원칙 위반 범위 작음). 출시 후 운영이 반복되면 **A를 사용자 맥 로컬 실행으로 시작**, 운영자 2명이 되면 배포(Vercel Pro 등). C는 개인정보 위탁·고지 부담 대비 이점이 적어 비추천
