# 기획 v2 — 취향이 쌓이는 앨범 · 말로 하는 코스 (PL-1 기획, 2026-11-26)

- **왜**: 오너가 3일 시나리오(#281)를 읽고 기획 방향 10가지를 줬다(리드 전달, 11-26). 이 문서는 오너가 **결정할 수 있게** 안과 근거를 모은다. 결정은 오너가 하고, 리드가 DECISIONS에 적는다.

  1. H1 알림 권한을 앱 시작 단계에서 묻는다 — 개발 레인이 따로 맡음
  2. H2 그대로 둔다(첫 답은 지난 날 목록에서 보면 됨)
  3. H3 21시 이후 알림 처리 확인 — 개발 레인

  6. 카톡 링크 자동 채움을 원함
  7. Android·iOS 둘 다 잘 돌아가야 함
  8. 5단계 중 ①~④를 어르신이 **말로** 할 수 있으면 좋겠다(스픽·말해보카 참고)

  10. 중심 개념: 어르신은 매일 자기 할 일을 하고, 자식은 따로 묻지 않고도 취향을 알아서 "우리 어머니가 바다를 좋아하시지" 하고 바다에 모시고 간다
- **이 문서가 다루는 것**: 1~4·10은 결정 항목으로 아래 절에 정리했다. 1·3은 개발 레인 몫이라 순서표(8절)에만 넣었다.

## 1. 중심 개념 다시 쓰기

### 1.1 한 문장 정의 (안)
> **어르신은 매일 옛날 사진 한 장으로 자기 시간을 보내고, 그동안 고르신 것이 쌓여 자녀에게 '부모님 취향'으로 보인다. 자녀는 따로 묻지 않아도 그 취향으로 함께할 일을 고른다.**

- 지금 정의(스토어 A안·전략 v3): "고르신 답이 노란 팻말로 가족에게 → 그 답으로 말을 건다"(`marketing/strategy.md`, DECISIONS 11-20 '마케팅 v3').
- 바뀌는 점: **'오늘 답 → 오늘 대화'에서 '쌓인 취향 → 함께할 일'**로 옮겨 간다. 대화를 꼭 하지 않아도 된다.

### 1.3 자녀 화면 안 (취향이 쌓여 보이는 모습)

**안 A — 취향 낱말 묶음(자주 고르신 것)**
```
┌ 우리 집 앨범 ─────────────── 설정 ┐
│ 엄마가 요즘 마음 가는 쪽            │
│                                    │
│  [가을]  [바다]  [라디오]  [숭늉]    │  ← 노란 팻말, 많이 고른 것이 앞
│  [시골길] [옛날 노래]               │
│                                    │
│ 이번 달 고르신 것 12가지 중         │  ← 횟수 대신 '가지 수'만(참여율 아님)
│                                    │
│ ┌ 함께 해 볼 일 ─────────────────┐ │
│ │ 바다 쪽 나들이를 골라 봐요       │ │  ← 제안 1줄(라이터)
│ └────────────────────────────────┘ │
│ 오늘 고르신 쪽 · 가을               │  ← 오늘 답은 작게
│        [ 응원 보내기 ]              │
└────────────────────────────────────┘
```
- 데이터: 지금 저장하는 **고른 답(answers의 보기 글자)** + ② 떠올린 낱말(5단계)만으로 된다. 같은 낱말을 센다.
- 한계: '봄 vs 가을'처럼 보기가 낱말 하나일 때만 잘 묶인다. '라디오 듣기 / 텔레비전 보기'는 그대로 쌓인다.

**안 B — 갈래별 취향 지도(계절·장소·먹을거리·소리·놀이)**
```
┌ 엄마의 취향 ───────────────────────┐
│ 계절   가을 ●●●  봄 ●              │  ← 점은 3개까지만(숫자 없음)
│ 장소   바다 ●●   시골 ●●            │
│ 먹을거리 숭늉 ●  식혜 ●             │
│ 소리   라디오 ●●                   │
│                                    │
│ 함께 해 볼 일 › 가을 바닷가 나들이   │
└────────────────────────────────────┘
```
- 데이터: **새로 필요**. 보기마다 갈래 표(예: option_a_tag='계절:가을')를 콘텐츠 표에 더해야 한다. 지금 season·place·era 태그는 **시드 파일 주석에만** 있고 DB 열이 아니다(DECISIONS 11-18 '맞춤 콘텐츠' — "마이그레이션 0").
- 콘텐츠 30일 × 보기 2개 = 60개 갈래 매기기(라이터, **추정** 반나절) + 서버 열 1개 + 집계 함수.

**안 C — 계절 달력(그 계절에 고르신 것)**
```
┌ 엄마의 사계절 ─────────────────────┐
│ 이번 가을  가을 · 바다 · 숭늉 · 라디오│
│ 지난 여름  (아직 없어요)            │
└────────────────────────────────────┘
```
- 데이터: 고른 답 + 날짜로 된다. 다만 **31일 파기** 때문에 지난 계절이 남지 않는다(1.5). 보관 기간을 늘리기 전에는 '이번 달' 한 칸뿐이다.

- **권장: 안 A로 시작해서, 콘텐츠 갈래 표가 생기면 안 B로 키운다.** 안 A는 서버·데이터 추가 없이 앱 집계만으로 된다(**추정** 앱 2~3일). 안 C는 보관 기간 결정 뒤.
- 덧붙임: 지금 C5 '이야기 주제 추천 · 곧 유료'의 유료 후보가 이 '취향 정리'가 될 수 있다(**추정**, 오너 질문 Q8).

### 1.4 다른 결정과 부딪히는 것
- **DECISIONS 11-18 '맞춤 콘텐츠: 고른 답으로 추론 안 함'**: 그 결정은 '콘텐츠를 고를 때' 고른 답을 쓰지 않는다는 뜻이다. 자녀에게 쌓인 답을 묶어 보이는 것은 다른 문제지만, **'취향'이라는 이름은 추론처럼 읽힌다** → 화면은 '자주 고르신 것'처럼 사실로만 쓰고, 성격·건강 같은 해석 문장은 두지 않는다.
- **⑤ 삭제와 0061**: 서버의 ⑤ 저장(`save_pass_on`, `pass_on_store_enabled` 기본 꺼짐)은 꺼진 채로 둔다. 테스터 빌드에는 ⑤ 단계를 아예 그리지 않는다(앱 변경 필요, **추정** 0.5~1일). 표를 지우는 마이그레이션은 v2가 확정된 뒤에 한다.
- **3일 시나리오 빈틈 M5(엄마는 돌려줄 길 없음)**: 오너가 '안 함'으로 정했으므로 닫는다.

### 1.5 윤리·법률 경계 — "의식하지 않아도 되지만, 분명히 안다"
오너 표현 "보여지는 걸 크게 인지하지 않는 상태"는 **'몰래'가 아니라 '한 번 분명히 정한 뒤 매일 신경 쓰지 않아도 된다'**로 옮긴다. 아래를 지키면 지금 원칙과 충돌하지 않는다.

| 지킬 것 | 지금 있는 장치 | v2에서 필요한 것 |
|---|---|---|
| 동의는 분명히, 한 번 | P2 세 줄 + [좋아요]/[싫어요] 같은 무게, 거부권 먼저(#175) | P2 첫 줄을 '쌓인 취향'까지 말하게 바꿈. 예: "고르신 것이 모여 가족에게 '좋아하시는 것'으로 보여요"(**라이터·법률 확정 필요**). `CONSENT_VERSION` 올림 → 기존 동의자 재동의(needs_reagree, DECISIONS 11-19) |
| 언제든 볼 수 있음 | 설정 '가족에게 이렇게 보여요'(P13p) | 미리 보기에 취향 화면을 그대로 보임 |
| 언제든 그만 | '그만 보여 주기' → 지난 답 지움(P13-2) | 취향 묶음도 함께 사라짐(같은 데이터라 자동) |
| 안 한 날은 안 보임 | 동의 body[1], 넘긴 날 무표시 | 취향 화면에 날짜별 빈칸·횟수·'이번 주 n번' 없음. '가지 수'도 넣을지 Q2 |
| 매일 의식하지 않아도 됨 | — | 매일 "가족이 봐요" 같은 말을 띄우지 않는다. 대신 **한 달에 한 번** 코스 홈 위에 "가족에게 이렇게 보여요" 한 줄 다시 보여 주기(**제안**) |
| 감시로 보이지 않음 | guardrails 1절('오늘 했는지 확인' 금지), U11 | 취향 화면에 '마지막으로 한 날'·'오늘 했어요' 같은 표시 금지. 자녀 알림은 지금처럼 연결·첫 답·응원만 |
| 보관 기간 | 고른 답 31일 파기(0023), '더 오래 보관' 선택은 법률 확인 뒤(DECISIONS 11-20 O-D) | 안 A·B는 31일 안에서도 된다. 계절·해마다 쌓이게 하려면 **보관 연장 = 새 동의 항목 + 방침 개정 + 공식 상담**(L-10과 같은 질문 꼴, 새 ID 필요) |
| 민감정보로 번지지 않음 | 보기에 건강·종교·정치·출신·가족사 금지(법률 4.3) | 취향 묶음에서 해석 문장(성격·건강 추정) 금지 |

## 2. 오늘 코스 v2 구조 (요약)

```
① 사진 보기 ──▶ ② 떠올려 보기 ──▶ ③ 둘 중 고르기 ──▶ ④ 낱말 ──▶ ⑤ (대체 콘텐츠, 4절) ──▶ P7
   말로 답하기      말로 고르기         말로 고르기        소리 내 읽기     예: 내일 사진 고르기
   (누르기도 됨)    (누르기도 됨)       (누르기도 됨)      (쓰기도 됨)
```
- 넘어가기 「오늘은 넘어갈게요」·「오늘은 여기까지 할게요」(③ 뒤)·이어 하기는 5단계 결정 그대로(DECISIONS 11-25).
- **말로 하기는 늘 '하나 더 있는 길'**이다. 누르기·쓰기 길을 없애지 않는다(3.2).

## 3. ①~④ 말하기

### 3.1 참고 앱에서 가져올 것 / 가져오지 않을 것
| 앱 | 확인한 것 | 가져올 것 | 가져오지 않을 것 |
|---|---|---|---|
| 스픽(Speak) | 첫 수업부터 말하게 하고, 발음·표현에 바로 피드백, AI와 대화([speak.com](https://www.speak.com/), [App Store](https://apps.apple.com/us/app/-/id1286609883)). 발음 점수가 너그럽다는 후기와 정확하다는 후기가 엇갈림([languatalk 리뷰](https://languatalk.com/blog/speak-app-review/), [hellotalk 리뷰](https://www.hellotalk.com/en/blog/speak-review)) | **누르면 바로 말하는 큰 버튼, 말한 것이 글자로 바로 보임** | 발음 점수·정확도 평가 — 우리에게는 '기억·말 시험'으로 읽힌다(writer 1-2 '정답·오답 금지', guardrails '두뇌 훈련' 금지) |
| 말해보카 | 앱 설명에 '스피킹 모드로 회화 연습'([App Store](https://apps.apple.com/kr/app/%EB%A7%90%ED%95%B4%EB%B3%B4%EC%B9%B4-%EC%98%81%EB%8B%A8%EC%96%B4-%EB%AC%B8%EB%B2%95-%EB%A6%AC%EC%8A%A4%EB%8B%9D-%EC%8A%A4%ED%94%BC%ED%82%B9-%EC%98%81%EC%96%B4-%EA%B3%B5%EB%B6%80/id1460766549)). 음성 인식 방식·채점 방식은 **확인 필요**(공식 설명 없음) | 낱말 하나를 소리 내 말하는 짧은 반복 | 점수·순위·연속 학습일 |

- 결론: 우리는 **'맞게 말했나'를 재지 않고 '말로도 고를 수 있다'**만 가져온다. 인식이 틀려도 막히지 않는다.

### 3.2 단계별로 무엇을 말로 하나
| 단계 | 말로 하는 일 | 앱이 하는 일 | 인식이 안 되면 | 저장·전송 |

### 3.4 기술 선택지

| 길 | 무엇 | 한국어 | 기기 밖으로 소리 나감? | 새 설치 | 공수(추정) |
|---|---|---|---|---|---|
| ① 기기 음성 인식 — 직접 만든 네이티브 모듈 | Android `SpeechRecognizer`(API 31+ `createOnDeviceSpeechRecognizer`) / iOS `SFSpeechRecognizer`(`requiresOnDeviceRecognition`) | 지원. 단 **기기 안(오프라인) 한국어 인식은 기기·OS마다 다름(확인 필요)**. Android는 기기 안 인식기가 없으면 예외, 일부 제조사 ROM은 시스템 인식기를 뺀다는 보고([Android 문서](https://developer.android.com/reference/android/speech/SpeechRecognizer), [개발 글](https://xckevin.github.io/en/blog/android-on-device-speech-recognition/)). iOS는 기기 안 지원 언어가 서버보다 적고 한국어 여부 **확인 필요**([WWDC19 256](https://developer.apple.com/videos/play/wwdc2019/256), [requiresOnDeviceRecognition](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition)) | 기기 안 모드면 안 나감. 일반 모드면 **Google·Apple 서버로 감** | **없음**(우리 Android 모듈 5개처럼 직접 작성). 단 네이티브 코드라 위험 리뷰 2 | Android 3~4일, iOS 2~3일 |
| ② 기기 음성 인식 — 라이브러리 | `expo-speech-recognition`(iOS SFSpeechRecognizer·Android SpeechRecognizer를 한 API로), `react-native-speech-recognition-kit`(TurboModule), `@react-native-voice/voice`(새 아키텍처에서 조용히 실패한다는 보고) ([비교 글](https://www.bitcot.com/?p=78489), [kit](https://github.com/Gautham495/react-native-speech-recognition-kit)) | ①과 같음(OS 인식기를 씀) | ①과 같음 | **있음 → 오너 승인**(DECISIONS 11-24 위임 밖: 새 npm·네이티브 설치). expo 계열은 Expo 모듈 기반이라 bare RN 설정 **확인 필요**(DECISIONS 11-20 'Expo 전환하지 않음') | 1~2일 + 검증 |
| ③ 서버 음성 인식(STT) | 녹음을 서버(예: Google Cloud STT, 이미 TTS 미리 생성에 Google Cloud 씀 — DECISIONS 11-19)로 보내 글자로 | 좋음, 사투리 강함(**추정**) | **나감** — 위탁·국외 이전, 음성은 개인정보(목소리) | 서버 함수 + 앱 녹음 패키지(승인) | 4~6일 + 법률 |

- **권장: ①(직접 만든 모듈, 기기 안 인식 우선)**.
  - 기기 안 인식이 안 되는 기기에서는 일반 모드(OS 서버)로 떨어진다. 그 경우는 방침에 'OS 음성 인식 사용' 한 줄이 필요하다.
  - 대안: 일반 모드를 쓰지 않고, 기기 안 인식이 없는 폰에는 마이크 버튼을 숨긴다.
  - 둘 중 하나를 Q5로 묻는다.
- Android 에뮬레이터에는 음성 서비스가 없다는 보고가 있다([kit README](https://github.com/Gautham495/react-native-speech-recognition-kit)). 그래서 **검증은 S25 실기기 몫**이다.

### 3.5 음성 데이터 처리 (권장 원칙)
1. **녹음 파일을 만들지 않는다.** OS 인식기의 결과 글자만 받는다.
2. **글자도 저장하지 않는다.** ①의 대답은 화면에만 잠깐 보이고 버린다. ②·③은 고른 보기 번호만 지금처럼 저장한다.
3. **서버·가족에게 보내지 않는다.** 이벤트에도 말한 글자를 싣지 않는다(지금 '낱말·번호 값은 어떤 이벤트에도 싣지 않는다' 원칙과 같음). 넣는다면 `voice_used` 참/거짓 하나(`tts_used`와 같은 꼴, **새 속성 — 서버 허용 목록 변경 필요**).
4. **마이크 권한은 처음 쓰려 할 때**(3.3).
5. 방침 영향:
   - 기기 안 인식만 쓰면 '수집 없음'에 가깝다(**추정**).
   - OS 서버 인식으로 떨어지면 Google·Apple로 음성이 간다. 이것은 OS 제공자의 처리다.
   - 방침에 고지할지는 **법률 확인 필요** → 공식 상담 새 항목 제안(L-12, 이 PR에서 상담 목록 파일은 고치지 않음).
   - 데이터 안전 양식 '오디오' 항목도 다시 본다.
6. ①의 자유 대답은 건강·가족사가 섞일 수 있다. 저장하지 않는 원칙이 민감정보(제23조) 쟁점을 피하는 핵심이다.

## 7. 카톡 링크 자동 채움 (M7)

근거: 스파이크 `2026-11-17-install-referrer-applinks.md` — **코드는 이미 들어 있다**. 도메인이 정해지지 않아 꺼져 있다.

## 8. 우선순위·순서 제안

| 묶음 | 내용 | 왜 이 자리 |
|---|---|---|
| **출시 전 필수** | ① ⑤ 제거(테스터 빌드에서 안 그림) ② 알림 권한 앱 시작 단계(오너 ①, 개발 레인) ③ 21시 이후 알림 처리 확인(오너 ③, 개발 레인) ④ 응원 4문장 안 1(법률 승인 키 2개) ⑤ 카톡 링크 자동 채움(도메인 게시와 함께) ⑥ 자녀 홈 안 A '자주 고르신 것'(데이터 추가 없음) + P2 문구 재검토 | 데이터·동의 범위를 크게 바꾸지 않는 것만 |
| **출시 후 1.1** | ⑦ 말하기 ①~④(Android) ⑧ ⑤ 대체 A 내일 사진 고르기 ⑨ 취향 지도 안 B(콘텐츠 갈래 표) ⑩ iOS 착수(Apple 계정 준비 병행) | 새 네이티브·법률 상담·콘텐츠 작업이 필요한 것 |
| **그 뒤** | ⑪ 자유 글(L-8·L-9 회신 뒤) ⑫ 보관 연장·계절 달력 안 C(새 동의) ⑬ 말하기 iOS·기본 승격 | 공식 상담·재동의가 걸린 것 |

- 확인 필요: ⑥을 출시 전에 넣으면 P2 문구가 바뀌는지에 따라 재동의 화면이 필요할 수 있다. 출시 전이라 기존 동의자가 없으므로(테스터 제외) **지금 바꾸는 것이 가장 싸다(추정)**.
