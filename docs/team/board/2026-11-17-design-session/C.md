# C. 자녀 "지난 답" 범위 (C5) — 팀 결정
근거: DECISIONS 결정 5(팀 내부 결정). 보드 안건 A "자녀 홈은 최근 고른 답+날짜만"(DECISION-MEMO §1). C5 시안은 날짜+답 목록, P2 동의 "고른 답과 날짜가 가족에게 보여요 / 안 한 날은 보이지 않아요 / 그만 보여 주면 지난 답은 지워져요". 서버는 `child_summary()`(최근 1개)만, 목록 RPC 없음. 앱 C5는 데이터가 있어도 빈 문구(오표시, coverage-audit).

## 1. 관점별 의견
- **PM**: 보드 결론은 **자녀 홈(C4)** 범위였고, 탭 "지난 답"은 별개로 시안·문구가 이미 목록을 전제한다. 제품 가치(SPEC 목표: "대화 소재")는 한 개보다 여러 개에서 나온다. 전화에서 "지난주에 바다 고르셨던데" 같은 소재. 목록 채택, 단 기간 제한.
- **디자이너**: 지금 C5 행은 답("가을")만 있어 맥락이 없다. 행 = 날짜 + 질문 한 줄 + 고른 답. 빈 날을 줄이나 빈칸으로 표시하지 않는다(달력 형태 금지).
- **라이터**: "지난 답"·"고른 답"이라는 말은 동의 문구와 같은 낱말이라 정합. 개수·빈도 요약("이번 달 12개") 금지(평가로 읽힘).
- **정책**: 동의 문구 첫 줄이 기간을 말하지 않아 "전부 영구히 보임"으로 읽힐 수 있다. 노출 범위를 문구에 적는다. 날짜 목록은 빈 날을 역산하게 하므로 감시 느낌 → 기간을 짧게, 집계 금지.

## 2. 반박 1회
- 정책 → PM: 날짜가 있으면 결국 "안 한 날"이 보인다. 날짜를 빼자. / PM: 날짜는 이미 동의 문구에 있고, 날짜 없는 답은 대화 소재로 쓰기 어렵다("언제 고르셨지?"). 기간 제한·집계 금지로 완화하고 날짜는 유지.
- 디자이너 → 정책: 30일이면 길다, 7일로? / 정책: 콘텐츠가 30일 주기라 한 바퀴를 넘기지 않는 30일이 자연스럽고, 7일이면 바쁜 자녀가 놓친다. 30일 유지.
- 라이터 → 디자이너: 질문 전문을 넣으면 행이 길어 150%에서 3줄. / 디자이너: 질문은 짧은 형("봄과 가을 중")으로 1줄, 넘치면 줄바꿈 허용(잘림 0 기준).

## 3. 결론 (PM 종합)
- **홈(C4)** = 최근 고른 답 + 날짜 1개(보드 결론 유지, 변경 없음).
- **지난 답 탭(C5)** = **최근 30일 안의 고른 답 목록**, 최신순, 날짜·질문·고른 답. 빈 날 표시·개수·빈도·연속 집계 없음. 페이지 나눔 없음(최대 30행).
- 동의한 어르신 것만. 동의 전 답은 원래 저장되지 않고, 철회 시 지워짐(기존). 30일 넘은 답은 **노출만 안 함**(저장은 연결 유지 기간 동안 — 처리방침에 명시, 법률 확인 항목 §4-5에 포함).
- 어르신이 여러 명이면 호칭별 구분(현재 `parent_title`은 가족 단위 → 빌드1은 한 목록, 행에 구분 없음. 다중 어르신 표시는 빌드2).

## 4. 화면 구조·문구 초안
```
{호칭}의 지난 답                         (설정)
최근 한 달 동안 고른 답이에요            ← 신규 보조 1줄
11월 16일   봄과 가을 중        가을
11월 15일   산과 바다 중        바닷가
...
[이야기 주제 추천 · 곧 유료]   (기존 유지)
빈 상태: 고른 답이 생기면 여기에 보여요 (기존)
동의 안 함: 답을 나누지 않는 중이에요 (C4와 같은 문장)
```
- P2 동의 첫 줄: "고른 답과 날짜가 가족에게 보여요" → **"최근 한 달 고른 답과 날짜가 가족에게 보여요"**(3줄 유지 원칙 지킴). 동의 버전 `v2`로 올림. v1으로 동의한 기기는 다음 실행 때 P2를 한 번 다시 보여 줌(출시 전이라 테스트 기기뿐, 가정).
- 화면 읽기: 행 단위 "11월 16일, 봄과 가을 중, 고른 답 가을"(답 뒤에 조사를 붙이지 않음).
