# 연결 쉽게 + 완료감 회의 결론 (2026-11-17)
위원 5명(기획 PM·디자인팀·UX 감사관(73세)·정책·앱 개발), r1 → r2. 원문 r1/, 표결 r2.md. 위임 원칙으로 채택. 시간은 추정, 어르신 검증 0회, 카톡 인앱 브라우저 동작 미확인. (주재자 보고 부록을 리드가 저장)

## 한 줄
연결은 "카톡 링크 한 번 → 설치·열기 → 번호가 채워진 확인 화면에서 [연결하기]"가 기본, 6자리 손 입력은 자동 확인 보조. 어르신에게 오늘·지난 30일 기록 보기, 코스 끝에 도장 "쾅"(진동 1·짧은 소리), 칭찬·연속 보상 없음. 단계 카드 어긋남 원인은 StepRow의 flexWrap + 최소 높이.

## A. 연결 쉽게 (빌드 1)
- 채택: 링크 한 번(기본), 대신 연결(문구만). 기각: 어르신 QR, 클립보드, 문자 자동 읽기, 낱말 조합. 뒤집은 QR(어르신 화면을 자녀가 찍음)은 빌드 2 부모님 먼저 흐름 승인 장치
- 흐름: ①자녀 공유 메시지 = 사람 말 + 링크 + 번호 단독 줄 "123 456" + 7일(토스 트랙은 Play 링크 금지) ②링크 https://<도메인>/c#123456(URL 조각, 서버 기록 안 남음): 앱 있으면 App Links, 없으면 Play referrer=code → 첫 실행 Install Referrer 1회 읽기(분석 이벤트에 번호 금지) ③첫 화면 질문은 건너뛰지 않음, "가족이 보낸 번호가 있어요" 띠 ④확인 화면 P1c: 호칭(peek RPC)·큰 번호·[이 번호로 연결하기]·"다른 번호 쓰기"·안심 한 줄, 자동 연결 금지, 만료·무효면 안내 ⑤손 입력: 6번째 숫자 후 300ms 자동 확인, "다음" 제거, 틀려도 숫자 유지, 성공 전 P1c ⑥연결 성공 시 자녀 알림
- 0018 무효화 규칙 그대로. 스파이크 관문(착수 첫날 2~3h): 카톡 인앱에서 referrer 보존·앱 열기, 실패 시 설치 경로 자동 채움만 빼고 출시

## B. 어르신 기록 보기
- 오늘 다시 보기(빌드 1): B2를 세 단계 전부 보기 전용으로 확장(대체). P3 완료 행 '›', 하단 "오늘 사진 다시 보기"
- 지난 날(빌드 1 조건부): 최근 30일 목록(폴라로이드 한 장=하루, 빈 날 없음, 달력 금지), 한 날 보기(날짜·사진·고른 것·낱말, 어르신이 친 글자 저장·표시 안 함), 동의 거부·철회 날은 "고른 것" 생략
- 서버 기록 컬럼(daily_sessions에 그날 받은 photo·question·word id)은 화면과 무관하게 빌드 1 필수

## C. 클리어하는 맛 (빌드 1)
- 금지: 칭찬·평가 문구, 하트, 연속 숫자, 부재 압박, 7칸 완성 특별 연출
- 단계 끝: 체크 원 그리기 280ms cubic-bezier(0.2,0,0,1) → 면 초록 200ms → "했어요" 120ms, 다음 행 테이프 8dp 240ms(160ms 지연). 동작 줄이기: 200ms 페이드
- 코스 끝(P7): 도장 1.3→1.0·불투명 180ms → 눌림 0.94 140ms → 인주 번짐 420ms → 500ms 문구 → 900ms 도장이 이번 주 오늘 칸으로 480ms. 약 1.4초, 아무 데나 누르면 건너뜀. 시스템 촉각 1회, 나무 도장 소리 250ms 이하(무음·읽어주기 중 안 냄, 설정 "효과음" 토글)
- 미연결이면 도장 문구 빼고 "번호를 받으면 도장도 찍혀요"류(라이터)
