# r1 · 앱 개발 대표 — 독립 의견

읽은 것: app/src(ConnectScreen·CodeEntry·CodeShow·CourseHome·StepRow·Text20·tokens), AndroidManifest(현재 인텐트 필터: 런처 + 카카오 OAuth만, 딥링크 없음), package.json(RN 0.88.1, 네이티브 의존성 최소), 0018, schema(answers·daily_sessions), 09-environments(staging은 Play 밖 배포). 시간은 모두 추정(가정).

## A. 연결 — 구현 관점
### (1) 링크 한 번: 두 갈래를 구분해야 한다
| 갈래 | 동작 | 필요한 것 | 미확인 |
|---|---|---|---|
| 1a 아직 설치 안 됨 | 링크 → Play 상세 → 설치 → 첫 실행에서 **Install Referrer**로 `code=123456` 읽기 | `com.android.installreferrer` 라이브러리 + 작은 네이티브 모듈(또는 기존 RN 래퍼 패키지 1개), 첫 실행 1회 읽기·'읽음' 저장 | ① 카톡 인앱 브라우저에서 `play.google.com/...&referrer=` 링크가 Play 앱으로 넘어갈 때 referrer 보존 여부 ② 사용자가 Play의 '열기' 대신 홈 아이콘으로 열어도 읽히는지(문서상 읽힘, 확인 필요) ③ **Play 경유 설치만** 값이 있음 → staging(adb·App Distribution)에서는 테스트 불가, 내부 테스트 트랙 필요 |
| 1b 이미 설치됨 | 링크 → 앱이 바로 열리며 번호 전달 | **Android App Links**: 우리 도메인 `https://<도메인>/c#123456` + `/.well-known/assetlinks.json`(서명 키 SHA-256) + `autoVerify` 인텐트 필터 + 앱의 링크 처리(앱 꺼짐/켜짐 둘 다) | ④ 카톡 인앱 브라우저는 App Links를 바로 열지 않고 웹페이지를 띄우는 경우가 많음(미확인) → 안내 페이지에 **"앱에서 열기" 버튼(intent:// 링크)** + "Play에서 받기" 버튼을 둬서 둘 다 처리 |
- 도메인: Play 등록에 **개인정보 방침 URL이 필수**라 site/를 어딘가 올려야 한다. 같은 호스팅에 `/c` 안내 페이지와 assetlinks.json을 두면 추가 비용은 작음. 도메인·호스팅 결정은 사용자(계정·비용).
- 서버 변경: **없음**(링크에 같은 6자리 번호를 실음). 확인 화면에 호칭을 보이려면 미리 보기 RPC `peek_invite_code(p_code)` → `{ok, parent_title}`(redeem과 같은 시도 한도) 신설, 0028 예정. 이게 없으면 확인 화면은 번호만.
- 앱 흐름: 첫 실행 → 첫 화면 질문을 **건너뛰지 않음**(이 폰이 자녀 폰일 수도: 자녀가 자기 폰에서 링크를 눌러 보는 경우) → "부모님 휴대폰이에요" 누르면 P1이 아니라 **확인 화면 P1c "가족이 보낸 번호가 들어 있어요 / 123 456 / [이 번호로 연결하기] / 다른 번호 쓰기"**. 이미 연결된 기기에서 링크가 열리면 "이미 연결돼 있어요" 안내(재연결 번호면 재연결 흐름).
- 추정: 1a 5~7h, 1b(인텐트 필터·링크 처리·안내 페이지·assetlinks) 6~9h, P1c 화면·상태 3~4h, peek RPC+pgTAP 3~4h, 실기기 매트릭스(카톡 인앱/삼성 인터넷/크롬 × 설치 전/후 × 앱 꺼짐/켜짐) 4~6h. **합계 21~30h**. 선행 스파이크 2~3h(①④ 확인)로 1a 효과를 먼저 증명.

## B. 기록 보기 — 데이터가 있는가
- **오늘 다시 보기**: 오늘 콘텐츠는 이미 `content`(세션)에 있고 고른 답은 `save_answer` 직후 앱 상태에 있음 → 서버 호출 0. 기능 회의 B2(사진만, 3~5h)를 세 단계로 넓히면 **5~8h**. 단 앱을 껐다 켜면 오늘 고른 답을 다시 받아야 함 → `get_today_content`가 오늘 내 답을 돌려주는지 확인 필요(미확인, 없으면 0021에 필드 1개).
- **지난 날**: 지금 스키마로는 **"그날 무슨 사진이었는지"를 알 수 없다**. answers는 질문 id·시각만, daily_sessions는 날짜·완료 단계만. 콘텐츠 순번(0026 어르신별 커서)이 들어오면 날짜→콘텐츠를 역산할 수도 있지만 깨지기 쉬움. **daily_sessions에 photo_id·question_id·word_id 컬럼을 추가(그날 받은 콘텐츠 기록)** 하고 `parent_history(p_days int default 30)` RPC가 날짜·사진·질문·내 답(동의 시)·낱말을 돌려주는 게 맞다. 0028(또는 0026과 합침).
  - 서버 6~8h(마이그레이션·RPC·RLS·pgTAP·파기 배치 30/31일 정합), 앱 화면(목록·한 날 보기·빈 상태·오프라인) 8~10h, 디자인 4h. **합계 18~22h**.
  - 과거 기록(컬럼 추가 전 날짜)은 사진 정보가 없음 → 출시 전이라 실사용자 없음, 문제 없음.

## C. 완료감 — 구현
- 모션: RN 기본 `Animated`(native driver)로 충분, 새 의존성 불필요. 체크 그리기는 react-native-svg `strokeDashoffset` 애니메이션(JS 구동, 280ms라 허용).
- 진동: RN `Vibration.vibrate(30)`은 `VIBRATE` 권한 필요(일반 권한). 시스템 촉각(`performHapticFeedback(CONFIRM)`)은 권한 없이 되지만 네이티브 모듈 몇 줄 필요. **시스템 촉각 권장**(사용자가 시스템 진동을 끄면 따라 꺼짐 = 존중).
- 소리: 짧은 효과음 재생에 네이티브 모듈 필요(배경 음악용 플레이어를 이미 넣을 예정이면 공유). **무음·진동 모드 확인은 `AudioManager.getRingerMode()` 네이티브** 필요. 효과음 스트림을 알림 계열로 두면 무음 모드에서 자동으로 안 남.
- 동작 줄이기: `useReduceMotion` 이미 있음.
- 추정: 단계 체크 3~4h, P7 도장 순간 5~7h, 촉각·소리 모듈 3~5h(BGM 플레이어와 공유 시 감소), 소리 에셋은 디자이너·사용자(생성/구매). **11~16h**.

## D. 디자인 다듬기 — 수정 비용
디자인팀이 짚을 것으로 예상되는 StepRow(flexWrap·패딩), Text20 줄 높이 표, 토큰 중복 이름 정리 → 4~6h + 전 화면 캡처 재확인 2~3h. 줄 높이 변경은 **전 화면 높이가 바뀌므로** 디자인 동결 전에 한 번에.

## E. 추가 발굴(개발이 보는 것)
1. 미연결 상태 완료 문구 "도장을 찍었어요"가 사실과 다름(미연결이면 도장 줄을 숨김) — 문구 분기 30분.
2. 연결 성공 시 자녀 알림: 푸시 인프라(빌드 1 필수)에 이벤트 하나 추가. 서버 트리거 or 앱 측 Realtime. 3~4h.
3. 링크 경로를 넣으면 **연결 퍼널 이벤트**(link_opened / referrer_found / code_prefilled / redeem_ok, 번호 값 금지)를 같이 넣어야 효과를 잴 수 있다.

## 내가 틀릴 수 있는 이유
- Install Referrer·App Links의 카톡 인앱 브라우저 동작은 기억과 일반론이다. 스파이크 전엔 1a가 실제로 몇 % 경우에 동작할지 모른다.
- RN 0.88 기준 서드파티 referrer 패키지의 New Architecture 호환을 확인하지 않았다(직접 모듈 작성 시 +2h).
