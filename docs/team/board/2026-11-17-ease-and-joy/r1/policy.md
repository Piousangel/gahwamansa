# r1 · 정책·개인정보 — 독립 의견

읽은 것: DECISIONS(보관 31일·30일, 동의 거부 시 미저장, 감시·평가 기각, 법률 권고, 푸시 08~21시), 0018_revoke_codes(가족당 살아 있는 가입 번호 1개, 사용 시 나머지 만료, 5회/10분·300회/10분 한도), 03-toss-inapp-analysis(교차 유도 금지). 법률 자문 아님.

## A. 연결 — 보안·정책
### 위협 모델
| 위협 | 지금(6자리) | 링크 자동 채움 시 | 대응 |
|---|---|---|---|
| T1 메시지가 다른 사람에게 전달돼 그 사람이 '부모'로 들어옴 | 있음(번호가 메시지 본문에 있음) | **같음**(번호=링크, 노출 범위 동일) | 0018: 사용 즉시 나머지 만료, 1회용. 연결 성공 시 자녀에게 즉시 알림(푸시+홈 표시) → 자녀가 알아챔 |
| T2 **낯선 사람이 어르신에게 링크를 보내 자기 가족에 붙임**(어르신 답이 남에게 감) | 가능(번호 불러 주기 사기) | **문턱이 낮아짐** — 누르기만 하면 됨 | **자동 연결 금지. 확인 화면에서 어르신이 직접 [연결하기]**. 확인 화면에 "누가 보낸 번호인지" 단서: 그 가족이 정한 호칭("'엄마'라고 부르는 가족이 보낸 번호예요")을 보여 주면 모르는 사람 링크를 걸러낼 단서가 됨 |
| T3 링크/설치 경로 값이 로그·분석에 남음 | 없음 | 웹 서버 접근 기록, 분석 SDK | 번호는 URL **조각(#)** 에 넣어 서버 기록에 안 남게(우리 안내 페이지), Play 링크의 referrer는 Play가 처리. 앱은 읽은 뒤 **사용·폐기, 분석 이벤트에 번호 금지** |
| T4 0018 무효화 이후 옛 링크 | 옛 번호 'expired' | 옛 링크도 같은 번호라 같은 'expired' | 확인 화면이 아니라 "이 번호는 이제 쓸 수 없어요. 가족에게 새 번호를 받아 주세요"로 바로. 설치 경로 값은 Play에서 최대 90일 다시 읽히므로(미확인, 공식 문서 확인 필요) **처음 1회만 읽고 기기에 '읽음' 표시** |
| T5 엿보기(확인 화면이 호칭을 노출) | — | 번호를 가진 사람은 호칭을 알게 됨 | 호칭은 낮은 민감도. 미리 보기도 redeem과 같은 시도 한도(5회/10분) 안에서만 |

### 안별 정책
- (1) 링크: Play 정책상 설치 경로(Install Referrer) 사용은 일반적 사용(광고 ID 아님). **개인정보 방침에 "설치 경로 정보는 기기 안에서 번호 채우기에만 쓰고 보내지 않음" 한 줄** 추가 권장. 앱 링크 검증용 도메인 파일은 개인정보 아님.
- (2) 어르신 쪽 QR: 정책 문제 없음. 뒤집은 방향(어르신 화면 QR → 자녀가 찍음)은 **물리적으로 함께 있다는 강한 승인 신호**라, 부모님 먼저 흐름(빌드 2)에서 내가 요구한 "승인 장치"가 될 수 있다 — 빌드 2 설계에 기록.
- (3) 대신 연결: 문제 없음. 단 동의(P2)는 **어르신 본인이** 읽고 누르도록 안내("동의는 부모님이 직접 눌러 주세요"). 자녀가 대신 누르면 동의의 의미가 약해짐.
- (4) 클립보드: Android 12+ "붙여넣음" 알림이 뜬다. 어르신이 "앱이 내 걸 훔쳐본다"로 오해할 수 있고, 방침 고지 대상. **반대**. 사용자가 "붙여넣기" 버튼을 직접 누를 때만 읽는 방식은 허용 가능하나 효과 적음.
- (5) 문자: SMS Retriever는 권한 없이 가능하나 우리 서버가 아니라 자녀가 보내는 문자라 앱 해시를 메시지에 넣어야 함(공유 메시지가 이상해짐). User Consent API는 시스템 동의 창이 뜸. 카톡 대다수 가정이라 효용 낮음. **빌드 1 반대**(권한 문제는 없음).
- (6) 낱말 조합: 정책 문제 없음, 보안 강도는 낱말 수에 따라. 사용성 이유로 다른 위원 판단에 맡김.
- 토스: 미니앱 안에서 **자사 앱 설치 유도 금지**. 토스로 들어온 자녀의 공유 메시지에는 Play 링크를 넣으면 안 되고 토스 미니앱 링크만(형식 미확인). 공유 메시지 조립을 트랙별로 분리할 것.

## B. 기록 보기
- 범위: **최근 30일**(자녀 "지난 답"과 같게, 보관 31일 안). 31일 넘은 기록이 화면에 남으면 파기 정책 위반 — 서버가 30일로 자르고 앱 캐시 금지.
- 동의 거부·철회 어르신: 답이 저장되지 않으므로 "고른 것"이 없다. 그 날 카드에 **빈 자리 문구 없이 사진·낱말만**. "저장 안 됨"을 반복해서 보여 주면 압박.
- 철회 시 지난 답 삭제(기존 결정) → 지난 날 화면에서도 즉시 사라져야 함.
- 낱말: 어르신이 친 글자는 저장하지 않는다(현재도 없음). 지난 날에는 그날 낱말(콘텐츠)만. 새 수집 항목 0 유지.
- 받은 응원 다시 보기: 응원 31일 보관과 일치하면 허용. read_at을 자녀가 못 읽는 0014 원칙은 그대로.

## C. 완료감
- 금지 목록 재확인: 칭찬·평가 문구, 하트, 연속 일수, 부재 압박("어제 안 하셨네요"), 한 주 다 채움 보상. 한 주 7칸 완성 특별 연출은 **반대**(사실상 연속 보상).
- 소리: 무음 모드 존중은 정책상 필수에 가깝다(공공장소 민망 → 앱 삭제 사유). 
- 진동: Android `VIBRATE`는 일반 권한(설치 시 자동, 사용자 고지 불필요). 시스템 촉각 피드백은 권한 없음.

## E. 추가로
- 확인 화면의 안심 문구(B4 "이 앱은 돈이나 은행 번호를 묻지 않아요")를 링크 경로 확인 화면에도.
- 공유 메시지에 링크가 생기면 카톡 미리 보기(썸네일·제목)가 뜬다 — 안내 페이지의 미리 보기 제목에 번호·호칭을 넣지 말 것(단톡 노출).

## 내가 틀릴 수 있는 이유
- Install Referrer 보관 기간(90일)과 재읽기 동작은 기억에 기댄 것이다. 공식 문서 확인 필요.
- T2(낯선 사람이 붙이기)가 실제로 얼마나 일어날지 모른다. 확인 화면 한 번이 지나친 장치일 수도 있다.
