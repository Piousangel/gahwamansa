# r1 · PM (토스 출신) — 독립 의견

기준: ① 사용자 원칙 "완성도 > 출시일", 단 **10 마스터의 군별 동결**을 깨지 않는 범위 ② 퍼널(설치 → 자녀 가입 → 연결 → 첫 답 → 첫 답 본 자녀 R → 재방문 → 곧 유료 관심)에서 가장 약한 칸을 메우는 것 ③ 토스식 "한 화면 한 가지 일". 숫자는 모두 가정.

## 빌드 1 판단 기준(제안)
- 새 화면 0, 기존 화면의 상태·한 줄·한 행만. 서버는 **이미 예정된 마이그레이션(0019~0021)에 접어 넣을 수 있을 때만**.
- 동결된 군에는 넣지 않는다. 오늘(11/17) 기준 ①②③ 모두 "디자인 확정 중"(10 §3 11/17~19)이라 지금이 마지막 기회.
- 총량 상한: 버퍼 포함 **30h 이하**(전체 332~484h의 약 6~9%).

## 빌드 1에 넣자고 주장하는 것
F11, F02, F15. F26은 0026 커서 확정이 백오피스 쪽 일정이라 **빌드 2 첫 업데이트**로.
F28은 끌리지만 "알림 한 번이 두 번이 된다"는 경로를 막을 장치가 정책에서 나와야 한다 → 빌드 2.

## 내가 틀릴 수 있는 이유
- 토스식 "한 화면 한 일" 기준이 어르신 화면에는 맞지만 자녀 화면에는 정보 밀도를 너무 낮게 잡을 수 있다.
- 30h 상한은 감이다. 디자인 QA 왕복(1차 승인 0/3)이 실제 병목이라 작은 기능도 승인 왕복 1회를 더 부른다.
