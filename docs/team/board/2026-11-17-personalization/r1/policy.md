# r1 · 정책·법률 — 독립 의견

> 법률 자문이 아니다. 실무 점검이며 확정은 변호사 질문으로 넘긴다(docs/team/legal/questions-for-lawyer.md). 조문 번호는 compliance-checklist와 같은 출처 수준(일부 2차).

## 지금 방침(privacy-v2.1)이 약속한 것
- 부모님은 "이름·전화번호 없이" 쓰고 "앱이 만든 무작위 번호로만 구분"한다.
- 가족에게는 "고른 답과 날짜"만 보인다. 이용 기록에는 "고른 답·글자 내용"을 넣지 않는다.
- 고른 답은 **"가족에게 고른 답 보여 주기"** 목적의 동의로만 저장되고, 31일 지나면 지운다.
- 13절: "모으는 정보나 보여 주는 범위가 넓어지면 앱 안에서 먼저 알리고, 필요하면 다시 동의".

## 축별 법적 분류
| 축 | 분류 | 판단 |
|---|---|---|
| 성별 | 일반 개인정보 | 수집 근거 약함(콘텐츠에 필요성 입증 어려움), 차별 우려. **기각**. 또한 호칭(엄마·아빠 등)을 콘텐츠 선택에 쓰면 "호칭 표시" 목적 밖 이용 → 금지 규칙으로 명문화 |
| 출생 시기(10년 단위) | 일반 개인정보 | 정확한 생년보다 낮은 식별성. 다만 "가족 + 10년대 + 고향 유형"이 결합되면 가족 안에서는 특정 쉬움(애초에 가족은 앎) |
| 자란 곳 유형(바다·산·들·도시) | 일반 개인정보 | 지명 없으면 식별성 낮음 |
| 사진 취향(둘 중 고른 사진) | 이용 행태 정보 | 가장 가벼움. 본인이 기능을 쓰려고 고른 값 → 서비스 제공 근거(제15조①4호) 가능성(확인 필요) |
| 직업 | 일반 개인정보 | 필요성 없음, **기각** |
| 종교 | **민감정보(제23조)** | 별도 동의 필요, 우리 목적에 과잉. **기각, 절대 수집 금지** |
| 건강·시력 | **민감정보(제23조)** | 위와 같음. 접근성은 OS 설정을 기기 안에서만 읽음(저장·전송 금지) |
| 사투리(출신 지역) | 일반 | 수집할 이유 없음, **기각** |

## 수집 주체별 위험
1. **자녀가 입력**: 정보주체(부모님)가 아닌 사람에게서 받는 정보 → 제20조(정보주체 이외로부터 수집한 개인정보의 수집 출처 등 통지). 요구 시 통지, 일정 규모 이상은 의무 통지(2차, 우리 규모 해당 여부 불확실). 무엇보다 "부모님은 이름 없이 쓴다"는 방침의 정신과 충돌. 자녀가 틀리게 넣을 때 정정 경로도 필요. **반대**.
2. **부모님 본인이 입력**: 근거 명확, 정정·삭제 쉬움. 선택이고 거부해도 불이익 없어야 함(제22조⑤ 취지).
3. **추론(고른 답에서 경향 학습)**: 리드 초안은 "새 개인정보 없음"이라 했으나 **틀렸다**. 추론 결과("이분은 도시 취향")도 그 사람에 관한 정보라 개인정보다. 또 고른 답은 "가족에게 보여 주기" 동의로만 저장되므로 **다른 목적(콘텐츠 선택)에 쓰는 것은 목적 외 이용**(제18조) 소지. 경향을 쌓으려면 31일보다 긴 보관이 필요해 **파기 약속과 충돌**. 동의 거부 어르신은 답이 없어 학습 불가 → 집단 간 불평등. **반대**. 단, 사람 단위가 아닌 **콘텐츠 단위 집계**(이 사진의 완료율·크게 보기 비율)는 지금 이용 기록 목적("앱 고치기") 안이라고 봄(확인 필요).

## 방침·동의 영향
- 부모님 본인이 사진 취향 1값을 고르는 안: 방침 2절 부모님 표에 행 1개("사진 고르기: 고르신 사진 종류(도시·시골·둘 다) / 사진 골라 보여 드리기 / 서비스 제공 / 계정 지울 때까지, 가족에게 보이지 않음"). 별도 동의 화면은 불필요하다고 봄(확인 필요). 13절에 따라 앱 안 고지 한 줄은 넣는다.
- 출생 시기·고향 유형을 묻는 안: 행 2개 + "왜 묻는지" 고지가 필요하고 P1 안심 문구("돈이나 은행 번호를 묻지 않아요")와 같은 흐름에서 신뢰 비용이 크다.
- **동의 거부 어르신에게도 취향값은 저장 가능**해야 공정하다: 답 공개 동의와 목적이 다르다(확인 필요).
- 자녀 화면 노출 0: 0014 열 단위 권한(`grant select (id, user_id, family_id, role, display_name, created_at)`)이므로 새 열은 자녀에게 기본 비공개. 이를 pgTAP로 고정.
- 이벤트: 사진 변형 값(city/country)을 이벤트 속성에 넣으면 이벤트(14개월 보관)에 취향이 남는다. 가족 가명키와 결합되므로 **속성 넣을지 법률 확인**, 넣는다면 값 목록 고정.

## AI 즉석 생성
리드 초안 동의. 추가로 AI 기본법 고지(compliance #13)가 "미리 만든 그림"에서 "개인별 생성물"로 바뀌면 이용자 쪽이 아니라 제공자 쪽 의무 검토가 필요해질 수 있다. 개인 정보를 프롬프트에 넣어 외부 API로 보내면 **국외 이전 행이 늘어난다**. 지양.

## 내가 틀릴 수 있는 이유
- 사진 취향 1값을 "서비스 제공" 근거로 둘 수 있는지는 해석이 갈린다. 동의로 받아야 한다는 답이 오면 화면에 동의 문구가 붙는다.
- 제20조 통지 의무의 규모 요건(2차 자료)을 정확히 확인하지 못했다. 자녀 입력이 생각보다 가벼울 수 있다.
