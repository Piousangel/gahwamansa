# r2 · 상호 반박과 표결 (2026-11-17)

진행: 회의 주재자가 r1 6건을 모두 위원에게 돌리고, 위원마다 반박 1~3개와 표결을 받았다. 같은 모델이 맡은 위원들이므로 의견이 쏠릴 수 있다. 소수 의견은 지우지 않고 남긴다.

## 1. 반박

### 리드 초안에 대한 반박
- **정책 → 리드 초안 "고른 답에서 경향 학습(새 개인정보 없음)"**: 사실과 다르다. 추론 결과도 개인정보다. 답은 "가족에게 보여 주기" 동의로만 저장하므로, 콘텐츠 선택에 쓰면 목적 외 이용 소지가 있다. 31일 파기 때문에 경향이 쌓이지도 않는다. 동의를 거부한 분은 답이 없어 학습 대상에서 빠진다.
- **콘텐츠 → 같은 안**: 봄/가을, 단감/홍시는 자란 곳과 거의 상관이 없다. 신호가 되려면 진단용 질문을 넣어야 하고, 그건 결국 묻는 것과 같다.
- **PM → 리드 초안 "10년 단위 출생 4종 × 풍경 4종"**: 16조합 × 30일 = 480장이다. 장당 후보 4장을 만들고 12항목으로 검수하면 1인 운영으로는 감당할 수 없다.
- **UX 감사관 → "자녀 선택 입력"**: 부모님은 내 정보가 들어간 줄 모르고, 자녀가 틀리게 넣을 수 있다(태어난 곳 ≠ 자란 곳). P1 안심 문구("돈이나 은행 번호를 묻지 않아요") 바로 뒤에 출생 시기를 묻는 흐름은 신뢰를 깎는다.

### 위원끼리 반박
- **정책 → 자녀 대변인(자녀 입력 + 부모 확인)**: 이 경우 제20조(정보주체가 아닌 사람에게서 받은 정보) 문제가 생긴다. 형제가 다른 값을 넣으면 충돌한다. 부모 확인 화면까지 만들면 부모님 화면이 결국 1개 늘어서, "부모님 화면을 늘리지 않는다"는 장점도 사라진다.
- **자녀 대변인 → UX 감사관**: 사흘째 코스 끝에 묻는 것도 부모님 화면 1개다. → **UX 답변**: 그래도 본인이 고르고, 도장 다음이라 흐름이 끊기지 않으며, 건너뛰면 다시 묻지 않는다. 같은 1화면이라면 본인 화면이 낫다. 자녀 대변인은 이 부분을 일부 받아들였다(소수 의견 유지).
- **PM → 서버(태그 열을 빌드 1에)**: 0024 트리거가 새 열 갱신을 막지 않으므로 빌드 2에 소급할 수 있다. 빌드 1은 마이그레이션 대장을 0032에서 닫는 편이 리뷰 부담이 적다. → **서버 답변**: prod 묶음(P2) 하나를 줄이는 이득은 작다. 비용 2h라 고집하지 않는다(소수 유지).
- **콘텐츠 → PM(시대 축 보류)**: 1940년대생의 회상 절정기는 1950~60년대라 70~80년대 화풍과 어긋난다. → **PM 답변**: 연령 분포를 모르는 상태에서 변형부터 만들면 낭비다. 태그는 지금 기록하고, 3가구 관찰과 빌드 2 데이터를 본 뒤 정한다. 콘텐츠 위원은 "빌드 3 재검토"로 물러섰다.
- **UX 감사관 → 서버("둘 다"는 홀짝으로 번갈아)**: "둘 다 좋아요"를 고른 분께는 지금 기본(시골)을 그대로 주는 편이 예측 가능하다. → **서버 수용**: 'both'면 기본 사진. 섞어서 보여 주는 방식은 데이터를 본 뒤 정한다.
- **정책 → 서버(이벤트에 variant 속성)**: 취향이 이벤트에 14개월 남는다. → **합의**: 집계에 필요한 건 "그날 기본/변형 중 무엇을 보냈나"뿐이다. 속성은 `variant: default|alt` 두 값만 쓰고 city·country라는 의미는 남기지 않는다. 그래도 서버의 day_index와 결합하면 추론이 가능하다는 점은 법률 질문으로 넘긴다.
- **콘텐츠 → 전원(계절)**: 상시 풀에 계절 장면이 13/14칸이다. 30일로 늘릴 때 계절과 무관한 장면을 늘리지 않으면 시즌 풀을 분리해도 어긋남이 남는다. → **전원 동의**.
