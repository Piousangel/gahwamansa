# 디자인 시스템 v4 회의 결론 (2026-11-19)
위원 6명(UX 리드·비주얼 디자이너·UX 감사관(73세·접근성)·자녀 대변인·RN 디자인 시스템 엔지니어·PM)이 r1(독립 의견) → r2(반박·표결) 순서로 진행했다. 원문은 r1/, 표결은 r2.md에 있다. 시간은 모두 **추정**이다. 어르신 검증은 0회이고, S25에서 500 굵기가 렌더되는지도 확인하지 못했다. 법률·정책 판단은 범위 밖이다.
계기: 오너의 실기기(Galaxy S25 staging) 캡처 3장(C0 로그인, P6 자판 쓰기, 자녀 응원 시트). 오너 지적은 "단조롭다(같은 색·볼드·크기만 조금 다름)", "버튼 영역이 정해져 있어 잘린다", "'‹ 오늘 코스'가 작다", "규칙과 공통 컴포넌트, 그 바탕의 기획이 필요하다"였다.

## 한 줄
위계를 만드는 수단이 크기 하나뿐이고 그 크기도 화면마다 숫자로 정했다. 잘림은 글을 줄여서(numberOfLines 0건)가 아니라 **틀**(하단 40% 상한 + 과적, 고정된 위 영역, 한 줄 입력칸 placeholder)에서 생긴다. 해결책은 v4 규칙이다. 글자 **역할**마다 크기·굵기·색을 묶고, 갈색은 누를 수 있는 것에만 쓰고, 본문은 차콜로 분리한다. Dock은 슬롯을 타입으로 제한하고, 틀(Screen variant)을 정하고, placeholder를 금지한다. 화면은 숫자가 아니라 역할 prop만 고른다.

## 2. 규칙 v4
### 2-1. 글자 역할 표 (어르신 / 자녀, 크기/줄높이 dp)
| 역할 | 어르신 | 자녀 | 굵기 | 색 | 쓰임 |
|---|---|---|---|---|---|
| display | 52/68 | 40/52 | 700 | inkTitle | 큰 숫자·완료 한 줄(확대 상한 1.5) |
| title | 32/44 | 26/36 | 700 | inkTitle | 화면 제목(Heading 1, 한 화면 1개) |
| heading | 26/36 | 20/28 | 700 | inkTitle | 섹션 제목(Heading 2) |
| bodyLg | 22/32 | 18/28 | 400 | inkBody | 질문 문장·카드 문장·선택지·시트 본문 |
| body | 20/30 | 16/24 | 400 | inkBody | 설명 문단 |
| sub | 20/30 | 16/24 | 400 | inkSub | 보조·날짜·안내(본문과 크기가 같으면 색으로 구분) |
| button | 주 30/38, 보조 24/32 | 18/26 | 700 | onAction / action | Button 안에서만 |
| link | 22/30 + 아이콘 24 | 17/26 | 400 + 밑줄 | action | 텍스트 링크(누름 높이 어르신 64·자녀 48) |
| backLink | 24/32 + 화살표 28 | 18/26 + 24 | 400 | action | BackLink 전용 |
- 규칙:
  - 화면은 역할만 고른다(숫자 size·weight·color 금지).
  - 한 화면에 700을 쓰는 역할은 최대 2개다.
  - 본문에는 bold를 쓰지 않는다.
  - 인접 단계 크기 비율은 1.2 이상이고, 모자라면 굵기·색으로 보완한다. 토큰 테스트로 자동 검사한다.
  - 빌드 1은 **400/700 두 단계**다. 500은 S25 실측에서 확인될 때만 쓴다.
  - Pretendard 번들은 빌드 2에 실측을 거쳐 정한다.
- 어르신 본문은 **20 유지**(r2 동수 3:3, 주재자 결정). 22로 키울지는 어르신 실사용 확인 1회 뒤 빌드 2에서 다시 정한다.
- 줄높이는 11-17 줄 높이 표를 유지한다(lineHeightFor). 하한은 audience별로 둔다(어르신 20 / 자녀 16, 16은 sub·약관 줄만).

### 2-3. 간격
- 4 격자. 같은 묶음 안 8, 묶음 사이 16(어르신 20), 구역 사이 32.
- 화면 좌우 여백은 어르신 24, 자녀 20.
- 남는 세로 공간은 화면 가운데가 아니라 행동 바로 위로 모은다.

### 2-4. 터치·버튼
- **높이는 최소값만 정한다(minHeight).** 내용이 늘면 따라 늘어난다. 글자를 담는 상자에 height·maxHeight 고정은 금지한다.
- 최소값: 어르신 주 72·보조 64·링크 64·간격 12 / 자녀 주·선택지 56·최소 48.
- **말줄임 금지가 원칙이다**(numberOfLines·ellipsize 금지, 줄바꿈). 예외는 ui/ 컴포넌트 내부에서만 허용한다.
  - 낱말 칸(KeyboardStep:312, 배율 1·고정 칸)
  - 브랜드 버튼(SocialButton, 가이드 고정)
  - 번호 칸
  - 예외는 주석과 테스트로 명시한다.
- 확대 상한은 숫자를 흩지 않고 역할 토큰에서만 정한다. 본문 2.0, 큰 제목·Dock·번호 1.5.
- Dock 규칙:
  - 슬롯은 **주 버튼 1 + 보조 1 + 한 줄 note**까지만 둔다(타입으로 제한).
  - 약관 같은 글은 본문 끝에 둔다.
  - 200%에서 넘치면 note → 보조 순으로 본문 끝에 보낸다.
  - 그래도 넘치면 위·아래 페이드를 필수로 두고, 테스트를 실패로 처리한다(r2 4/6, 소수는 완전 금지).
  - 본문이 빈 화면은 Screen이 판단해 행동을 본문에 둘 수 있다.

### 2-5. 뒤로 가기·상단 바
- 공용 **BackLink** 하나로 통일한다.
  - SVG 화살표 28(획 3) + 글자 24(자녀 18), 색은 action.
  - 옅은 알약 면 paperSoft + line 테두리 1.5.
  - 어르신은 높이 64·폭 120 이상, 자녀는 높이 56.
  - 문구는 목적지("오늘 코스로")로 쓰고, 보이는 글과 TalkBack 라벨을 같게 한다.
  - 위치는 왼쪽 위다.
- BackBar·ToCourseHomeLink·TextLink(뒤로 용도)는 BackLink로 흡수한다. 글자 배율 때문에 숨기는 처리(B5)는 없앤다.
- TopBar = `back? + title? + action?`. 탭 화면은 TopBar, 스택 화면은 BackLink를 쓴다.
- 자판이 열리면(form·step) 위 영역을 BackLink 한 줄로 접는다. 단계 정보는 TalkBack 라벨로 유지한다.

### 2-6. 화면 세분화
- **한 화면 한 목적.** Dock의 주 행동 1개가 그 목적이다.
- 틀(Screen variant)은 6종이고, 모든 화면은 하나를 고른다.

| variant | 쓰임 |
|---|---|
| step | 코스 단계(P4~P6) |
| list | 설정·기록(P13·P15·C5·C7) |
| form | 입력(P1·C0 이메일·C2) |
| done | 완료(P7·C9) |
| state | 빈·오류·오프라인 전면 |
| intro | 첫 화면, 40% 예외 |

- 덮개는 Sheet·Dialog다.
- variant가 정하는 것: Dock 상한, 자판 정책, 면 규칙, 간격, 포커스 순서(위 → 본문 → 독, 첫 포커스는 제목). 화면 파일은 dockMaxRatio 같은 숫자를 고르지 못한다.
- 섹션 구분: 흰 면은 누르거나 한 덩어리로 읽는 것, 여백 24~32는 섹션 사이, 스티치 구분선은 화면당 1곳이다. 1px 선만으로는 구분하지 않는다.
- 상태가 여러 개인 한 파일(C0 choose·email·code)은 스택 화면으로 나눈다(Q9).

### 2-7. 상태(빈·로딩·오류·오프라인)
- **StateView** 하나로 처리한다(`kind` loading·empty·error·offline, title·body·action 1개).
- 이미 받은 내용이 있으면 화면을 바꾸지 않고 같은 자리에 띠(Banner)만 띄운다(ChildHome:92 방식).
- 로딩: 자녀는 카드 자리를 유지하는 뼈대로 보여 준다. 어르신은 "불러오고 있어요" 한 줄 + busy 상태로 둔다.
- 오프라인은 아이콘과 문구로 알리고, 색만으로 알리지 않는다. 안내는 1회 읽어 준다.
- 빈 상태: 아이콘 + 한 줄 + 할 일 1개. 칭찬·평가·부재 압박 문구는 금지한다(ease-and-joy C절).

### 2-8. 입력
- **placeholder 금지.** Field에 prop 자체를 두지 않는다.
- 안내는 입력칸 위 label과 hint(여러 줄 가능)로 하고, 자판이 열려도 보이게 한다. 예시도 hint 줄에 쓴다.
- 카드는 통째로 보이거나 통째로 숨긴다. 반쯤 걸치는 상태는 금지한다.

## 3. 공통 컴포넌트와 API 초안
| 컴포넌트 | API 초안 | 대체하는 것 |
|---|---|---|
| Text | `role: 'display'\|'title'\|'heading'\|'bodyLg'\|'body'\|'sub'\|'label'\|'numeral'\|'hand'`, `tone?: 'default'\|'muted'\|'accent'\|'info'\|'done'\|'danger'\|'onAction'`, `style?: LayoutOnlyStyle` | Text20의 size·weight 지정 126건, 원시 Text 4파일(BackBar·SocialButton·RoleChoiceButton·DeleteLink) |
| Heading | `level: 1\|2` (= title·heading + header 역할 자동) | Text20 size 28/24 bold 제목 약 70건, StepHeader 제목 |
| Screen | `variant`(위 6종), `top`, `dock` | 지금 Screen의 dockMaxRatio·fill prop(내부로 숨김) |
| TopBar / BackLink | `TopBar back? title? action?` / `BackLink to: 'prev'\|'course'\|...` | BackBar·ToCourseHomeLink·TextLink(뒤로)·StepHeader 머리 |
| Button | `kind: 'primary'\|'secondary'\|'text'\|'danger'`, `size: 'dock'\|'inline'`, `label`, `icon?`, `loading?`, `disabledReason?` (높이·글자는 audience로 결정) | BigButton·SmallButton·TextLink·DeleteLink·RoleChoiceButton |
| SocialButton | `provider: 'kakao'\|'google'\|'apple'` (ui/로 이동, minHeight만, 가이드 값) | features/child/SocialButton |
| Dock | `primary`, `secondary?`, `note?: string` (초과는 타입 에러) | 화면별 bottom 묶음 |
| Card / Section | `Card tone: 'paper'\|'polaroid'\|'notice'` / `Section title?` | 화면별 card 스타일(KeyboardStep styles.card 등) |
| ListRow | `title`, `subtitle?`, `leading?`, `trailing: 'chevron'\|'switch'\|node`, `onPress?` | SettingsRow·RoleChoiceButton·가족 행 |
| Sheet / Dialog | 이름 유지, 본문은 Text role만, 덮개 규칙 | BottomSheet·Dialog |
| Choice | `items: {key,label,icon?,hint?}[]`, `mode: 'radio'\|'action'`, 1열, 두 줄 허용 | SelectCard, ChildHome 응원 option |
| Field | `label`, `hint?`, `error?`, `kind: 'text'\|'email'\|'otp'\|'word'` (placeholder 없음) | 입력칸 4곳(KeyboardStep·OtpField·ChildLogin 이메일·삭제 확인) |
| Banner / Toast | `tone: 'info'\|'done'\|'danger'\|'offline'` (유지, 자녀 글자도 역할 규칙) | 유지 |
| StateView | `kind`, `title`, `body?`, `action?` | 화면별 로딩·오류 분기(ChildHome.tsx:76-86 등) |

**코드로 강제하는 방법**
1. **타입**
   - 역할 prop만 받는다. Text·Button의 `style`은 레이아웃 속성(margin·align)만 받는 타입으로 좁힌다(lint 우회 차단, r2 RN 소수 의견 채택).
   - Dock 슬롯 수와 Field placeholder 부재도 타입으로 막는다.
2. **ESLint**(features/·app/ 경로에만 적용, ui/ 제외)
   - `no-restricted-syntax`로 막는 것: fontSize·fontWeight·lineHeight·color 리터럴, height·maxHeight 숫자, `numberOfLines`·`maxFontSizeMultiplier`·`placeholder`, Text20 `size`.
   - `no-restricted-imports`로 RN의 Text·TextInput·Pressable을 막는다.
   - **처음엔 warn으로 시작하고, 동결 창(AU-10)에 error로 올린다.**
3. **기준선 테스트** `dsBaseline`: 위반 수를 고정하고 늘면 실패시킨다.
4. **토큰 테스트**
   - tone×surface 허용 조합의 WCAG 대비(어르신 7, 자녀 4.5, 경계 3).
   - 인접 역할 크기 비율 1.2 이상.
   - tokens-v4.json과 생성물의 일치.
5. **RNTL**
   - fontScale 2.0을 주입한 Dock 슬롯·상한 검사.
   - 각 role의 상한·minHeight 존재.
   - Choice·BackLink의 a11y 역할과 라벨.
   - 한계: 실제 줄바꿈·잘림·자판 높이는 측정할 수 없다.
6. **Maestro + 실기기**
   - 글자 1.3·1.5·2.0 × (S25, 320×640)으로 캡처 3화면과 P3~P7 캡처 회귀. 카카오 버튼·입력칸 assertVisible.
   - S25 체크리스트(굵은 글꼴 설정 켬 포함).

## 8. 오너에게 보여 줄 핵심 5줄
1. 단조로운 원인은 글자색이 갈색 하나(본문·버튼·제목이 같은 계열)이고 절반이 볼드라 크기만으로 위계를 만들고 있었기 때문입니다. v4에서는 글자 **역할**마다 크기·굵기·색을 묶습니다. 본문은 차콜·보통 굵기, 제목은 진갈 굵게, 갈색은 누를 수 있는 것에만 씁니다.
2. 잘림은 글을 줄여서가 아니라 **틀** 때문입니다. 하단 영역에 버튼·약관을 너무 많이 넣었고, 자판이 열려도 위 제목이 고정돼 있었고, 입력칸 안에 안내문을 넣었습니다. 버튼은 최소 높이만 정하고, 하단은 "주 버튼 1 + 보조 1"까지만, 입력 안내는 칸 위로 옮기도록 규칙과 타입으로 막습니다.
3. 뒤로 가기는 공용 BackLink 하나로 통일합니다. 화살표 아이콘 + 글자 24 + 알약 모양이고, 누름 영역은 64×120 이상입니다. 글자를 키우면 아래 '오늘 코스로'가 숨던 문제도 없앱니다.
4. 화면은 6가지 틀(단계·목록·입력·완료·상태·첫 화면) 중 하나를 고르고, 글자·버튼·선택지·입력칸은 공통 컴포넌트 14종만 씁니다. 숫자 크기·색 직접 지정은 lint·타입·테스트로 막습니다(처음엔 경고).
5. 빌드 1에는 규칙 전부, 토큰, 핵심 컴포넌트, 오너가 본 3화면, 어르신 코스 P3~P7, C3를 넣습니다(약 40~55h 추정, 기능 동결 1~2일 지연). 나머지 화면은 토큰 효과와 회귀 확인만 하고 빌드 2에서 이행합니다. 카카오 잘림과 P6 자판 문제는 각 레인이 이미 고치고 있습니다.
