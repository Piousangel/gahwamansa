## 0. 핵심 진단: 자녀 화면은 어르신 규칙을 그대로 쓰고 있다
| 증거 | 파일:줄 | 결과 |
|---|---|---|
| 글자 하한이 어르신 20으로 고정 | `ui/Text20.tsx:16-17`(`Math.max(MIN_BODY_FONT, size)`), `tokens.ts:100`(`MIN_BODY_FONT = elder.min`) | `typeScale.child`(30/18/16, `tokens.ts:44`)는 **아무 데서도 못 쓴다**. 자녀 본문도 20 이상이라 제목 28과 차이가 작다 |
| 기본 글자색이 하나 | `Text20.tsx:34`(`color.ink`), `tokens.ts:8-9`(ink = action = `#744821`) | 본문·링크·버튼·제목이 모두 같은 갈색. 오너가 말한 "같은 색에 볼드"가 바로 이것 |
| 버튼·터치가 어르신 값 | `BigButton.tsx:31,107-113`(72/32), `ChildHome.tsx:183`(선택지 `size.touchMin`=64), `ChildChrome.tsx:8,43`("자녀 본문 최소 20, 터치 64") | 자녀 화면 밀도가 어르신과 같다. 정보는 적은데 화면을 꽉 채운다 |
| 하단 영역 40% 상한 안에서 스크롤 | `Screen.tsx`(dock `maxHeight = height*0.4`), `tokens.ts:97`, `ChildLogin.tsx:156-163` | 카카오(60+12)·구글(72)·약관 2줄·연령·이메일 링크가 40%를 넘어 dock 안에서 스크롤되고 **카카오 버튼이 얇은 띠로 잘린다**(캡처①). 위 본문은 비어 있다 |
| 뒤로 링크가 본문과 같은 모양 | `BackBar.tsx:47-49`(22 bold ink, 64) | 크기는 충분하지만 아이콘·면 없이 본문 글과 같은 색이라 "작아 보인다". DECISIONS 182의 자녀 56 규칙과도 다르다 |

결론: 단조로움의 원인은 "크기만 다른 같은 색 볼드" 한 축 위계. 자녀 화면은 **색·굵기·크기·면(배경) 네 축**을 쓰는 별도 규칙이 필요하다.

## 3. C0 로그인 재구성안
- 위(40%): 브랜드 마크 + "가화만사성"(인쇄 제목) + 가치 한 줄("부모님의 하루 답을 매일 받아 봐요", 사실 확인 후, DECISIONS 165) + 작은 예시 카드(C4 답 카드 축소판, 장식). 빈 공간을 "무엇을 받게 되는지"로 채운다.
- 아래 dock: 카카오 → 구글(→ iOS Apple) **같은 높이 56·폭·반경 12**(GUIDELINES 33-37, DECISIONS 442). 약관·연령 2줄은 dock 밖 본문 끝 또는 버튼 아래 16 inkSub 한 덩어리. 이메일 링크는 TextLink 1개.
- 규칙: 소셜 버튼 묶음은 dock 상한에 걸리지 않게 **`SocialButtonGroup`이 자기 높이를 보장**하고 넘치면 약관부터 본문으로 보낸다(지금 `large` 분기만 있음, `ChildLogin.tsx:27,161`). 레이블은 가이드 완성형("카카오 로그인")인지 copy와 대조 필요.

## 4. 응원 시트 선택지 재구성 (Choice 컴포넌트)
- 모양: 왼쪽 작은 그림 아이콘(SVG, 해·차·이불 같은 사물. 하트 금지 DECISIONS 160) + 문구 18 regular + 오른쪽 "보내기 ›" 행동 표시. 아이콘 색만 4개를 다르게(면 색 4종 중 sky·accentSun·accentPeach·doneSoft) 해 구분.
- 상태: 기본 / 눌림(actionSoft) / 보내는 중(스피너, 다른 선택지 비활성) / 보냄(체크 + 토스트). "하나를 누르면 바로 보내요"는 유지하되 **부모님 화면 미리보기 한 줄**("부모님 화면에 이렇게 보여요")을 시트 머리에 두는 안을 제안(오선택 불안 감소). 한 번 탭 즉시 전송은 유지.
- 문구 규칙: 4개 문구는 평가·칭찬이 아니라 안부·감사라 충돌 없음. 다만 "사랑해요, 오늘도 좋은 하루예요"는 두 문장이라 길이가 튄다 → 한 문장 15자 안팎으로 맞추는 규칙 제안. 이모지는 OS마다 모양이 달라 쓰지 않고 SVG 아이콘으로.

## 5. C4 홈 정보 위계
1) 호칭 라벨(16 inkSub) → 2) 답(48~72 inkTitle bold, 유지) → 3) 날짜 칩("오늘"은 done 계열 칩, 지난날은 회색 칩) → 4) 대화 문장(18 regular inkBody) → 5) 응원 버튼(dock 56). 지금은 2를 뺀 나머지가 같은 갈색 bold/regular 20~24라 한 덩어리로 보인다(`ChildHome.tsx:153-164`). 연결 끊김 배너는 noticeSoft 면 + 아이콘으로 카드와 구분.

## 7. 다른 위원과 부딪힐 쟁점
| 쟁점 | 예상 상대 | 내 입장 |
|---|---|---|
| 자녀 본문 18·하한 16 허용 | 접근성 감사관(20 유지 주장 예상) | 자녀(30~40대)는 18이 표준이고 확대 2.0은 유지. 하한 16은 보조 줄만. `Text20` 하한을 역할별로 |
| 색 축 추가(본문색 분리·선택지 아이콘 4색) | 비주얼(종이·갈색 톤 일관성) | 톤은 유지하되 같은 갈색 명도 3단 + 면 색 포인트. 위험 화면(C8)이 잘 읽히는 게 근거 |
| 한 컴포넌트 두 스케일 vs 자녀 전용 컴포넌트 | RN DS 엔지니어 | 컴포넌트는 하나, `scale: 'elder' \| 'child'` 토큰 세트로 분기. 자녀 전용 복제는 반대 |
| 시트 미리보기 추가 | PM(탭 수·범위) | 미리보기는 시트 머리 한 줄이라 탭 수 증가 0. 빌드 범위가 빠듯하면 빌드 2로 미뤄도 됨 |
