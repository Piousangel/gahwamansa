# r2 · 위원 ① 레퍼런스 리서처 A — 반박·표결 (2026-11-19)

r1 8개(A~H)와 r2-ballot.md(V1~V27)를 읽고 썼다. 추가 웹 조사는 하지 않았다. 아래 근거는 r1 A의 레퍼런스 표와 다른 위원 r1의 인용을 쓴다. 시간과 수치는 추정이다.

## 1. 반박 (최대 3)

### 반박 1 — C H1 '어르신이 묻는 날'(V15)을 1순위로 두는 것
- C는 어르신 화면에서 "기다리는 중" 상태를 없애 기다림 압박을 막는다(C §2 H1 위험과 대책). 하지만 **화면에 표시가 없어도 압박은 기억에 남는다.** 어르신이 직접 "물어보기"를 눌렀으니 다음 날 답이 없으면 스스로 알아챈다. 표시를 지워도 "우리 애가 안 답했네"라는 서운함은 지워지지 않는다(추정).
- 레퍼런스에서 반응이 잘 쓰이는 패턴은 **보내는 쪽이 답을 기대하지 않는 신호**다. Aura의 "love"는 올린 사람에게 알림만 가고 회신을 요구하지 않는다(https://blog.bestbuy.ca/smart-home/aura-carver-smart-photo-frame-review). Storyworth도 놓친 주를 나중에 답하게 해서 기다림을 만들지 않는다(https://welcome.storyworth.com/faq). 반대로 BeReal은 상호 공개를 강제했고, 이것이 압박 장치로 비판받는다(https://www.bothrs.com/story/dissecting-the-app-bereal).
- 그래서 순서를 바꾸자고 제안한다. **V16(답을 기대하지 않는 한 탭 신호)을 먼저 넣고, V15는 C가 제안한 오즈의 마법사 1주 실험 결과를 본 뒤 정한다.** 실험 인터뷰에는 "자녀가 답하지 않은 날 기분"을 따로 묻는 문항을 넣는다. C가 정한 판단 기준(자녀 답 비율 70%)은 뒤집어 보면 30%의 날에 어르신의 물음이 답 없이 끝난다는 뜻이다.

### 반박 2 — B의 주 버튼 88dp(V23)
- B 스스로 밝혔듯 14mm 수치는 후속 논문의 인용 문장으로만 확인했고, 원문 표는 미확인이다(B H4, B §미확인). 연구의 탭 대상이 정사각형인지도 미확인이다. 우리 주 버튼은 **너비가 화면 가득**이라서 "14mm 정사각 대상"의 결과를 높이 한 축에만 옮기면 근거가 약하다(추정).
- 높이를 올리면 v4 화면 높이 예산과 부딪친다. 이것은 B 자신의 D-c 항목이고, H의 "단계 3행 + 주 버튼을 스크롤 없이" 레드라인과도 걸린다.
- 그래서 조건부로 적용하자고 제안한다. 88dp 쪽 상향은 **너비가 좁은 대상만**(P5 선택지, P1 키패드 숫자 키) 검토하고, 화면 가득한 주 버튼은 72dp를 유지한다. GrandPad와 Jitterbug에서 배울 점도 크기보다 **같은 자리**와 **글자 라벨**이다(A r1 #21·#22).

### 반박 3 — E S1 '소리 듣고 고르기'(V12)의 문장 틀
- E는 소리 하나를 듣고 "어느 쪽이 떠올라요?"라며 두 장면 중 하나를 고르게 한다(E S1). 그런데 기차 기적 소리를 들려주고 장면 두 개를 보여 주면, 둘 중 하나는 **소리와 맞는 장면**이 된다. 정답 없는 의견형이라고 해도 실제로는 **짝 맞추기 퀴즈**로 읽힌다(추정). Memory Lane Games처럼 정답이 있는 사진 퀴즈가 바로 우리가 피할 반례다(A r1 #19, https://apps.apple.com/us/app/id1517193093).
- BBC RemArc에서 소리는 **맞히는 문제가 아니라 회상 단서**로 쓰였다(https://learningonscreen.ac.uk/viewfinder/articles/bbc-remarc).
- 수정안은 두 가지다. ① 두 선택지 모두 그 소리와 어울리게 만들고 취향을 묻는다(예: 빗소리 → "비 오는 날엔 부침개 / 낮잠"). ② 소리를 P4 사진의 배경으로만 쓴다(A r1 패턴 9). 어느 쪽이든 "소리와 맞는 장면 고르기"라는 형식은 금지한다.

### 자기 수정 (내 r1 제안 2건 철회·축소)
- **V21 철회.** r1을 쓸 때 P6의 '오늘은 넘어갈게요'가 이미 처음부터 보이고, 20초가 지나거나 두 번 실패하면 버튼으로 커진다는 점을 확인하지 못했다(D 202행, H 91·198행). H는 이것을 "안 해도 되는구나" 하는 안도를 주는 설계로 평가했다. 지금 방식이 Storyworth의 "숙제감" 위험을 이미 막고 있으므로 유지한다.
- **V24 축소.** Komp식으로 사진을 맨 위에 크게 두면 H의 레드라인(단계 3행 + 주 버튼 스크롤 없이)과 충돌한다. 대신 **'지금 할 차례' 행이나 독 주 버튼 안에 오늘 사진 작은 썸네일**을 넣는 안으로 줄인다. 이렇게 하면 레이아웃 순서는 그대로 두고 "사진이 와 있다"는 신호만 준다.
