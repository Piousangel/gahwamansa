# r1 · 브랜드·캐릭터 디자이너 (독립 의견, 2026-11-17)
근거로 본 것: design-system/assets/character·album(SVG 28개), content/photos/day-01.jpg, DECISIONS.md(안2, Gemini 허용). day-01은 필름 질감의 사실적 사진이라 품질은 충분하다. 다만 그 결은 "사진" 결이고, 해님(평면 벡터)과 섞일 때는 결이 다르다는 점을 전제로 의견을 쓴다.

## A. 해님 마스코트: **조건부 찬성(하이브리드)**. 최종 원본은 SVG 하나로 둔다
작업 방식(4단계, 각 단계 끝에 사용자 검토 1회):
1. **콘셉트 탐색(Gemini, 3방향 x 4장 = 12장)**. 방향을 프롬프트로 나눈다. ①지금 해님 다듬기(둥근 해·광선 8개) ②"햇살 도장"(한국 전통 도장·인주 느낌, 원 안의 해) ③"창호지 해"(종이 오림·판화 질감). 세 방향 모두 같은 고정 문구를 넣는다: 평면 벡터, 선 1종, 색 3+먹색(#FFC93C/#F59E0B/#FF9E7A/#4E2F14), 흰 배경, 정면, 글자·그림자·그라데이션 없음, 큰 눈·아기 비율 금지.
2. **고르기**. 12장을 40px로 줄여 한 장에 늘어놓고, 실루엣이 해로 읽히는지를 1순위로 고른다. 큰 그림에서 예쁜 안은 탈락할 수 있다.
3. **SVG로 다시 그리기(팀)**. Gemini 그림은 따라 그리지 않고 **비율·인상만 가져간다**(트레이싱 금지). 그 이유는 ①자동 벡터화는 path가 수백 개라 상태를 관리할 수 없고 ②저작권 판단에서 사람이 그린 몫이 클수록 유리할 가능성이 있어서다(정책 확인 필요). 지금의 구성 격자(96 단위, 몸통 r28, 광선 r37~44, 눈 y44, 입 y54, 선 4)를 새 안의 비율로 고쳐 **한 장의 "구성 규격"**으로 고정한다.
4. **파생은 코드로 만든다**. 표정 5종, 도장 3종, 빈 상태 4종은 지금처럼 생성 스크립트 한 곳(몸통·광선 공통, 눈·입·눈썹만 교체)에서 만든다. 그래서 하나를 고치면 전부 같이 바뀐다. Gemini로 표정을 하나씩 뽑으면 표정마다 얼굴형·광선 수가 흔들린다(참조 이미지로 고정이 되는지 미확인). 그러니 표정에는 Gemini를 쓰지 않는다.
- **작은 크기 규칙**: 40 이하에서는 표정을 쓰지 않고 도장(기본 미소, 선 5, 눈 9.2) 하나만 쓴다. 24px 앱 아이콘·알림 아이콘에는 얼굴 없이 해 실루엣만 쓴다.
- **안2와 맞추기**: 마스코트에 질감(종이·크레용)을 넣지 않는다. 앨범 질감은 테이프·스티치가 맡고, 해님은 평면으로 둔다. 둘 다 질감을 가지면 화면이 시끄러워진다.

## B. UI 아이콘: **찬성(Gemini 쓰지 않음)**. 상태색·currentColor·24 격자가 필요하다. 벡터 외에는 답이 없다.

## C. 일러스트형 에셋: **조건부 찬성**
- 스토어 그래픽·스플래시 배경·온보딩 큰 그림은 Gemini를 적극 쓴다. 단, **해님은 합성한 SVG 원본을 얹는다**(Gemini가 그린 해님을 앱 안에 두 버전으로 섞지 않는다).
- 앱 안 빈 상태·완료 축하는 지금 SVG를 유지한다. 160x120에 소품 1개면 래스터가 이점이 없고, 용량·다크모드 대응에서 불리하다.
- 앱 아이콘: Gemini로 콘셉트를 탐색하고 최종은 SVG로 다시 그린다. 1024px에서 16px까지 같은 원본이 필요하다.

## D. 법·표시: **조건부(리드 초안에 동의, 1개 추가)**
- 마스코트를 상표로 등록할 생각이면 **AI 생성물 그대로는 쓰지 않는다**는 원칙을 지금 정해 두자(A-3의 직접 그리기). 보호 가능 여부는 전문가 확인 항목이다(미확인).
- 생성 프롬프트·고른 안·다시 그린 과정을 `docs/design/brand-provenance/`에 남겨 두면 나중에 설명할 근거가 된다.

## E. 어린이 느낌 줄이기: **찬성(같이 다룬다)**. 구체 수치 제안
- **비율**: 눈 간격을 넓히고 눈을 작게. 지금 눈 지름 7.6/몸통 56(약 14%)을 10~12%로 낮춘다. 얼굴을 몸통 중앙보다 약간 아래로 두지 않는다(아래로 내리면 아기 얼굴이 된다). 볼터치 불투명도를 낮추고 크기를 줄인다(타원 10x6.8 → 8x5 후보).
- **표정**: 웃음은 입을 닫은 미소를 기본으로 한다. 입을 벌린 "활짝"은 완료 순간에만 쓴다. 하트를 안는 응원은 자녀가 보낸 응원 표시에만 쓰고 어르신 칭찬에는 쓰지 않는다. 졸림의 z는 귀여움 코드라서 "기다림"(눈을 뜨고 시선을 옆으로)으로 바꾸는 안을 검토한다.
- **말투**: 해님은 "손주"가 아니라 **"동네 이웃·말동무"**로 둔다. 반말·의성어("짝짝짝", "와~")·물결표·과한 감탄은 금지한다. 칭찬은 결과가 아니라 시간에 고마워하는 말로 한다("오늘도 와 주셔서 고마워요"는 좋다. "참 잘했어요"는 선생님 말투라 피한다). 지금 copy praise 중 "잘하셨어요"는 검토 대상이다.
- **움직임**: 통통 튀는 모션을 빼고 천천히 커지는 것 1회만 둔다.

## F. 빌드 1에서 뺄 것(제안)
- 해님 손 흔들기·응원 하트(자녀 응원 표시가 빌드 1에 없으면), 테이프 3종 중 2종(plain만 유지), 스티치 3종 길이(타일 하나로 충분), 폴라로이드 기울기 3종(CSS 회전으로 대체), 종이 결(안2에서 안 씀).
- 남길 것: 해님 기본·활짝·걱정·기다림, 도장 3종, 빈 상태 4종, 모서리 없음.

## 내가 틀릴 수 있는 이유
1. 어린이 느낌은 비율보다 **노랑+원형+볼터치라는 조합 자체**에서 올 수 있다. 수치를 조정해도 해결이 안 될 수 있으니 어르신 5명 관찰이 필요하다.
2. Gemini 참조 이미지 기능이 충분히 일관되면 래스터 표정 세트가 SVG보다 따뜻하고 손이 덜 갈 수 있다(미검증).
3. "직접 다시 그리기가 저작권에 유리하다"는 내 추정은 법률 판단이 아니다.
4. 사용자가 원하는 것이 "더 공들인 그림"이라면, 평면 SVG 고수는 기대에 못 미칠 수 있다.

## 빠진 질문
- 해님이 사진(사실적)과 같은 화면에 놓일 때 결이 어울리는가? 시안으로 비교한 적이 없다.
- 다크모드에서 먹색 외곽선을 어떻게 할지.
- 마스코트 이름 "해님"을 유지할지(어린이 느낌 논의와 연결된다).

## 사용자에게 묻고 싶은 것
1. "신경 써서 뽑으면 좋겠다"가 **그림체를 바꾸자**는 뜻인지, 아니면 **지금 해님을 더 다듬자**는 뜻인지.
2. 해님을 상표·굿즈 등 장기 브랜드 자산으로 쓸 계획이 있는지(있다면 직접 다시 그리기가 필수).
