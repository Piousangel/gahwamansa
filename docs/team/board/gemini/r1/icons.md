## 기술 비교 요약 (값은 추정, 미확인 표시)
| 항목 | SVG(현재) | Gemini 래스터 |
|---|---|---|
| 용량 | 아이콘 1개 약 0.3~1KB, 해님 약 1KB | PNG 1장 수십~수백 KB, 밀도 3벌 필요(추정) |
| 상태 색·굵기 | 코드 한 줄(color, bold 폴더) | 상태마다 새 파일 |
| 작은 크기 | 24~32에서 선명(리드 렌더 확인) | 40 이하에서 뭉개질 위험이 큼 |
| 150%·다크 모드 | 그대로 확대, 색 토큰 교체 | 다시 생성하거나 흐려짐 |
| 대비 측정 | 획 색 하나라 계산 가능 | 측정 어려움 |
| RN | react-native-svg 필요(번들 영향은 앱 개발 미확인) | Image로 바로 표시, 단순 |
| 토스 WebView | 인라인 SVG·img 모두 가능(미확인) | img 가능, 로딩 지연 |

## 내가 틀릴 수 있는 이유
1. 최신 생성 모델은 단색 플랫 아이콘을 꽤 정확히 그릴 수 있고, 생성 후 자동 벡터화(트레이싱)로 SVG를 얻으면 비용이 더 낮을 수 있다(품질 미검증).
2. react-native-svg의 실제 렌더 비용이나 안드로이드 구형 기기 성능 때문에, 큰 해님은 래스터가 더 나을 수 있다.
3. 어르신에게는 질감 있는 그림이 더 따뜻하고 알아보기 쉬워서 벡터의 "깔끔함"이 오히려 차갑게 느껴질 수 있다(관찰 데이터 없음).
4. 팀이 손으로 그리는 속도가 병목이면, 일관성보다 속도가 더 중요한 단계일 수 있다.
