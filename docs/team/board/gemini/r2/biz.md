# 사업 기획 의견 (Gemini 에셋 R2) · 2026-11-17
r1 6개 파일(brand, icons, ux, policy, qa, biz)을 모두 읽고 작성. 수치는 가정.

## 동의하지 않는 의견 2개와 반박
1. **정책 F "스토어 그래픽·아이콘 최종본은 상표 검색 결과 이후"**: 조건부 반대.
   - 순서는 맞지만 "변리사 확인까지 기다림"으로 해석되면 11/25 Play·토스 제출이 막힌다.
   - KIPRIS 검색은 무료이고 오늘 사용자가 직접 할 수 있다(사실: 공개 검색 서비스). 그러니 **KIPRIS 1차 검색만 제출 전 필수**로 둔다. 변리사 확인과 출원은 출시 후로 미룬다.
   - 앱 이름은 스토어에서 바꿀 수 있으나 리뷰·인지도가 쌓인 뒤 바꾸면 비용이 커진다(가정). 그래서 결정 시점은 "출시 전 검색", 출원은 "유료 전환 전"이 맞다.
2. **브랜드 A의 4단계, 단계마다 사용자 검토 1회(3방향 12장, 40px 비교, SVG 재작도, 구성 규격)**: 빌드 1 기준 반대.
   - 방법은 옳다. 하지만 마스코트 재설계는 빌드 1 사업 가치(연결, 코스, 자녀가 답 봄)에 닿지 않는다. 사용자 검토 4회는 1인 개발 일정에서 그대로 지연이 된다.
   - 빌드 1은 기존 SVG를 유지하고(정책·QA·UX·icons와 일치), 4단계는 빌드 2에서 진행한다. 이때 첫 결과물은 앱 아이콘 1개로 좁힌다.

## 바뀐 입장
- 앱 아이콘: r1의 "앨범·집 상징 우선"을 수정해 브랜드 r1의 **"얼굴 없는 해 실루엣(+도장 결)"** 쪽으로 기운다. 16~24px에서 앨범·집 그림은 뭉개진다. 해 실루엣은 작은 크기에서 읽히고, 해님·이름과 한 줄로 이어진다. 어린이 느낌도 얼굴을 빼면 줄어든다(가정).
- C: 앱 안 래스터는 빌드 1에 0장(QA 규칙 동의). Gemini는 앱 밖(스토어·토스 썸네일·마케팅 카드)에만 쓴다.

## 쟁점: "가화만사성" 식별력 약함의 함의
- 사업적 의미: 등록이 어렵다면 이름을 지킬 수 없다. 누구든 비슷한 이름의 앱을 낼 수 있고 검색 결과에서 묻힌다(가정, KIPRIS 미조회).
- 권고: (1) 이름은 "**가화만사성 + 식별 요소**" 결합형을 후보로 둔다. 예: "해님 가화만사성", "우리집 가화만사성". 결합 표장이 식별력을 높이는지는 미확인, 변리사 확인 필요. (2) 보호의 무게는 이름보다 **해 도장 로고(도형)**에 둔다. 이 로고는 사람이 다시 그린 SVG여야 한다(브랜드·정책 공통). (3) 오늘 KIPRIS에서 "가화만사성" 선등록을 검색한다. 동일·유사 선등록이 앱·교육·소셜 관련 분류에 있으면 출시 전 대안명으로 바꾼다.
- 스토어 검색 관점: 관용구라 검색어 경쟁이 심할 수 있다(미확인). 스토어 부제에는 "부모님과 매일 이야기 거리" 같은 설명형 키워드를 붙인다.

## 빌드 1 에셋 범위 최종안
- **앱 안(SVG만)**: 해님 표정 3종(기본·활짝·걱정), 도장 1종, 빈 상태 1장(해님 88 + 문구), UI 아이콘 중 실제 쓰는 것만(약 15종, icons 안). 응원 수신(P8)이 빌드 1이므로 응원 표시 해님 1종은 유지.
- **앱 밖(Gemini 탐색 → 사람 정리)**: 앱 아이콘 1개(얼굴 없는 해 실루엣, 사용자가 3안 중 선택), 토스 썸네일·Play 피처 그래픽 1장, 스크린샷 템플릿, 스플래시 1장(단색+로고).
- **뺄 것**: 해님 재설계, 표정 2종·자세 변형, 온보딩·축하 래스터, 테이프·스티치 변형 다수, 마케팅 캐릭터 시리즈.
- **제출 전 게이트**: KIPRIS 1차 검색, Gemini 상업 이용 약관 확인. 둘 다 미확인이면 스토어 그래픽을 기존 SVG로만 구성한다(대체 가능해서 일정 위험 0).
