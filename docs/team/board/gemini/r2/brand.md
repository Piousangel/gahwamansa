# r2 · 브랜드·캐릭터 디자이너 (2026-11-17)
읽은 것: r1 6개(biz·brand·icons·policy·qa·ux). 사람 반응·법 판단은 여전히 가정이다.

## 동의하지 않는 의견 2개와 반박
1. **사업: "말투만 빌드 1, 비율·표정 재설계는 빌드 2"와 "앱 안 28개 SVG는 다시 그리지 않는다".**
   - 반박: 아이 느낌의 원인으로 UX가 코드에서 짚은 볼터치·점 눈·활짝 입은 path 몇 개를 고치는 일이다. 생성 스크립트 한 곳에서 수치(눈 14%→11%, 볼 10x6.8→8x5, 활짝 입 축소)만 바꾸면 28개가 같이 바뀐다. 반나절 분량으로 추정하며 미검증이다.
   - 빌드 2로 미루면 토스 첫 노출 스크린샷에 지금 얼굴이 굳는다. 사업이 강조한 "한 번 보면 다시 알아보는 일관성"을 지키려면, 출시 전에 고치는 편이 오히려 싸다.
   - 판화·도장풍으로 그림체를 바꾸는 큰 재설계는 사업 말대로 빌드 2가 맞다.
2. **UX: "판화·도장 같은 어른스러운 평면 그림"으로 그림체 전환 + 자녀 화면 해님 없음.**
   - 방향에는 공감한다. 다만 판화풍 질감은 40~44px 도장에서 가장 먼저 뭉개진다. 또 안2의 테이프·스티치가 이미 질감을 맡고 있어 해님까지 질감을 가지면 화면이 시끄러워진다(r1 A).
   - 수정안: 질감이 아니라 **형태 언어**만 가져온다. 선을 더 곧고 단정하게, 광선은 짧고 같은 길이로, 원형 인주 도장 테두리를 쓴다. 판화풍 질감은 앱 밖(스토어·스플래시) 래스터에서만 쓴다.
   - 자녀 화면은 해님을 **완전히 빼기보다 도장(연속일)만** 남기자. 도장은 부모가 한 일을 보여 주는 기록이라 감시의 반대편에 있다. 말풍선·얼굴 해님은 자녀 화면에서 빼는 데 동의한다.

## 바뀐 입장
- **표정 3종 축소에 동의(UX·QA·아이콘 일치).** 빌드 1은 기본·활짝·걱정 3종과 도장 1종만 쓴다. 졸림은 z가 귀여움 코드라 빼고, 기다림은 기본 표정과 "잠시만요" 문구로 처리한다. 응원 하트·손 흔들기는 빌드 2다. 도장 3종 기울기는 같은 파일 하나를 CSS로 돌리는 것으로 대체한다.
- **사업의 "앱 밖은 Gemini, 앱 안은 SVG 고정"에 찬성.** QA 조건(앱 안 래스터 0장, 빌드 1)과 합치면 검수 규칙이 한 줄로 끝난다. 앱 아이콘은 정책 조건대로 사람이 다시 그린 SVG로 만든다.
- **정책의 "생성물을 그대로 쓰지 않고 사람이 다시 그린 SVG"에 찬성하고 강화한다.** 트레이싱·자동 벡터화도 금지한다(아이콘 위원의 자동 벡터화 대안 기각). 생성 원본·프롬프트·고른 이유·다시 그린 파일을 날짜별로 `docs/design/brand-provenance/`에 보관한다. 프롬프트에 "○○ 스타일" 같은 작가·캐릭터명은 넣지 않는다.
- **빈 상태 일러스트 4종 축소.** UX 지적("오류 순간에 큰 그림은 놀람")을 받아들여 앱 안 빈 상태·오류는 해님 56과 문구로 처리한다. 160x120 그림은 완료 축하 1장만 남긴다.

## 남은 이견
- 자녀 화면 도장 유지(나)와 해님 전면 제외(UX)가 갈린다. 사용자 결정 또는 자녀 인터뷰가 필요하다.
