# QA·접근성 의견 (Gemini 에셋 R2) · 2026-11-17
r1 6개를 모두 읽었다. 수치는 가정, 토스 WebView 실측은 미확인.

## 동의하지 않는 의견 2개와 반박
1. **brand F(빌드 1에 표정 4종(기본·활짝·걱정·기다림) + 도장 3종 + 빈 상태 4종 유지)**: 일관성 논리는 맞지만 검증 범위가 커진다. 표정 하나가 늘 때마다 "쌍별 판별 테스트"가 3쌍에서 6쌍으로 늘고, 빈 상태 4종은 각각 오류 화면 문구·alt·150% 레이아웃 회귀를 만든다. 반박안: 빌드 1은 표정 3종(기본·활짝·걱정), 도장 1종(얼굴 없음 또는 기본 미소, 40px 이하에서는 표정 판별 대상 아님), 빈 상태는 해님 기본 + 문구 한 줄로 통일. "기다림"과 도장 변형은 생성 스크립트에 남겨 두되 화면에 쓰지 않는다(코드 비용 0, 검증 비용 0).
2. **UX C/F(완료 축하만 그림을 키운다, 완료 축하 1장 유지)**: 완료 순간은 `record_session_step` 응답을 기다리는 화면이라 2초 반응 규칙과 겹친다. 큰 래스터가 늦게 뜨면 "완료가 안 됐나" 하는 혼란이 생긴다(가정). 반박안: 완료 축하는 SVG 해님(활짝) + 도장이 찍히는 짧은 동작(동작 줄이기 설정 시 생략)으로 하고, 큰 일러스트는 빌드 2에서 실측한 뒤 판단한다.

## 바뀐 입장
- r1의 "앱 안 래스터 금지"를 **"앱 안 UI 에셋(마스코트·아이콘·빈 상태·축하)은 SVG만, 콘텐츠 사진은 별도 규칙"**으로 고친다. 사진은 기능 자체라 금지 대상이 아니다(icons·policy·UX 모두 사진은 래스터로 전제).
- 사진 규칙(옛날 사진, 현재 JPEG 장당 약 340KB): ① 번들에 넣지 않고 서버에서 그날 1장만 받는다. ② 표시 폭 × 2배(약 780px, 가정)로 리사이즈한 WebP를 목표로 하고 장당 150KB 이하를 예산으로 둔다(현재 대비 약 절반, 실측 필요). ③ 코스 홈에서 미리 받아 두고(prefetch), 사진 단계에서는 정해진 크기의 자리를 먼저 그려 2초 안에 반응한다. 실패하면 "다시 불러오기" 버튼 1개를 보여 준다(designer §6). ④ 사진 위에 글자를 올리지 않고, 사진 제목을 alt로 쓴다. ⑤ "AI로 만든 그림" 고지가 사진 단계에 매번 보이는지를 회귀 항목에 넣는다(policy·UX D에 동의, 사용자 결정 전까지 판정 보류). 측정은 느린 LTE 실기기 3회, 사진 표시까지 3초 이내(가정)를 경고선으로 둔다.
- E에서 UX의 "말투가 그림체보다 아이 취급을 더 만든다"에 설득됐다. QA 금지어 grep 목록에 "짝짝짝", "와~", 물결표, 느낌표 연속, "참 잘했어요"를 추가하자고 라이터에게 제안한다.

## 표정 3종 축소 시 검증 범위
- 크기: 실제로 쓰는 슬롯만 검사한다(icons 기준 88·72·56). 40 이하(도장·알림)는 표정 판별을 하지 않고 실루엣이 해로 읽히는지만 본다(brand 규칙과 같음).
- 사람: 3표정 × 3크기 = 9장을 팔 길이에서 보고, 판별자 3명 중 어르신 1명 이상이 맞혀야 한다. 56px 이상에서 정답률 90% 이상이면 합격(가정). 회색조로도 1회 본다.
- 자동: 3쌍(기본-활짝, 기본-걱정, 활짝-걱정)의 렌더 픽셀 차이 비율을 낸다. 임계값은 사람 결과로 보정한 뒤 회귀 경고로만 쓴다.
- 의미: 걱정 표정은 오류 화면에서만 쓰고 "어르신 탓" 느낌이 없는지 관찰 질문 1개로 확인한다.

## 에셋 레지스트리 단일 참조
- `assets-manifest`(또는 앱의 registry 파일)를 하나의 출처로 둔다. 항목마다 id, 파일 경로, 형식(svg/webp), 표시 크기, 밀도, alt(장식이면 빈 값), 쓰는 화면, 출처(사람/Gemini 참고/생성)를 적는다.
- 빌드 전 자동 검사(스크립트는 개발 몫): 코드가 경로를 직접 import하는 것 0건(grep), 레지스트리 id가 모두 실제 파일과 맞을 것, 쓰이지 않는 파일 경고, alt 필드 누락 0건, 형식·용량 예산 위반 0건, 앱 안 UI 에셋 중 래스터 0건.
- 회귀: 에셋을 바꾸면 id는 그대로 두고 파일만 교체한다. 바뀐 id가 쓰이는 화면 목록을 레지스트리에서 뽑아 그 화면만 스크린샷 비교를 다시 승인한다. 시안·앱·테스트가 같은 id를 쓰면 코드 변경은 0이다.
- 표정 파생은 brand의 생성 스크립트가 원본이다. 레지스트리에는 그 결과 파일만 등록해 원본이 두 개로 갈라지지 않게 한다.
