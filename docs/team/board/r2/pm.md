# PM 의견 (R2) · 2026-11-17
r1 7개(pm, biz, ux, writer, policy, qa, dev)를 모두 읽고 작성. 시간·확률은 추정, 외부 사실은 문서 기준이고 미확인은 표시.

## 동의하지 않는 의견 2개와 반박
**1. UX의 H 대안: "엄마 소식이 3일째 없어요. 안부 전화 한번 어때요?"(자녀 선택 알림). biz의 "최근 3일 기록 없음이면 가치 없음" 논리도 같은 계열.**
- 반박: 이 알림은 이름만 바꾼 "아직이에요"다. 어르신 입장에서는 "며칠 안 열면 자녀에게 알려진다"는 말이 곧 감시이고, UX 자신이 구조 문제 C로 짚은 위험(독촉 전화 → 어르신이 앱을 끔)을 되살린다. 보드 배경이 "목표는 대화 늘리기, 감시가 아니다"다. 안부 확인은 서비스 약속 밖이며 의료·안전 기능으로 오해될 소지도 있다(정책 확인 필요, 미확인).
- 부재 신호 문제는 맞지만 해법은 알림이 아니라 **빈 화면 설계**다: 소식이 없으면 "가장 최근에 고른 답 + 날짜"를 남기고 그 아래 자녀 행동(응원 보내기, 오늘의 대화 소재)을 둔다. 자녀가 날짜를 보고 스스로 판단하게 한다. 이 알림이 필요하다는 증거(자녀 이탈이 무소식 때문이라는 데이터)는 아직 없으므로 **출시 후 가설로 보류**한다.
**2. dev의 G: 빌드 1에서 리포트·푸시 후순위, 자녀 홈은 "오늘 했는지 + 고른 답"만.**
- 반박: (a) "오늘 했는지"는 쉬는 날 곧 "안 했음"이라 A·H와 모순된다(내 r1, writer·policy·QA도 이 조건을 달았다). (b) 리포트를 통째로 빼면 자녀가 "고른 답"을 쌓아 볼 곳이 없어 서비스 핵심 가치(DECISIONS: 밸런스 게임 → 자녀 리포트)가 사라지고, 전환 분모("첫 리포트를 본 자녀")가 정의 불가능해진다. 최소형(최근 고른 답 목록 N개)은 C4 안 같은 데이터라 공수가 작다(가정). 푸시 후순위에는 동의.
- 수정: 자녀 홈 = 최근 고른 답 + 날짜, 같은 화면의 "지난 답 보기" 목록 1개를 최소 리포트로 삼는다. 상세 리포트·"곧 유료" 시트·답변 이력은 빌드 2.

## 바뀐 입장
- **H**: UX·writer·QA가 "침묵은 고장으로 읽힌다"고 일치해서 내 "부재 시 어제 답 표시"에 **중립 상태 문구 허용 규칙**을 더한다. 금지어(아직·못·안 함·끊김)는 grep 게이트(QA 제안 채택), 허용은 사실 서술("마지막 답: 어제 · 나무 아래 쉬기")뿐.
- **동의 거부 범위(③)**: policy의 구멍 지적을 받아들인다. 거부하면 답뿐 아니라 참여 여부도 자녀에게 보내지 않는다(자녀 홈은 "연결만 됐어요" 중립 상태). 내 r1은 이 충돌을 보지 못했다. dev 말대로 UI 숨김이 아니라 서버(sessions_read)에서 닫아야 한다.
- **F·일정**: dev의 82~110h(전체)·55~65h(최소)·11/30 제출 확률 30~40%를 받아들여 "11월 토스 제출"은 목표에서 내린다. 근거 없는 내 40~60h보다 dev 분해가 구체적이다. 대신 Play 시계를 **지금 시작**한다(아래 F).
