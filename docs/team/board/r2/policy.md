# 정책·개인정보 의견 (R2)
2026-11-17. r1 7개 전부 읽음. 법률 자문 아님, 법적 판단은 "전문가 확인 필요".

## 쟁점 ① 서버 반영 (dev 지적에 동의, 최소 조치)
사실(dev r1): 자녀가 `daily_sessions`를 RLS로 직접 읽는다. UI 숨김만으로는 동의 문구와 실제 노출이 달라질 수 있다(자녀 앱을 우회해 API를 호출하는 경우). 정책상 최소 조치:
1. 자녀의 `daily_sessions` 직접 select 제거, 자녀 노출은 `child_today_summary()` 같은 RPC 하나로만. RPC가 돌려주는 항목 = 동의 문구에 적힌 항목(1:1). 연속일·단계·소요시간은 RPC에 없음(서버 내부·어르신 도장용으로만).
2. **동의 상태를 서버에 저장**(철회 포함, 문구 버전·시각)하고 RPC와 자녀의 `answers` 읽기 정책이 `동의=켜짐`일 때만 값을 준다. 철회 즉시 자녀 응답이 비어야 한다. 이 게이트가 없으면 "철회했는데 자녀가 계속 본다"가 생긴다(가장 큰 위험).
3. pgTAP 2건: 자녀가 세션 행을 못 읽음 / 동의 꺼진 가족에서 자녀 RPC 결과가 빔. 문구-화면-RPC 3자 대조표를 게이트에 추가(QA 제안 지지).
4. 분석 도구로 보내는 이벤트에 답 내용을 넣지 않는다(방침 1절과 일치).

## 쟁점 ② 동의 거부·철회 시 "오늘 했는지" (최종 권고)
**숨긴다.** 거부·철회한 가족의 자녀 홈에는 답도 참여 여부도 없고 "엄마가 이어서 하면 여기에 보여요" 같은 중립 상태만 둔다. 이유: 참여 여부도 어르신의 활동 기록이라 거부 의사에 포함되어야 일관적이다. 사용자 관점: "싫다고 했는데 왔는지는 보인다"는 거부의 의미를 없앤다. r1 때는 "일관적"이라고 했지만 이제 **권고**로 올린다.
- 동의한 경우 공개 범위는 PM안(고른 답과 그 날짜)으로 맞춘다. "오늘 했는지"는 "오늘 날짜의 답이 있는가"로 **파생**되므로 별도 항목이 아니고, 동의 문구에는 "오늘 했는지도 보여요"를 쓴다(UX·writer 지지).
- 쓰지 못하는 것: 연속일, 단계 칩, 소요시간, "아직", 며칠째 없음(아래).

## 반박 2개
**1. UX: "엄마 소식이 3일째 없어요" 선택 알림(r1 H).** 반대. (a) "N일째 없음"은 어르신 활동 부재를 자녀에게 보내는 **새 수집·제공 항목**이다. 동의 문구에 한 줄 넣는 정도로 해결되지 않고, 어르신 거부 시 쓸 수 없는 목적 외 안부 감시가 된다(전문가 확인 필요). (b) 앱을 안부 확인 서비스로 만든다. 그러면 알림이 안 온 날을 "무사"로 읽는 책임 문제가 생긴다. (c) 감시 회피라는 A의 취지와 충돌. 대신: 빈 상태는 중립 문구 + "안부·안전 확인 서비스가 아니에요" 고지, 자녀가 직접 응원을 보내는 행동으로 연결(biz·PM 지지). 필요하면 v2에서 **어르신이 직접 켜는** "며칠 쉬면 자녀에게 알려 줘요" 옵션으로 검토.
**2. biz: 주간 요약 "이번 주 N일 함께"(r1 A).** 반대. 일수 집계는 연속일·참여 빈도의 다른 얼굴이다. 못 한 날 수가 역산되고, 동의 문구에 없는 항목이다. 허용 대안: 주간에는 "이번 주 고른 답 모음"(답 자체와 날짜)만. 빈도 숫자는 자녀 화면에 두지 않는다.

## 바뀐 입장
- A: 조건에 서버 게이트(동의 상태 저장)를 필수로 올림. r1은 문구 일치만 말함.
- 쟁점 ② : "숨길지 사용자 결정"에서 "숨긴다 권고"로.
- H: r1의 "연결 끊김은 별도 알림"은 유지하되 범위를 좁힘. 시스템 상태(연결 해제·토큰 무효)만 알리고 사용 행동 부재는 알리지 않음.
- B: dev·biz의 "서버 재연결 경로 유지, 문구만 추가"를 수용(정책상 문제 없음, 단 재연결 시 **동의 재확인**).

## 쟁점 ③ 법률 전문가 확인 항목
**출시 전 필수(전문가 의견 없이 공개하면 위험이 큰 것)**
1. 방침 법정 필수 항목 점검과 처리위탁·제3자 제공·국외 이전 고지(Supabase 리전 미정, FCM, 토스·카카오 경유). 방침 4절 "확인 필요" 해소.
2. 동의 구조: 답 공개 동의와 푸시 동의 분리 요건, 문구의 충분성, 철회 시 기존 기록 처리, 거부 시 불이익 고지.
3. 어르신 대리 동의(자녀가 어르신 폰에서 눌러 주는 경우)의 유효성과 완화 문구.
4. 14세 미만 가입 방지 문구와 법정대리인 동의 요건(자녀 가입 연령 확정 포함).
5. 삭제 처리 기한, 백업 보존 기간, 법정 보존 의무 여부, 보호책임자 지정 의무(개인 운영자).
6. (토스 트랙 착수 전) anonKey의 개인정보·가명정보 분류, 토스와의 위탁/제공 관계, 연결 해제 시 삭제 트리거.
**후순위(출시 후 가능, 조건 유지 시)**
7. 건강정보 민감정보 해당 여부: 리포트가 상태 해석을 하지 않는 동안 후순위. 해석 기능 추가 전 필수로 전환.
8. 식약처 의료기기·광고 규정: 금지·허용 표현 가이드 준수 전제로 후순위. 스토어 설명 확정 전 표현 점검은 내부로 가능.
9. 카카오 로그인 동의항목·심사 요건(실무 확인이라 법률 아님).
10. 부재 알림·주간 요약 같은 범위 확장 기능(도입 시점에 필수).
