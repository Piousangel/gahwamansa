# UX 감사관 의견 (R2)
r1 7개 파일을 모두 읽은 뒤 작성. 표기: 사실=r1·문서 근거, 가정=내 추정. 시간 수치는 dev·pm의 추정을 인용한 것이며 내가 잰 값이 아니다.

## 동의하지 않는 의견 2개와 반박
**1. 라이터: "오늘은 아직 소식이 없어요. 천천히 기다려 봐요"를 자녀 화면 한정으로 허용(H 후보).**
- 문제: 아침 7시에 이 말을 읽는 45세 직장인(가정)에게 "아직"은 "곧 와야 한다"는 기대를 심는다. 감사 C4_pending이 지적한 독촉 경로 그대로다. 자녀 화면에서도 "아직"이 독촉이 되는 것은 어르신 화면과 같다.
- 대안: 못 한 날은 **어제 고른 답과 날짜**를 보여 주고 "어제 고른 답으로 이야기해 볼까요?"로 잇는다(라이터 후보 3번, pm·biz와 같은 방향). 금지어 목록에 자녀 화면의 "아직"도 넣는다.
**2. 사업 기획: F 대안 시나리오 1 "자녀가 어르신 대신 코스를 하고 전화로 맞춰 본다"(자녀 폰 대행).**
- 문제: 어르신이 직접 쓰지 않으면 자녀 홈의 "엄마의 선택"이 거짓이 된다. 자녀가 맞춘 답을 엄마의 답처럼 읽게 되고, 이후 진짜 어르신이 연결되면 신뢰가 깨진다. biz가 스스로 쓴 단점("퀴즈 게임으로 변질")이 결정적이므로 시나리오에서 제외를 권한다.
- 같은 맥락의 보조 반박(biz 주간 요약): "이번 주 N일 함께"는 N=2인 주에 "5일 안 했다"로 읽힌다. 주간 수가 아니라 **누적 "함께한 날 N일"(줄지 않는 수)**만 쓴다.

## 바뀐 입장
1. **F 순서를 바꾼다.** r1의 "자녀 입구=토스, 어르신=Play 병행"은 dev 견적(토스 전체 82~110h, 11월 제출 확률 30~40%, 가정)을 보면 11월에 둘을 동시에 낼 수 없다. 어르신의 첫 5분이 가장 중요하므로 **어르신 입구(Play 앱, 자녀가 설치)를 먼저**, 토스는 자녀 전용 최소 슬라이스로 후행. dev(Play 복귀가 가장 쌈)·pm(둘 중 하나만 현실적)에 동의.
2. **A에서 "오늘 했는지" 표시를 포기한다.** r1의 "안 한 날 중립 한 줄"보다, pm 지적(오늘 했는지는 H와 자기모순)과 dev 제안(서버가 미참여 데이터를 안 줌)이 더 안전하다. 자녀가 보는 날짜가 곧 신호이므로 정직하다.
3. **H의 "며칠 무소식 안부 알림"은 빌드 1에서 뺀다.** policy의 "안부 확인 서비스로 오해" 우려와 어르신 동의 문구 변경 부담 때문이다. 빌드 2 후보로만 남기고 사용자 결정을 받는다.
4. E의 호칭을 "번호 발급 전 필수"에서 pm 제안(발급 화면 선택 입력 1칸, 기본 "부모님")으로 완화한다. 가입 이탈이 늘 수 있다는 지적이 타당하다.

## 쟁점별 최종 형태
**① A·H: 자녀 홈에 무엇이 어떤 말로 보이는가**
| 상태 | 자녀 홈 (한 화면, 위에서 아래) |
|---|---|
| 오늘 답 있음 | "{호칭}이 오늘 가을을 고르셨어요" + 사진 이름 + 대화 소재 한 줄 + 응원 보내기. 누적 "함께한 날 12일" |
| 오늘 답 없음 | "어제(11월 16일) {호칭}이 가을을 고르셨어요. 어제 고른 답으로 이야기해 볼까요?" + 응원 보내기 |
| 한 번도 답 없음(연결 직후) | "{호칭}과 연결됐어요. 고른 답이 생기면 여기에 보여요" |
| 동의 거부(또는 철회) | "{호칭}과 연결됐어요. 고른 답은 {호칭}이 준비되면 보여요" (거부 사실을 "남기지 않기로 했어요"로 쓰지 않음, writer 안 방향). 응원은 그대로 가능 |
- 제거: 단계 칩 3개, 연속일, "오늘 코스 n/3", "아직이에요", "대기·진행 중". 서버에서 자녀의 `daily_sessions` 읽기를 닫아 UI가 아니라 데이터로 막는다(dev, 사실: 현재 RLS로 열려 있음).
- 동의 문구(어르신): "고른 답과 날짜를 자녀분이 볼 수 있어요 / 그 밖의 것은 안 보여요". 서버가 닫혀 있으면 "그 밖의 것은 안 보여요"가 거짓이 아니다(writer 후보 3 조건 충족). 거부 시 참여 여부도 자녀에게 보내지 않는다(policy 조건 2에 동의, 일관성).
- 응원 추천 문구는 상태에 맞춘다. 답이 없거나 거부 상태에서는 "오늘 고른 답이 궁금해요" 미리 선택 금지(감사 C4_cheer).
- H 원칙 개정안: "못 한 날을 알리지 않는다"가 아니라 **"못 한 날을 평가하지 않는다"**. 금지: "아직", "안 했어요", "미완료", "끊김", 붉은색. 허용: 날짜가 붙은 과거 답. 단 **연결이 끊긴 것(앱 삭제·토스 탈퇴·기록 지움)은 숨기지 않는다**: "{호칭} 폰과 연결이 풀렸어요. 새 번호를 만들어요"(policy 제안 4).
- 온보딩에 "안부·안전 확인 서비스가 아니에요" 한 줄(policy 제안 2)은 약관·첫 화면 아래 작은 글로만 둔다. 자녀 홈에는 쓰지 않는다(가치 약화, 가정).
**② F: 어르신이 토스를 안 쓸 때**
- T0 질문을 둘로 늘린다: (a) 토스 설치·인증이 끝나 있는가, (b) **혼자 토스에서 우리 앱을 찾아 열 수 있는가**(qa·biz 질문과 합침). 3가구는 일화이므로 "아니오"만 신뢰한다(biz).
- 판정: (b)가 3가구 중 한 가구라도 "아니오"이거나 도달 경로가 미확인이면 어르신 입구는 Play 앱(자녀가 직접 설치, 번호 전달은 말로)이다. 모두 "예"일 때만 토스 어르신 화면을 빌드한다.
- 첫 5분 지표(가정): 설치 후 번호 입력 화면까지 3탭 이내, 자녀가 옆에 있는 경우를 기본 흐름으로 설계한다(r1 질문 1 유지). 토스 안 어르신 단독 검증은 qa 말대로 대리 시연이 안 되므로 판정에서 분리.
- 토스는 자녀 전용 최소 슬라이스(식별·번호 발급·홈·응원·삭제, dev 기준 약 12~16h 화면 + 서버 인증)로 12월 이후. 자녀가 부모에게 미니앱 링크를 보내는 것이 "자사 서비스 이동 유도"에 걸리는지는 미확인(biz 질문 2).
**③ qa "자체 글씨 크게 보기" vs dev 공수**
- 사실: 토스는 핀치 줌 비활성이고 OS 글자 확대의 WebView 반영은 미확인(qa·04). Play RN 앱은 OS 확대를 따르므로 이 설정이 필수가 아니다(가정, 실기기 확인 필요).
- 타협: **토스 클라이언트에만** 빌드 1에 포함하되 최소형으로 한다. (1) 모든 글자를 처음부터 rem+CSS 변수로 쓴다(재작성 화면이라 추가 비용이 작다, dev 확인 요청). (2) 선택지는 2단계("보통/크게", 크게=1.5배) 토글 1개. (3) 위치는 첫 코스 시작 전 1회 "글씨가 잘 보이세요? [더 크게]" + 설정(C7)에 유지. (4) 검증은 대표 6화면(P1·P3·P4·P5·P6·C4)만, 150% 전 화면은 후순위.
- 컷 금지(pm과 동일): keep-all, 스크롤 영역 지정(P4·P5·P6·P9, C0~C4·C8). 비용이 작고 어느 트랙이든 가용성에 직결된다(감사 Top 3·4).
