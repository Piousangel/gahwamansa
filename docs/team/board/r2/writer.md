# UX 라이터 의견 (R2) · 2026-11-17
r1 7개를 모두 읽었다. 관점은 "말"이다. 확인하지 못한 것은 "가정"으로 표시.

## 동의하지 않는 의견 2개와 반박
1. **UX r1 H: "엄마 소식이 3일째 없어요. 안부 전화 한번 어때요?" 선택 알림 + 어르신 동의에 "며칠 안 열면 자녀분께 알려요".** 반박: (1) 문장은 중립이지만 "N일째 없음"은 결석 일수를 세는 것이라 "아직 안 했어요"와 같은 신호다. (2) 어르신 동의 화면에 "안 열면 알려요"를 쓰면 어르신은 "열어야 한다"는 압박을 받고, 동의 문구가 가장 무서운 문장을 품게 된다. (3) 정책 r1이 지적한 대로 안부·안전 확인 서비스로 오해되면 의료·안전 책임 문제가 생긴다(미확인). 대안: 일수를 세는 알림은 빌드 1에서 빼고, 부재 시 "가장 최근 답과 날짜"를 보여 준다(PM안). 연결이 끊긴 경우만 "연결이 끊겼어요"로 따로 알린다(정책 r1 4번 동의).
2. **Dev r1 G: 자녀 홈 = "오늘 했는지 + 고른 답".** 반박: "오늘 했는지"는 안 한 날의 부재 표시가 되어 H와 자기모순이다(PM r1 A가 같은 지적). 답에 날짜가 붙으면 했는지는 이미 알 수 있고, 안 한 날은 "어제 답"이 보이므로 화면이 비지 않는다. 서버에서 daily_sessions를 자녀에게 닫는 Dev의 제안(A)은 찬성이며, 그러면 "안 한 날" 개념이 자녀 화면에 생기지 않는다.

## 바뀐 입장
- r1에서 "자녀 화면 한정으로 '아직'과 '오늘은 아직 소식이 없어요' 허용"이라 썼으나 **철회**한다. 부재를 말로 만들면 어느 화면이든 독촉이 된다(PM, UX 근거).
- r1 A의 "오늘 했는지를 좋은 소식으로" 보여 주자는 안을 **"가장 최근에 고른 답 + 날짜"로 바꾼다.** 동의 문구와 화면이 같아지고 문구가 짧아진다.
- 호칭 기본값은 "부모님"(UX·PM와 같음). 호칭을 고르는 순서는 번호 만들기 전(UX 의견 채택).
- "안부 확인 서비스가 아니에요" 고지(정책)는 찬성하되 어르신 동의 화면이 아니라 자녀 온보딩·설정에 둔다.

| 안건 | 표결 | 확정 조건 한 줄 |
|---|---|---|
| A | 조건부 찬성 | 자녀에게는 "최근 고른 답+날짜"만 보이고 단계 칩·연속일·"아직"은 UI와 서버(RLS) 모두에서 닫는다. 동의 문구를 이 범위에 맞춘다 |
| B | 조건부 찬성 | 재연결 변형은 보류, "연결이 끊겼어요. 자녀분께 새 번호를 받아요" 1장은 두 트랙에 둔다 |

| H | 조건부 찬성 | "평가하지 않는다"로 고쳐 쓴다. 못 한 날은 침묵이 아니라 어제 답과 날짜를 보여 준다. 일수를 세는 알림은 뺀다 |

## 확정 문구 제안 (후보 각 1개)
호칭 변수 `{호칭}` = 엄마·아빠·어머니·아버지·할머니·할아버지·부모님(기본값). 조사는 문구 안에서 **붙이지 않는다**: "{호칭}의 ~", "{호칭} 소식"처럼 조사 없는 구조 또는 "의"(받침과 무관)만 쓴다. 불가피하면 호칭마다 `이/가`, `은/는`, `을/를` 형을 목록에 같이 저장한다(엄마 가·는·를, 어머니 가·는·를, 부모님 이·은·을). 자녀 화면은 높임 통일. 반말형 대화 소재는 쓰지 않는다.

| 위치 | 확정 문구 | 처리 메모 |
|---|---|---|
| 자녀 홈 한 줄 요약 | 제목 "{호칭}의 최근 답", 큰 글자 "가을", 작은 글자 "11월 16일", 아래 "가을 이야기를 해 볼까요?" | 큰 글자는 선택지 값(따옴표·조사 없음). 날짜는 오늘이면 "오늘" |
| 못 한 날 중립 문구 | 제목 "{호칭}의 최근 답", 날짜가 어제 이전이면 그 날짜 그대로 표시 + "이 답으로 이야기를 시작해 봐요" | "아직", "안 했어요", "N일째" 금지. 날짜만 사실로 보여 줌 |
| 답이 한 번도 없을 때 | "고른 답이 생기면 여기에 보여요" | 호칭·조사 없음. 안부 확인이 아니라는 고지는 설정 하단 한 줄 |
| 연결 끊김(자녀) | "연결이 끊겼어요. 새 번호를 만들어 {호칭} 폰에 알려 주세요" | 못 한 날과 구분되는 유일한 경고. 호칭 뒤 조사 없음 |
| 동의 제목 | "고른 답이 자녀분께 보여요" | 13자 |
| 동의 본문 | "어느 날 골랐는지도 보여요" / "안 한 날은 보이지 않아요" / "글씨 쓴 기록은 안 보여요" | 문장 3개, 한 줄씩. 두 번째 문장은 서버가 daily_sessions를 닫아 사실이 될 때만 쓴다 |
| 동의 버튼 | "좋아요" / "싫어요" | 2~3자 |
| 동의 거부 후 | "괜찮아요. 앱은 그대로 써요" + "고른 답은 자녀분께 안 보여요" | 자녀 화면 확정: "답을 나누지 않는 중이에요"("아직 비어 있어요"류는 금지) |
| 응원 발송 확인(자녀) | "{호칭}께 보냈어요" | "께"는 받침과 무관해 조사 문제가 없다 |
| 지우기 확인(어르신) | "고른 답과 기록이 모두 지워져요. 되돌릴 수 없어요" | 자녀에게 남는지는 정책 확정 후 한 줄 추가 |

## 내가 틀릴 수 있는 이유
1. "가장 최근 답 + 날짜"가 오래되면(예: 2주 전) 자녀는 결국 안부 신호로 읽는다. 문구로는 이 문제를 못 푼다.
2. "안 한 날은 보이지 않아요"가 어르신에게 "자녀가 못 하면 모른다"는 안심이 되는지 오히려 "보는 중"으로 읽히는지는 미확인(가정).
3. 호칭 7개 닫힌 목록이 사용자 애칭을 막는 불만이 될 수 있다.

## 사용자에게 묻고 싶은 것
- 일수를 세는 안부 알림(UX 제안)을 빌드 1에서 빼는 데 동의하는지.
- 거부 후 자녀 화면 문구 "답을 나누지 않는 중이에요"가 서운하게 읽히지 않는지(자녀 3명에게 확인 필요).
