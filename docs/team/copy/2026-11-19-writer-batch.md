# 라이터 확정 묶음 (2026-11-19)

여러 레인이 '라이터 확인 전'으로 넣어 둔 문구를 한 번에 정했다.

- 찾은 곳: `git grep "라이터 확인 전\|_status"` 결과를 origin/main, origin/ux-audit(PR #2), origin/feat/invite-page-ios-branch(PR #4)에서 확인했다. P13 미리보기는 어르신 레인이 진행 중이다(main에 문구 키만 있고 쓰는 코드는 아직 없음).
- 기준: `docs/team/writer.md` 1절(해요체, 한 문장 20~30자, 앱이 주어, 재촉·평가 금지, 자녀 문장 40자 이내), 금지어(`app/__tests__/copyBan.test.ts`: 아직·못 했·미완료·N일째·틀렸·치매/치료/예방, 서버 0049 `push_text_clean`: 혜택·할인·이벤트·무료·유료·쿠폰·적립·포인트·경품·광고·다시오세요), 코드가 실제로 하는 일과 맞는지.
- 반영: main 대상은 이 PR에서 `docs/team/copy.ko.json`을 고치고 `scripts/sync-copy.sh`로 앱 사본에 복사했다. PR #2·#4·어르신 레인 대상은 표에만 적었고, 해당 레인이 반영한다.

참고: `ask_failed`는 `catch` 쪽(`NotifyRows.tsx:129`)에서도 쓰인다. 권한 요청 자체가 예외를 던진 경우인데, 지금 runtime은 예외를 값으로 바꾸므로 사실상 일어나지 않는다. 일어나더라도 다시 열면 같은 [알려 주세요] 줄이 다시 보이니 문장이 거짓이 되지는 않는다.

## 4. P13 '가족에게 이렇게 보여요' 미리보기, 거부 상태 (어르신 레인이 반영)

`settings.preview.sub`('최근 한 달 고른 답과 날짜가 보여요. 연결된 날과 답을 보여 주는 중인지도 보여요')는 보여 주는 중일 때만 맞다. 거부하거나 그만 보여 준 상태에서는 자녀 화면에 `child.not_shared`('답을 나누지 않는 중이에요')만 뜬다(`ChildHome.tsx:140`, `ChildReport.tsx:46,102`). 고른 답과 날짜는 보이지 않으니 첫 문장이 거짓이 된다. 동의 화면 `consent.decline_note`('가족은 답을 보여 주지 않는 중인 것만 알아요')와도 맞춰야 한다.

| 키 | 현재 | 확정안 | 이유 |
|---|---|---|---|
| `settings.preview.sub` (보여 주는 중) | 최근 한 달 고른 답과 날짜가 보여요. 연결된 날과 답을 보여 주는 중인지도 보여요 | (그대로) | 보여 주는 중일 때는 사실이다. |
| 새 키 `settings.preview.sub_off` (거부·그만 보여 줌) | — | 지금은 고른 답이 가족에게 보이지 않아요. 답을 보여 주지 않는 중인 것만 보여요 | 자녀 화면이 실제로 보여 주는 것(나누지 않는 중이라는 표시)만 말한다. 두 문장 모두 20자 안팎이다. 거부를 탓하거나 다시 켜라고 재촉하지 않는다. '아직'도 쓰지 않았다. |
| `settings.preview.not_typed`, `not_days` (거부 상태) | 사진과 자판으로 쓴 글자는 보이지 않아요 / 안 한 날은 보이지 않아요 | 거부 상태에서는 빼는 것을 권한다 | 거짓은 아니다. 하지만 답 자체가 안 보이는 상태에서는 군더더기이고, 한 화면에 세 문장 이하라는 규칙도 있다. 남길지는 레인이 정한다. |

어르신 레인이 미리보기 코드를 넣을 때 `sub_off` 키를 copy.ko.json 원본에 추가하고 sync한다. main에 키만 먼저 넣으면 레인 변경과 충돌하므로 이 PR에는 넣지 않았다.
