## 1. 바뀐 것 한눈에
| 무엇 | 전 | 후 | 코드 |
|---|---|---|---|
| 읽기용 문장 변환 | 화면 글을 그대로 엔진에 넘김 | 읽기가 갈리는 숫자(달·세는 말·기념일·시각)·단위·괄호·가운뎃점·줄임표·영문 약어를 읽는 말로 바꾼 뒤 넘김. 애매하면 그대로 | `app/src/audio/spokenText.ts` `toSpoken` |
| 한 글자씩 | `한 글자씩, 나, 무.` 한 문장(쉼표 쉼, 짧음) | `한 글자씩.` / `나.` / `무.` 글자마다 따로 말함 | 같은 파일 15번 규칙 |
| 문장 사이 쉼 | 엔진의 문장 끝 틈뿐(약 0.1~0.3초, 엔진마다 다름) | 문장이 끝나면 **0.4초** 더 쉬고 다음 문장 | `engines.ts` `TTS_TUNING.sentencePauseMs` |
| 말 빠르기 | Android 0.9 · iOS 0.45 | **그대로**(근거는 3절) | `TTS_TUNING.rate` |
| 높낮이 | 1.0 | **그대로**(근거는 3절) | `TTS_TUNING.pitch` |

- 값은 `engines.ts`의 `TTS_TUNING` 한 곳에서 바꾼다. `TTS_RATE`는 그 별칭이다.
- 바꾼 글은 **기기 TTS에 넘길 때만** 쓴다. 화면 글자는 그대로다. 미리 생성 음성 파일 키(원문 문장)도 그대로라서 파일 찾기에는 영향이 없다.
- 미리 생성 음성 스크립트(`scripts/tts/synth.mjs`)는 아직 원문을 Google에 보낸다. B 단계를 다시 시작할 때 `toSpoken`을 합성 입력에 쓸지 정한다. 지금 콘텐츠에서는 한 글자씩 말고는 바뀌는 글이 없다(4절).

## 2. 쉼: 엔진이 지원하는 방식 조사
`@mhpdev/react-native-speech` 1.4.4는 글을 그대로 넘긴다. Android는 `TextToSpeech.speak`, iOS는 `AVSpeechUtterance(string:)`이다. 소스 `android/.../RNSpeechModule.kt`와 `ios/RNSpeech.mm`에서 확인했다.

| 방법 | Android(Google·삼성 엔진) | iOS | 이 앱에서 |
|---|---|---|---|
| SSML `<break time>` | `speak()`는 일반 글로 읽는다. 엔진에 따라 태그를 소리 내 읽을 위험도 있다 | iOS 16부터 `AVSpeechUtterance(ssmlRepresentation:)`이 있지만 라이브러리가 쓰지 않는다 | **못 씀** |
| 무음 발화 | `playSilentUtterance`(API 21+)가 있지만 라이브러리가 열어 주지 않는다 | `postUtteranceDelay`도 라이브러리가 열어 주지 않는다 | **못 씀**(네이티브 수정이 필요해 새 설치·패치 금지와 충돌) |
| 쉼표 | 문장 안 짧은 쉼 | 같음 | 가운뎃점·괄호·빗금·문장 안 줄임표 → 쉼표 |
| 문장 나누기 | 발화마다 끝 억양과 틈이 생긴다 | 같음 | 이미 한 문장씩 넣고 있다(#43). 한 글자씩 읽기도 이제 글자마다 나눈다 |
| JS 대기 | 엔진과 무관 | 같음 | **새로 넣음**: 앞 문장 `onFinish` 뒤 `sentencePauseMs`를 기다렸다 다음 문장을 넣는다. 기다리는 사이 멈추거나 새로 읽으면 넣지 않는다. 마지막 문장 뒤에는 기다리지 않는다 |

## 3. 말 빠르기·높낮이 기본값 근거
| 값 | 결정 | 근거 |
|---|---|---|
| 빠르기 Android 0.9 / iOS 0.45 (보통보다 약 10% 느림) | 유지 | 고령 청자는 말이 조금 느릴 때 문장 인식이 좋아진다([Lessa & Costa 2022, PMC9442445](https://pmc.ncbi.nlm.nih.gov/articles/PMC9442445/)). 하지만 많이 늦추면 오히려 수행이 떨어진다는 합성음 연구도 있다([NCSU 학위논문](https://repository.lib.ncsu.edu/server/api/core/bitstreams/4b423c1e-aebb-4c0d-8a12-8edf6159d964/content) 등. 초록·검색 요약 기준이고 원문 수치는 확인하지 못했다). 노인 대상 음성 UI 연구에서도 선호 속도는 사람마다 달랐다([Wang 외 2023, PMC10132265](https://pmc.ncbi.nlm.nih.gov/articles/PMC10132265/)). 그래서 지금의 '조금 느림'에서 더 늦추지 않는다 |
| 문장 사이 0.4초 더 쉬기 | 새로 넣음 | 늦춘 만큼의 시간을 **언어 경계(문장·구 끝)에 쉼으로 주면** 고령자의 회상이 좋아졌다. 무작위 위치에 준 쉼은 효과가 거의 없었다([Wingfield 외 1999 "Regaining lost time", Psychology and Aging](https://scholarworks.brandeis.edu/esploro/outputs/journalArticle/Regaining-Lost-Time-Adult-Aging-and/9923958199101921)). 사람도 큰 구문 경계에서 더 길게 쉬고, 고령자일수록 더 길게 쉰다([Fallon·Peelle·Wingfield 2006](https://psychsoc.gerontologyjournals.org/cgi/content/abstract/61/1/P10)). 0.4초는 엔진 틈(0.1~0.3초)과 합쳐 0.5~0.7초다. 낭독의 문장 사이 쉼으로 흔히 쓰는 범위 안이다(가정값) |
| 높낮이 1.0 | 유지 | 노인성 난청은 고음역부터 손실되고, 1~3kHz 대역에 자음 단서가 많다(청각학 일반 기술, 검색 요약 기준). 하지만 목소리 높낮이를 낮추면 더 잘 들린다는 직접 근거는 찾지 못했다. 기기 TTS의 pitch는 음색(포먼트)까지 함께 옮겨 부자연스러워진다. 바꿀 근거가 생기면 `TTS_TUNING.pitch` 한 곳에서 바꾼다 |
| 낯선 낱말·기호를 읽는 말로 | 새로 넣음 | 고령자도 익숙한 낱말과 맥락이 있으면 합성음을 젊은 사람만큼 이해한다. 하지만 낯설거나 복잡한 낱말이 나오면 청력의 영향이 커진다([Wolters 외 2007, SSW6](https://www.isca-archive.org/ssw_2007/wolters07_ssw.html)). 그래서 'AI'·숫자·기호를 엔진마다 다르게 읽지 않게 한 가지 읽기로 고정한다 |

한국어 방송 낭독의 공식 분당 음절 수 기준은 찾지 못했다(아나운서 휴지 규칙 연구 [JAKO199520828542266](https://koreascience.kr/article/JAKO199520828542266.page?lang=ko)는 속도가 느릴수록 문장 사이 휴지가 길어진다고 보고). 최종 값은 S25 듣기와 QA-04에서 정한다.

## 4. 읽기 규칙(`toSpoken`) — 순서대로
**원칙(리드, #238 리뷰 뒤): 확실한 꼴만 바꾸고, 애매하면 원문 그대로 엔진에 맡긴다.** 틀리게 바꾸는 것이 안 바꾸는 것보다 나쁘다.
그래서 숫자는 읽기가 갈리는 곳만 말로 바꾼다. 달 이름, 세는 말 앞 고유어, 기념일, 시각, 영하, 개월이 여기에 든다.
해·날·소수·큰 수·전화번호·분수는 숫자 그대로 둔다. 기기 엔진은 이런 숫자를 한자어로 바르게 읽는다.

| # | 규칙 | 예(→ 바뀜, = 그대로) |
|---|---|---|
| 1 | 날짜는 `YYYY.M.D`·`YYYY-M-D`만 `년·월·일`로 바꾼다(`M/D`는 분수와 헷갈려 다루지 않음). `(화)`는 화요일 | `6월 5일(목)` → `유월 5일 목요일` |
| 2 | 큰 수 쉼표 지우기 | `1,000원` → `1000원` |
| 3 | 범위 `~` → '에서'. **달·시각을 말로 바꾸기 전에** 처리한다(#238 재확인 M-B). `숫자~숫자+세는 말·달·단위`는 양쪽에 붙이고, 세는 말이 붙은 범위는 물결만 바꿈 | `3~5개` → `세 개에서 다섯 개`, `3~4월` → `삼월에서 사월`, `3월~5월` → `삼월에서 오월`, `2:30~3:00` → `두 시 30분에서 세 시`, `오전 9시~오후 6시` → `오전 아홉 시에서 오후 여섯 시` |
| 4 | `N개월`은 한자어. 달은 **붙어 있고 1~12이며 뒤가 조사·끝일 때만** 달 이름(6월 유월, 10월 시월). 앞이 가운뎃점·붙임표·빗금이면 나열·범위 꼴이라 그대로 | `3월에` → `삼월에` / `2002 월드컵`·`10 월세`·`16월`·`3·4월`·`1-2월` = |
| 5 | 기념일: **목록(`ANNIVERSARIES`)에 있는 꼴만** 읽는다. 목록은 국가기념일(「각종 기념일 등에 관한 규정」: 2·28, 3·8, 3·15, 4·19, 5·18, 6·10, 6·25, 제주 4·3), 3·1절, 광복절 8·15, 그리고 이름으로 굳은 역사 사건(1·4 후퇴, 2·8, 5·16, 6·15, 6·29, 10·26, 12·12)이다. 마침표 꼴은 목록에 있고 '전쟁·운동(운동장 제외)·광복·후퇴·절' 등이 뒤따를 때만 | `6·25` → `육이오`, `4·19` → `사일구`, `6·10` → `육십`, `10·26` → `십이륙`, `6.25 전쟁` → `육이오 전쟁` / `1·2학년`·`1·2층`·`5·6개`·`8.15`·`1.2 운동장`·`1.5 전쟁` = |
| 6 | 시각 `H:MM`(1~12시) → 고유어 시(뒤에 붙은 '분'은 하나로). 영하 `-N도/℃` → 영하(글 처음·공백·괄호 뒤만, `영하 -5도`는 붙임표만 지움) | `10:30` → `열 시 30분`, `10:30분` → `열 시 30분`, `영하 -5도` → `영하 5도` / `3:2`·`13:00`·`온도는-2도` = |
| 7 | 세는 말 앞은 고유어(1~99, 0으로 시작하지 않음, **세는 말 뒤가 낱말 경계(끝·조사)일 때만**, 앞이 가운뎃점·붙임표·빗금이면 그대로): 개·살·명·마리·시간·시(12 이하)·번째(1은 '첫')·그릇·잔·장·권·벌·켤레·송이·군데·달·곳·가지·사람. '번'은 횟수·번호가 애매해 넣지 않음 | `9시` → `아홉 시`, `20살` → `스무 살`, `1시간째` → `한 시간째` / `3달러`·`2개국어`·`10시대`·`1번 버스`·`15시`·`100살`·`5·6개` = |
| 8 | 단위 기호 → 말(숫자는 그대로): km·kg·cm·mm·m·g·ml·L·%·℃ | `3km` → `3 킬로미터`, `30%` → `30 퍼센트` |
| 9 | 영문: 아는 이름(Google·Lyria)은 한글로, 대문자 약어 2~4자는 한 글자씩. 한 글자·5자 이상·소문자가 섞인 낱말은 엔진에 맡김 | `AI` → `에이아이`, `TV` → `티브이` / `A4`·`5G`·`COVID-19`·`No.1` = |
| 10 | 따옴표·꺾쇠(「」『』“” 등)는 지움 | `「학교종」` → `학교종` |
| 11 | 괄호: 앞에 쉼표. 뒤에 조사가 바로 붙으면 그대로 잇고, 아니면 뒤에도 쉼표 | `AI(Google Lyria)가` → `에이아이, 구글 리리아가` |
| 12 | 가운뎃점(·ㆍ・)·화살표 → 쉼표(숫자 사이는 그대로). 빗금은 한글 사이만 쉼표(`1/2`·`A/S` =). `&` → 그리고 | `AI가 만든 그림·실제 장소가 아니에요` → `에이아이가 만든 그림, 실제 장소가 아니에요` |
| 13 | 줄임표: 뒤가 공백이나 끝이면 마침표(문장 쉼), 문장 안이면 쉼표 | `그때는…좋았지요` → `그때는, 좋았지요` |
| 14 | 읽지 않는 기호(★·~·#·* 등)는 지움 | `★ 오늘의 낱말 ~` → `오늘의 낱말` |
| 15 | 한 글자씩: `글자씩, 가, 나.` → 글자마다 따로 말함(글자 사이 = 문장 쉼, 따라 쓰기용) | `한 글자씩, 나, 무.` → `한 글자씩.` / `나.` / `무.` |

전화번호(`010-1234-5678`)와 0으로 시작하는 수(`007`)는 어느 규칙에도 걸리지 않아 그대로 간다.
리뷰 QA-2의 입력 42개와 재확인 입력 38개는 모두 시험(`spokenText.test.ts` '리뷰 #238 QA-2 입력'·'재확인 입력')으로 고정했다. 틀린 읽기가 다시 나오면 시험이 실패한다.

두 번 돌려도 결과가 같다(시험으로 고정). 미리 생성 음성이 중간에 실패하면 남은 문장을 기기 TTS로 잇는데, 이 경로에서도 안전하다.

## 6. 오너 S25 듣기 목록(10개)
들을 곳: 코스 화면에서 '읽어 주세요'를 누른다(사진=P4, 둘 중 고르기=P5, 낱말=P6, 응원=P8).
각 문장마다 **① 빠르기 ② 문장·글자 사이 쉼 길이 ③ 발음**을 '좋음 / 빠름·느림 / 길다·짧다 / 틀림'으로 적어 주면 된다.

| # | 화면 | 날 | 들을 문장 | 확인할 것 |
|---|---|---|---|---|
| 1 | P6 낱말 | 1일 | 나무. 한 글자씩. 나. 무. | 글자 사이 쉼(엔진 틈+0.4초)이 따라 쓰기에 맞는가, 너무 끊기는가 |
| 2 | P6 낱말 | 3일 | 부엌. 한 글자씩. 부. 엌. | 받침 홀로 읽기: '엌'이 [억]으로 들리는가 |
| 3 | P6 낱말 | 26일 | 낚싯대. … 낚. 싯. 대. | 겹받침·사이시옷 글자를 홀로 읽을 때 발음 |
| 4 | P6 낱말 | 29일 | 닭장. … 닭. 장. | 겹받침 '닭'을 홀로 읽기([닥]) |
| 5 | P6 낱말 | 30일 | 흙담. … 흙. 담. | 겹받침 '흙'을 홀로 읽기([흑]) |
| 6 | P6 낱말 | 16일 | 버스. … 버. 스. | 짧은 글자 '스.'가 끝 억양과 함께 어색하지 않은가 |
| 7 | P4 사진 | 15일 | 장에 가면 제일 먼저 어디를 보셨어요? / 장바구니에 꼭 담던 건 뭐예요? | 가장 긴 질문 두 개: 빠르기, 두 질문 사이 쉼 |
| 8 | P5 고르기 | 28일 | 잔치 음식은요? / 국수, 아니면 전. | 단음절 선택지 '전'이 묻히지 않는가, 질문과 선택지 사이 쉼 |

| 10 | P8 응원 | — | 가족이 보낸 응원이에요. / 사랑해요, 오늘도 좋은 하루예요 / 늘 고마워요 | 응원 여러 개를 이어 읽을 때 쉼, 끝 억양 |

결과를 이렇게 반영한다.
- 쉼이 길다·짧다 → `TTS_TUNING.sentencePauseMs`(지금 400, 시험 허용 범위 200~800)
- 빠르다·느리다 → `TTS_TUNING.rate`
- 글자 홀로 읽기 발음이 틀리면 → 한 글자씩 규칙(15번)을 쉼표 나열로 되돌리거나 글자 뒤 마침표를 빼는 안을 비교한다

## 7. 남은 것
- 미리 생성 음성(B 단계)을 다시 시작하면 합성 입력에 `toSpoken`을 쓸지 정해야 한다. 쓰면 Chirp도 한 글자씩·에이아이 읽기를 같게 하고, 파일 키는 원문 그대로 둔다.
- AI 고지·사진 설명을 '읽어 주세요'에 넣을지는 기획·라이터가 정할 일이다. 넣으면 4절 규칙이 이미 적용된다.
