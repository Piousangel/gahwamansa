## 결론 (3줄)
1. **C-2 권장: 빌드 1은 A(자유 텍스트 열지 않음) + 앱 밖 '카톡으로 이어 쓰기'(저장 0)를 대안으로 검토.** 자유 텍스트를 앱 안에 열 때는 B만으로는 부족하고 **B+C(필터 + 가족 안에서만 + 신고·차단 + 약관 동의)를 한 묶음으로**, 빌드 2 이후 방침 v2 개정과 함께 연다. 이유: Play·App Store 모두 사용자 간 1:1 콘텐츠에 신고·차단을 요구하고(가족 한정 예외 없음), 자유 글은 방침 2절 "직접 쓴 글은 받지 않습니다"(privacy.html:44)를 뒤집으며, 어르신 화면 200%에서 40자는 약 6~7줄이다.
2. **D-1 판정: 지금 P2 동의(v5)의 '취지' 범위 안(같은 받는 사람·목적·기간·정해진 선택지)이라 재동의는 필요 없다고 본다(확신도 중간). 다만 방침 2절 수집 항목 표·3절, 약관 제2조 '고른 답' 정의·제7조 기능 목록은 '둘 중 하나'·'오늘의 질문'으로 좁게 적혀 있어 갱신이 필요하다.** 조건 4개(4.3절)를 서버 계약(DV-2)에 넣어야 한다.
3. **오너 결정 필요: ① C-2 빌드 1 A안 승인과 '카톡으로 이어 쓰기' 채택 여부 ② 앱 안 자유 글을 연다면 시점(빌드 2·방침 v2)과 신고를 1인 운영자가 받을 수 있는지(처리 기한 약속) ③ D-1 문서 갱신을 방침 v1 게시본에 미리 넣을지, D-1 출시 때 v2 개정으로 할지 ④ D-1을 넘긴 날 자녀 카드에 아무 표시도 하지 않는다(권고)는 원칙 확인.**

## 3. 세 안 비교
### 안 A — 열지 않음 (+ 선택: 앱 밖 '카톡으로 이어 쓰기')
- 내용: 지금처럼 정해진 문장만(C-1 확대 15개, `copy/2026-11-24-cheer-expansion.md`). 선택 확장으로, 자녀 시트 맨 아래 「직접 쓰고 싶으면 카톡으로」 버튼이 OS 공유창을 연다(빈 글 또는 고른 문장 미리 채움). **앱·서버는 글을 받지도 저장하지도 않는다.**
- 필요 작업: 서버 0 / 앱 S(공유 인텐트 1개, 선택) / 문서 0 — 방침에 새 수집 항목 없음(카톡 전송은 이용자가 직접 하는 앱 밖 행위). 이용 기록에 '공유 버튼 누름' 이벤트를 남기려면 이벤트 이름만, 글 내용 0(방침 2절 이용 기록 행 범위 안).
- 위험: 낮음. 단점은 앱 안 '남긴 것'이 생기지 않음(오너 의도의 일부만 충족).
- UGC 요건: 해당 없음(앱 안에서 이용자 간 콘텐츠 교환 없음, 추정).

### 안 B — 길이 제한 + 금지어 + 개인정보 패턴 차단 + 31일 파기
- 내용: 자녀가 최대 N자 입력. 서버가 저장 전 검사해 거부.
- 필요 작업
  - 서버(M): `cheers`에 `body text null` + check(길이·키와 배타), `send_cheer`에 자유 글 경로, 검사 함수 `cheer_text_ok(text)`:
    - 정규화는 `push_text_clean`과 같게(보이지 않는 글자·자모 분리 우회 차단, 0049:33-39).
    - 개인정보: 0049 `admin_check_args`의 패턴 재사용 — 메일(@·at/dot 표기), 하이픈·공백 제거 뒤 숫자 9자리 이상(전화·주민번호·계좌, 0049:22-30). 주소는 낱말 패턴(시·구·동·로·길 + 숫자)으로 **경고만**(오탐 많음).
    - 금지어: 욕설 목록 + 가드레일 1절 낱말 + 광고 낱말.
    - 우회(「공일공…」 한글 숫자, 띄어 쓴 욕설 변형)는 **남는 위험**으로 적는다.
  - 앱(M): 입력 시트, 글자 수 표시, 거부 사유 안내(「번호나 주소는 넣을 수 없어요」), 받는 쪽 P8 표시·TTS.
  - 문서: 방침 2절 자녀 행·4절·데이터 안전 #10·App Privacy 라벨, 약관 제7조·제10조.
- 길이 권고: 40자는 200%에서 6~7줄(R5). **20자 이하**(≈3~4줄)를 권고, 디자인 실측으로 확정.
- 위험: **B 단독은 스토어 정책 미충족**(R9: 신고·차단 없음) → 심사 거절 가능. 민감정보(R2)·괴롭힘(R3)은 필터로 일부만 줄어든다.

### 안 C — 가족 안에서만 + 신고·차단 (B의 필터 포함)
- 내용: B + 받는 사람은 같은 가족의 부모님만(지금 `send_cheer`의 family 검사 그대로, 0059:27) + 받는 쪽 **신고**와 **보낸 사람 차단** + 쓰기 전 약관 동의 확인.
- 필요 작업
  - 서버(M~L): `cheer_reports`(신고 대상 한마디 사본·사유·시각·처리 상태), `cheer_blocks`(부모님→자녀, 차단 시 `send_cheer`가 조용히 실패 또는 `blocked`), 운영자 처리 함수(감사 기록 0039 방식), 신고 들어오면 해당 한마디 즉시 숨김(임시조치 성격). 파기: 신고 사본은 '처리 끝난 날 + 30일'(제안), 차단 목록은 계정이 있는 동안.
  - 앱(M~L): 어르신 P8에 「이 한마디 신고」·「이 가족 한마디 그만 받기」 — **어르신이 실수로 누르지 않도록 2단계 확인**, 문구는 라이터. 차단 해제는 설정에서. 자녀에게 '차단당함'을 직접 알리지 않음(가족 갈등 방지, 추정) — 단, 보낸 한마디가 전달 안 됨은 알려야 사실 고지에 맞음 → 「지금은 한마디를 보낼 수 없어요」 정도.
  - 운영: 신고 메일·관리 화면 확인 주기(1인 운영자, 예: 영업일 2일 안). Apple은 'timely responses'를 요구.
  - 문서: B의 문서 + 방침 4절(신고·차단 기록 행), 약관 제10조(금지 내용 예시)·제11조(신고 처리·임시 숨김)·신고 방법, 내부관리계획 §7 파기 목록, consent-exposure-map(자녀가 차단 사실을 알 수 있는지 행 추가).
- 위험: 중간(관리 가능). 남는 것은 R2(민감정보, L-8 회신 대기)·R10(부가통신, L-9).

## 4. D-1 '먼저 떠오른 것 고르기' — 동의 범위 판정
### 4.1 기능 (사실, 기획 문서)
- 사진 단계 안 한 칸, 셋 중 하나 고름(예: 아랫목/김장/연탄 나르던 길), 넘어가도 사진 단계는 끝남, 자녀 카드에 「아랫목을 떠올리셨어요」 — `board/2026-11-24-content-direction.md:12, 36, 148`.
- 서버 계약은 아직 없음(같은 문서 :16 '법률 → DV-2 계약'). 지금 `answers.choice`는 `('A','B')`만 허용(`20261116000001_core.sql:66`).

### 4.3 판정과 조건
- **판정: 재동의(CONSENT_VERSION 올림)는 필요 없다고 본다(팀 내부 의견, 확신도 중간).** 동의의 5요소 중 받는 사람·목적·기간·거부권이 같고, 항목은 '정해진 선택지에서 고른 답'이라는 같은 종류가 하나 늘어나는 것이다. 다만 방침·약관에 적힌 정의가 '둘 중 하나'·'오늘의 질문'이라 **문서 갱신은 필수**다(법 제30조 처리방침 공개 — 수집 항목은 사실과 같아야 함). 확신도를 높이려면 7절 L-10.
- 이 판정은 아래 **조건 4개가 서버 계약(DV-2)에 들어갈 때만** 유효하다.
  1. **같은 동의 문**: P2 '좋아요'가 있을 때만 저장(`answers`와 같은 consent_required 검사). 거절·철회 상태면 저장 0, 자녀에게 0.
  2. **같은 기간·같은 삭제**: 31일 파기 배치·'그만 보여 주기' 즉시 삭제·계정 삭제 cascade·마지막 자녀 삭제에 모두 포함(pgTAP로 확인). 자녀 목록도 30일.
  3. **정해진 선택지만**: 셋 중 하나의 키/번호만 저장. '기타 직접 쓰기' 칸을 두지 않는다(두면 C-2 문제가 그대로 들어옴).
  4. **넘긴 날 무표시**: D-1을 넘긴 날 자녀 카드에 「안 골랐어요」류 표시를 하지 않는다. 동의 body[1] 「안 한 날은 보이지 않아요」와 같은 원칙이고, 넘김이 '점검'으로 읽히는 것을 막는다(consent-exposure-map #3, guardrails 1절 감시·안부 오해).
- 콘텐츠 규칙(라이터·콘텐츠 레인): 세 선택지에 **건강·종교·정치·출신 지역·가족사(피난·사별 등)**를 넣지 않는다. 고른 답이 민감정보나 사생활 추정 근거가 되지 않게 하기 위함(제23조 취지, 추정).
- 알림: D-1 고른 값도 푸시에 넣지 않는다(방침 2절 알림 비고와 같음).

### 4.4 방침·약관 변경안 (원문은 고치지 않음)
- 방침 2절 부모님 「오늘 코스」 행(privacy.html:52): 「고른 답(**질문에서 둘 중 하나, 사진을 보고 먼저 떠오른 것 셋 중 하나 — 고르신 경우만**)과 고른 날짜 — 동의하신 경우에만 저장」
- 방침 3절(:88): 「"좋아요"를 누르시면 고른 답(**질문의 답과, 고르셨다면 사진을 보고 먼저 떠오른 것**)과 날짜가…」
- 방침 1절 한눈에 보기(:25)는 '고른 답'이라 그대로.
- 약관 제2조(:48): 「"고른 답": 부모님 이용자가 오늘의 질문**이나 사진에서 정해진 보기 중** 고른 답과 그 날짜입니다.」
- 약관 제7조(:89): 「…둘 중 하나를 고르는 질문, **사진을 보고 먼저 떠오른 것 고르기(하고 싶을 때만)**…」
- 데이터 안전 양식 #7·App Privacy 라벨: 항목 분류는 같음('기타 사용자 콘텐츠' 범주) — 설명 문장만 보강.
- **시점**: 방침 v1이 아직 게시 전이면 D-1 출시 여부와 관계없이 미리 넣지 **않는다**(없는 기능을 적으면 사실과 다름). D-1이 빌드 2라면 방침·약관 v2 개정(13절 고지, 약관 제3조 7일 전 고지, 내부관리계획 §6 버전 등록)으로 넣는다. 이용자에게 불리한 변경은 아니라고 보지만(수집이 늘지만 같은 동의 안), 앱 안 알림으로 함께 알리는 것을 권고.
