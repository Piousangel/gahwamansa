# App Store App Privacy 라벨 초안 + Play 데이터 보안 대응표 (iOS 감사 N4, L6, 2026-11-19)

> **법률 자문 아님.** App Store Connect "App Privacy" 입력 초안. 분류 이름·정의는 Apple 안내(https://developer.apple.com/app-store/app-privacy-details/, 11-19 조회)를 따랐고, 콘솔 칸 이름은 입력 때 다시 확인한다.
> 기준: Play 대조표 `data-safety-form.md` §1의 행 번호(#)를 그대로 쓴다. iOS에서만 생기는 행은 **i1~i3**. 빌드 2 iOS 구현 전이므로 iOS 행은 전부 **예정**.
> 표기: **사실** = 코드·결정·공식 문서로 확인 · **추정** = 판단 · **결정 필요** = 리드·L1.

## 0. Apple 기준에서 먼저 정할 것 (사실: 위 Apple 안내)
- **수집(collect)** = 기기 밖으로 보내서, 요청을 실시간으로 처리하는 데 필요한 시간보다 오래 운영자나 제3자 파트너가 볼 수 있는 것. 기기 안에서만 처리하는 데이터는 수집이 아니다.
- **사용자와 연결(linked)**: 데이터가 이용자의 **계정·기기·그 밖의 정보를 통해 신원에 연결되어 수집되는지**로 판단한다. Apple 원문: 앱이 모으는 데이터는 대개 신원에 연결되며, 연결 안 됨이 되려면 수집 **전에** 사용자 ID·이름 같은 직접 식별자를 떼고 다시 잇지 못하게 처리해야 하고, 수집 **뒤에도** 다시 잇거나 연결 가능한 다른 데이터와 묶지 않아야 한다. 개인정보 법령상 개인정보는 연결된 것으로 본다. → 기기 수준 ID(설치 ID·푸시 토큰)와 함께 모이는 데이터는 **연결 예가 기본**.
- **추적(tracking)**: 다른 회사 앱·웹 데이터와 합쳐 맞춤 광고·광고 측정에 쓰거나 데이터 브로커에 주는 것. 우리 앱은 **추적 안 함**(광고 SDK·광고 ID 없음, D-04). 로그인 SDK가 데이터를 광고에 다시 쓰면 그것도 추적이 되므로 카카오·구글 iOS SDK의 개인정보 매니페스트를 B2에 확인한다(§3).
- **목적**: 제3자 광고 / 개발자 광고·마케팅 / 분석 / 제품 맞춤화 / 앱 기능 / 기타. 우리 앱은 **앱 기능**과 **분석**만.
- Apple이 Apple 프레임워크·서비스로 직접 모으는 데이터는 운영자가 신고할 책임이 없다(Apple 안내 "You are not responsible for disclosing data collected by Apple"). 다만 운영자가 Apple에서 **받아 저장하는 것**(Apple 로그인 고유 번호·이메일)은 신고한다.

## 3. B2에 확인할 것
1. 카카오 iOS SDK·GoogleSignIn·Firebase iOS의 `PrivacyInfo.xcprivacy` 수집 항목·추적 여부(감사 문서 Privacy Manifest 라이브러리 행). Xcode Archive → Generate Privacy Report 결과를 이 표와 대조.
2. 앱 `PrivacyInfo.xcprivacy`의 `NSPrivacyCollectedDataTypes`를 §2와 같게 채운다(지금 비어 있음 — 감사 문서, 사실).
3. #15·#16을 "연결 안 됨"으로 낮추려면 Crashlytics·FCM 설정이 Apple 조건을 채우는지 확인(확인 전에는 연결 예 유지).
4. Apple 로그인 구현이 결정대로 이메일만 요청하는지, 삭제 때 재인증 → 즉시 해제·폐기, 실패 시 재시도 큐 30일인지(i2·i3, 결정 11-19).
5. 구글 iOS 로그인이 이름을 요청하는지(스코프) — #3 메모 "구글 이름이 있으므로 이름은 남음"의 전제.
