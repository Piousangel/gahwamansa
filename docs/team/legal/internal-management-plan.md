## 2. 처리하는 개인정보 (방침 2절과 같은 목록, 요약)
- 자녀: 카카오 회원번호(닉네임은 선택), 구글 고유 번호·이메일·이름·프로필 사진 주소, 이메일 인증번호 가입자의 이메일, 호칭, 만든 번호, 응원.
- 부모님: 익명 로그인 ID, 번호 입력 기록, 동의 이력, (동의 시) 고른 답, 코스 기록.
- 자동: 푸시 토큰·Firebase 설치 ID(FCM), Crashlytics 오류 기록, 이용 기록(가명 기기값, 14개월), 서버 접속 기록(Supabase).
- 기기 안에만: 로그인 상태, 초대 번호(최대 7일), 미연결 도장 날짜(7일). 서버로 보내지 않음(초대 번호는 연결할 때만).

## 3. 접근 권한 관리
1. 권한은 **최소 1명**: production Supabase 조직 멤버는 보호책임자 1명(Owner). 다른 멤버 초대 금지(13 §1.1 운영 칸 "Studio 조건부 사용 규칙", BO §2).
2. 앱 코드에는 **service_role·secret 키를 넣지 않는다**. 출시 빌드마다 번들 grep으로 확인(release-gates A9, 사실: 검사 명령 있음).
3. 서버 비밀값(FCM 서비스 계정, 카카오 Admin 키)은 Supabase Edge Function secrets에만, 저장소·문서·채팅에 쓰지 않는다.
4. 권한 변경(추가·삭제·키 교체)은 §6 대장에 그날 적는다. 키가 노출됐거나 의심되면 즉시 교체(US-16 선례).

## 5. 암호화
- 전송: 앱 ↔ Supabase·Firebase 모든 통신 HTTPS(사실).
- 저장: Supabase 저장 암호화 여부는 공식 문서 확인 전(**추정**, 방침 11절 확인 항목). 확인 전까지 방침에 "저장 암호화"를 단정하지 않는다.
- 비밀번호: 이용자 비밀번호를 받지 않는다(소셜·인증번호·익명). 인증번호는 Supabase Auth가 처리, 10분 만료(사실: OTP 600초 설정 예정, SV-14).
- 기기: 초대 번호는 앱 전용 저장소(MODE_PRIVATE, 자동 백업 꺼짐), 처리한 링크는 원문 대신 해시(사실: spike 구현). staging 개발자 메뉴 보관 세션은 앱 전용 저장소·백업 꺼짐·7일 만료(사실: DECISIONS 11-18), production 빌드에는 메뉴가 없다(release-gates A8).

## 6. 접속 기록 보관과 점검 (관리자 접근 기록)

- 수기 대장(아래 양식): 저장 위치 {저장소 밖 문서 위치}, **1년 이상 보관**(고시 1년 기준 적용 여부는 질문 8).
- 점검: 매월 1일 대장과 감사 로그를 대조, 설명 안 되는 접속이 있으면 §9 사고 절차.

## 7. 파기
- 자동: pg_cron `purge-expired-data` 매일 실행 — 고른 답·코스 기록 31일째, 응원 31일, 초대 번호·입력 시도 30일, 알림 큐 30일, 이용 기록 14개월(사실: 0023·0028). production 첫 실행 성공을 G-INT 전에 확인(release-gates G-18).
- 요청 삭제: 앱 안 삭제는 즉시(0017·0026). 웹 요청은 접수일부터 10일 안(보통 7일), 감사 기록 남는 RPC로 처리하고 대장에 적는다.
- 백업: 일 1회 백업 7일 보관 후 덮어쓰기(Pro, 사실: DECISIONS 11-17 운영 결정).
- 테스터 명단(Gmail): 비공개 테스트 종료 후 {테스트 종료일 + 30일}까지 삭제(LG-12 약속), 삭제한 날 대장에 기록.
- 내려받은 자료(지표 CSV 등)에는 개인 식별값을 넣지 않는다(SV-16 스니펫 `is_test` 제외·20명 미만 비율 숨김 규칙).
