## 1. 작업 단위의 완료 정의 (모든 단위 공통)
각 단위는 아래 6칸이 모두 찼을 때만 "완료"다. 하나라도 비면 다음 마일스톤으로 넘어가지 않는다.
1. 기획: 상태 목록·예외·문구가 확정 문서에 있음(라이터 확정, 임시 문구 0)
2. 디자인: 시안에 모든 상태 + 150%·200% + 화면 읽기 순서 주석
3. 개발: 시안 1:1, 서버 변경은 pgTAP 포함(테스트 먼저), tsc·lint·jest·통합 통과
4. 리뷰: 작성자 ≠ 검토자 코드 리뷰(놓침·부족·과함), 지적 처리 기록
5. 실기기 QA: 100%·150%·200% 캡처, TalkBack 순회, 비행기 모드 1회
6. 디자인 QA 승인: 시안 담당 디자이너가 `device-review/QA-<화면>.md`에 "승인"

## 3. 의존 순서와 병행
```
[1단계 바로 시작, 병행]  U0 공용 컴포넌트 · U1 오디오 스파이크 · U12 브랜드 · U14 이벤트 · U17 원격(사용자)
          │
[2단계, 3줄 병행]
  어르신 줄: U2 음성 → U3 한글 입력 → U4 P7·P8
  자녀 줄:   U6 홈 → U5 응원 보내기 → U8 설정
  마감 줄:   U10 기존 화면 승인 · U11 공통 상태   (실기기 연결 필요)
          │
[3단계]  U7 지난 답 · U9 곧 유료 · U13 소리 · U15 푸시
          │
[4단계]  U16 접근성 패스 → U18 출시 자료 → U19 출시 관문
```
- 서버 작업(U4·U5·U6·U7·U14·U15의 RPC)은 마이그레이션 번호 충돌을 막기 위해 **한 줄로 순서대로**(서버 담당 1명). 앱 작업은 화면 파일이 겹치지 않아 병행 가능.
- 디자이너는 2명 분리 권장: ① 어르신·브랜드(U3 시안, U12, U13 분위기) ② 자녀·공통(U5~U9, U11). QA 승인은 각자 자기 시안만.
- 병목은 개발이 아니라 **실기기 QA와 디자인 승인 왕복**(지금까지 승인 0건, 미승인 판정 3건이 모두 재캡처 대기). 폰이 연결된 날에 캡처를 몰아서 찍는다.

## 6. 결정 질문 (최대 5개, 이미 결정된 것은 제외)
1. **푸시 알림을 빌드 1(출시본)에 넣을까요?** SPEC MVP에는 있고, 제 백로그는 빌드 2로 분류했었습니다.
   추천: **넣는다**(하루 1회 "오늘의 추억이 도착했어요", P12 권한 안내 화면 포함). 매일 돌아올 이유의 핵심이고 "빠진 기능 자르지 않는다" 원칙과 맞음. 비용 +12~18h, Firebase 계정은 사용자.
2. **한글 따라 쓰기를 어떻게 "다 썼다"고 볼까요?**
   추천: **채점하지 않는다.** 점선 위에 일정 길이 이상 그으면 "다 썼어요"가 켜지고 "지우고 다시"를 둔다. 틀렸다는 말·점수 없음(말투 원칙 "평가하지 않는다"와 같은 방향). 화면 읽기 사용자는 "듣고 넘어가기" 대체 경로. 대안(획 순서·모양 판정)은 +10h 이상, 어르신 좌절 위험.
3. **음성 읽어주기 목소리**
   추천: **휴대폰 내장 한국어 음성(TTS)**. 오프라인 동작, 콘텐츠가 늘어도 비용 없음. 한국어 음성이 없는 기기는 버튼을 숨기지 않고 "휴대폰 설정에서 한국어 음성을 받아 주세요" 안내(실기기 확인 필요). 대안: Gemini로 미리 만든 음성 파일 번들(목소리 품질 균일, 콘텐츠마다 생성·용량·AI 음성 고지 필요).
4. **비공개 테스트를 언제 시작할까요?**
   추천: **시나리오 A** — 핵심 고리(M2)가 원격에서 동작하는 빌드로 11/24~28에 비공개 테스트를 먼저 시작하고, 테스트 기간 중 빌드를 계속 올리며, **공개(프로덕션) 신청은 전 화면 QA 승인(M4) 뒤에만**. 공개 출시본의 완성도는 그대로 지키면서 14일 시계를 먼저 돌려 약 1~2주 당김. 단 테스터가 미완성 화면을 보게 되므로 테스터 안내문에 "테스트 버전" 명시.
5. **자녀가 볼 수 있는 "지난 답"의 범위**
   보드 결론은 "최근 고른 답+날짜만"인데, 확정 시안(C5 지난 답 탭)과 동의 문구(P2 "고른 답과 날짜가 가족에게 보여요")는 목록을 전제합니다.
   추천: **고른 답+날짜 목록(최근 30개, 안 한 날은 표시 안 함, 참여율·연속일 없음)**. 동의 문구와 1:1이고, 철회하면 목록도 지워짐. 정책 담당 재검토 1회 후 확정. 대안: 최근 1개만 → C5 탭과 "이야기 주제 추천"이 의미를 잃어 탭 구조를 다시 설계해야 함.

- 실기기·디자인 승인 왕복이 예상보다 길면 M4가 뒤로 밀린다(가장 큰 불확실성). 대응: 캡처 몰아 찍기, 승인 기준표를 화면마다 미리 공유.
- TTS 엔진·오디오 포커스는 기기별 차이(삼성 기본 엔진 등) 미확인 → U1 스파이크에서 먼저 확인.
- 원격 서버 반영과 소셜 로그인 키가 늦으면 M2(원격 2대 동작)가 늦어지고 시나리오 A의 테스트 시작도 밀린다.
- 토스 미니앱은 이 일정에 넣지 않았다(07 계획대로 Play 다음). 병행하면 위 처리량 가정이 깨진다.
