# qa.md: 테스트·접근성·실사용 관찰 (가화만사성)

작성 2026-11-17 · 대상: 빌드 1(테스트 트랙 업로드용) · 코드 미실행, 설계 문서와 서버 5단계 구현 사실(coordinator 전달)만 근거
가정: 질문 없이 아래를 가정한다. (G1) 실기기는 Android 2대 이상(어르신용 저가형 1대 포함). (G2) 시각은 모두 KST. (G3) 어르신 앱 글자 최소 20sp, 버튼 64dp 이상, 한 화면 주요 버튼 3개 이하(SPEC 7-6). (G4) 숫자 중 "추정·가정"은 실측이 아니다. 도구명은 확인하지 못한 것은 "미확인".

역할 분담 원칙: 서버 규칙(보안·멱등·시간)은 자동 테스트가 소유한다. 사람은 "느낌과 이해"(5초가 빠른가, 문장이 이해되는가)만 소유한다. 자동 테스트가 통과해도 실기기 게이트는 생략하지 않는다.
reason 문장 매핑은 반드시 단위 테스트로 7개 전부(invalid / used / expired / rate_limited / busy / already_linked / not_parent_device) 비어 있지 않고 영어·코드 노출이 없음을 확인한다. 화면에 reason 원문이 보이면 출시 차단.

## 3. 실기기 시나리오
표기: 사전(P) / 절차(S) / 기대(E) / 실패 시 기록(R). 공통 R: 폰 모델·Android 버전·앱 버전, 시각(KST), 화면 녹화, 코드 앞 2자리 외 마스킹, A·B의 uid 말 4자리(개발 쪽 로그 조회용).

**S1 정상 흐름** P: A 로그인, B 신규 설치. S: A 번호 생성 → B 입력 → 연결 → 동의 "좋아요, 시작할게요" → 사진 → 밸런스 → 글씨 쓰기 → 완료. E: 5초 연결, 도장 1개, A 홈 1분 내 반영, 응원 문구 표시(빌드 2). R: 막힌 화면, 걸린 시간, 문구 캡처.

**S2 코드 틀림 5회 잠금(rate_limited)** P: 연결 안 된 B, 유효 코드 보유. S: 틀린 6자리를 1~5회 입력 → 6번째에는 올바른 코드 입력. E: 1~4회는 invalid 문장("번호를 못 알아봤어요… 틀려도 괜찮아요"), 5회 이후 올바른 코드도 잠금 문장(기다려 달라는 안내, 몇 분인지 이해되는 말)이며 10분 뒤(경계 10분 5초) 올바른 코드로 연결. 잠금 중 앱이 죽지 않고 "다음" 버튼이 무한 로딩 아님. R: 실제 잠금 시작·해제 시각, 안내 문장이 "실패·잠김·차단" 단어를 쓰는지. 확인 포인트: 5회째가 잠금을 시작하는지 6회째인지 서버 구현과 일치(개발 확인).
  - 변형: 앱 종료·재설치로 uid가 바뀌면 잠금이 풀리는 것은 설계상 우회 가능(dev §4, 수용). 기록만 하고 결함으로 올리지 않음.
**S2b 서버 busy**: 전역 300회는 실기기로 재현하지 않는다. 훅 또는 목 서버 응답으로 busy 문장만 확인(문장이 어르신 탓이 아님, "잠시 뒤에 다시" 류).

**S3 코드 만료(expired)·사용(used)·형식 오류** P: 만료 코드(개발이 `expires_at` 조정, §7), 이미 쓰인 코드. S: 각각 입력. 숫자 5자리·글자 섞기도 입력. E: expired는 "쓸 수 있는 기간이 지났어요", used는 "이미 쓴 번호" 계열 문장, 5자리는 버튼 자체가 눌리지 않거나 invalid 문장. 7일 만료 경계: 발급 6일 23시간 뒤 성공, 7일 1분 뒤 expired(경계는 DB 시각 조정으로만 검증). R: 화면 문구, 같은 코드 재시도 시 문장 변화.
**S3b already_linked / not_parent_device**: 이미 가족에 연결된 B에서 다른 가족 코드 입력 → 이해 가능한 문장(예: 이미 연결되어 있어요, 자녀분께 말씀해 주세요). 자녀 계정 기기에서 어르신 코드 입력 화면 접근 불가 또는 문장 확인. 문장이 없으면(영문·빈 화면) 높음.

**S4 동의 거부** P: 신규 B, 연결 직후. S: "싫어요, 다음에 할게요" → 코스 3단계 완료 → A 홈 확인 → B에서 설정 등에서 다시 동의 → 다음 날 코스. E: 코스는 끝까지 보임, 거부 후 안내 "알겠어요. 마음이 바뀌면…", 자녀 홈은 "어르신이 아직 준비 중이에요", 거부 중 answers 0행(개발이 DB 조회로 확인), 거부 전 저장분 영향 없음, 재동의 후부터 저장. R: 거부 중 자녀 화면 문구, 저장된 행 수.
  - 주의: 동의 거부 시 접속 여부(daily_sessions)를 자녀에게 보일지는 미결정. 결정 전까지 현재 구현대로 기록만 하고 판정 보류.
**S5 인터넷 끊김** P: 코스 중간. S: (a) 코드 입력 중 비행기 모드 → "다음" (b) 사진 로딩 중 (c) 마지막 단계 완료 직전 (d) 끊긴 채 완료 후 복구. E: "인터넷이 잠깐 끊겼어요" 문구, 하던 곳부터 이어가기, 복구 후 daily_sessions 정확히 1건 완료, 연속일 중복 증가 없음. 무한 로딩·빈 화면·크래시 0. R: 끊은 시점, 복구 시점, 유실된 단계.
**S6 강제 종료 후 재실행** S: 코스 2단계에서 최근 앱 목록 스와이프 종료 → 재실행; 코드 입력 중 종료; 연결 직후 동의 화면에서 종료. E: 재실행 시 코드 재입력 요구 없음(익명 세션 유지), 동의 화면으로 복귀(건너뛰지 않음), 오늘 진행 단계 유지 또는 처음부터라도 혼란 없음. 10회 콜드 스타트 반복 크래시 0. R: 복귀한 화면.
**S7 폰 교체·재설치 재연결** P: B 연결 완료, 답변 3일치. S: B 앱 삭제 → 재설치 → 처음 화면 → A에서 "기존 어르신 다시 연결"로 새 코드 → B 입력. E: 같은 어르신 프로필에 연결, 이전 답변·연속일 유지, 이전 폰(있으면)은 접근 불가. 재설치 직후 Android 자동 백업이 세션을 복원하는지 관찰(복원되면 코드 입력 없이 들어가므로 별도 기록, 미확인 위험). 새 코드를 쓰지 않고 "새 가족 만들기"로 잘못 가는 경로가 없는지. R: 복원 여부, 이전 기록 유지 여부, 걸린 시간.
**S8 푸시 거절** §2 조건 7과 동일 + Android 12 이하 기기(권한 요청 없음) 1대. 빌드 2에서 수신 허용/거절 비교 추가.
**S9 TTS 엔진 없음** P: 설정에서 TTS 엔진 사용 안 함 또는 엔진 없는 기기(저가 기기 비율 미확인). S: 코스 전체에서 "읽어 주세요" 탭. E: 코스 진행에 영향 없음, 읽기 실패 시 짧은 안내 1회(탓하지 않는 문구), 버튼 비활성 아님. 읽는 중 "멈추기" 동작, 화면 이탈 시 음성 중단. R: 엔진 상태, 안내 문구.
**S10 같은 날 코스 두 번 완료** §2 조건 5 + 두 번째 시도 때 화면이 "오늘 코스는 여기까지예요. 내일 또 만나요" 류인지(재시작이 아니라). 도장·연속일·자녀 홈 불변.
**S11 자정 경계(KST)** 서버가 날짜를 정하므로 폰 시계를 바꾸지 않는다. S: 23:50 시작해 00:05 완료, 폰 시계를 하루 앞으로 설정한 기기에서 코스. E: 날짜는 서버 기준(00:00 KST 이후 완료는 다음 날로 집계), 폰 시계 변조가 연속일에 영향 없음, 자정을 넘기면 오늘의 콘텐츠가 바뀜 안내 또는 정상 진행. 하루 유예(어제 완료 시 연속 유지) 동작은 자동 테스트가 소유, 실기기는 2일 연속 사용 1회로 N=2 확인. R: 시작·완료 시각, 집계된 날짜.
**S12 콘텐츠 순환(14일분 시작)** 자동 테스트 소유. 실기기는 시드로 15일째에 1일째 콘텐츠가 나오는지만 개발이 보여 주고 확인.
**S13 계정 삭제** A에서 삭제 → 로그아웃, 가족 데이터 정리, 방침·삭제 안내 URL 접속 확인. 삭제 후 B 화면이 이해되는 문장인지.

## 4. 접근성 점검
웹 검색은 하지 않았다. 아래 도구 이름은 일반 지식이며 현재 제공 여부·버전은 **미확인**, 사용 전 스토어에서 확인한다. 기준 수치(터치 48dp, 대비 4.5:1·3:1)는 WCAG·Android 지침으로 알려진 값이며 출처 URL은 미확인.

## 5. 어르신 3가구 실사용 관찰 프로토콜
목적: "도와주지 않고 지켜봤을 때" 어르신이 혼자 시작·완료할 수 있는지 확인. 평가 대상은 앱이지 어르신이 아니다.
**5-1 사전 준비·동의(방문 전 자녀 통해 전달, 방문 시 구두 재확인)**
- 서면 또는 자녀 대신 어르신 본인의 구두 동의를 받는다(법적 서식 아님, 개인정보 검토는 정책 담당 미확인). 항목: (1) 앱 쓰는 모습 관찰·메모 (2) 화면 녹화 (3) 얼굴 촬영(기본 "안 함", 손과 화면만 허용 여부 별도) (4) 입에서 나온 말 기록 (5) 언제든 중단 가능 (6) 중단해도 불이익 없음 (7) 기록은 개선 목적으로만 쓰고 이름 대신 "가구 1~3"로 저장.
- 촬영·녹음 거부 시 메모만 한다. 거부 사실도 기록하되 압박하지 않는다.
- 일정: 어르신 컨디션 좋은 오전, 1회 40분 이내(가정). 식사·약 시간 피한다. 어르신 폰이 없으면 테스트 전용 폰을 빌려 주되 개인 정보 없는 상태로.
**5-2 역할**: 진행자(스크립트 낭독·질문, 앱은 손대지 않음) 1명, 기록자(표 작성, 시계) 1명. 가능하면 자녀는 같은 방에 있되 어르신 시야 밖(뒤쪽)에서 "도와주지 않기"를 약속. 사용자 본인이 진행자나 기록자가 되면 앱 개발자 입장 방어를 하지 않는다.
**5-3 존엄 원칙**: 시험이 아니다 / 틀림·실패 단어 금지 / 어르신 탓으로 돌리지 않기("앱이 어려웠네요") / 한숨·화면 대신 눌러 주기 금지 / 존댓말, 호칭은 어르신이 정함 / 속도 맞추기, 침묵을 채우지 않기 / 언제든 "그만할게요" 가능, 즉시 중단 / 못 한 것은 "앱이 못 도운 지점"으로 기록 / 눈높이 앉기·글씨 큰 종이 안내 / 끝에 반드시 감사와 "많이 도와주셨어요" / 결과를 자녀에게 비교·평가로 전하지 않기 / 사진은 공개 자료에 얼굴 없이.
**5-4 진행 스크립트(약 35분)**
1. (3분) 인사, 목적 설명: "이 앱을 어르신이 쓰기 편한지 보는 거예요. 틀려도, 못 해도 괜찮고, 잘 안 되면 앱이 부족한 거예요." 동의 확인.
2. (2분) 자녀가 미리 폰에 앱 설치, 어르신은 홈 화면에서 앱 아이콘을 직접 찾아 켜도록 요청(설치 단계는 자녀 몫, 설치 확인만).
3. (20분) 과제: "자녀분이 번호를 보냈다고 해 볼게요. 여기 번호가 있어요(종이 카드, 예: 482 915, 테스트용). 오늘 사진을 보고 싶으시면 해 보세요." 이후 침묵. **도와주지 않기 규칙**: 질문받으면 "어떻게 하면 될 것 같으세요?"로 되돌린다. 안전 개입은 두 가지뿐: 어르신이 명백히 괴로워할 때(중단 제안), 30초 이상 아무것도 못 눌러 앱이 멈춘 것으로 보일 때(앱 문제로 기록하고 "제가 도와드릴게요" 후 복구). 도움을 주면 **도움 횟수·종류**를 기록(힌트 단계: 1 말로 방향, 2 화면 가리키기, 3 대신 눌러 줌).
4. (5분) 선택 과제: 틀린 번호 입력 상황은 어르신이 자연스레 겪을 때만, 일부러 만들지 않음. 코스를 마치면 "방금 자녀분께 어떻게 보일 것 같아요?"
5. (5분) 질문 8개(§5-6), 감사와 인사.
**5-5 관찰 항목 표(기록자용)**
| 시각 | 화면 | 헤맨 지점(멈춤 5초 이상·잘못 누름·되돌아감) | 소요(초) | 도움 단계(0~3) | 입에서 나온 말(그대로 적기) | 표정·몸짓 | 앱 탓/기기 탓 구분 |
|---|---|---|---|---|---|---|---|
측정할 소요: 아이콘 찾기~코드 입력 화면, 6자리 입력 완료, "다음"~연결, 동의 읽기·결정, 사진 단계, 밸런스 단계, 글씨 따라 쓰기, 전체. 기록 칸에 "큰 소리로 읽음/읽어 주기 사용/무시" 포함.
**5-6 끝나고 질문 8개**(개방형, 하나씩)
1. 처음 켰을 때 무엇을 해야 할지 알 수 있었어요?
2. 번호를 쓰는 곳은 쓰기 편했어요? 불편했던 점은요?
3. "고른 답이 자녀분께 보여요"라는 말, 무슨 뜻으로 이해했어요? (동의 화면 이해도)
4. 사진을 보고 떠오른 게 있었어요? 얼마나 보고 싶으셨어요?
5. 글씨 쓰기와 질문 고르기 중 어느 쪽이 더 편했어요? 왜요?
6. 소리로 읽어 주는 기능은 어땠어요? 필요했어요?
7. 글자와 버튼 크기는 어땠어요? 눈이 피곤하지는 않았어요?
8. 내일 또 켜 보고 싶으세요? 아니라면 무엇이 달라지면 켜실까요?
**5-7 성공 기준(가정, 3가구는 통계가 아님)**
| 지표 | 합격 | 경고 |
|---|---|---|
| 도움 없이(도움 단계 0) 코스 3단계 완료 | 3가구 중 2가구 이상 | 1가구 이하 → 빌드 2 전에 화면 수정 |
| 코드 입력~연결(첫 시도, 도움 없이) | 3가구 모두 3분 이내(가정) | 한 가구라도 도움 3 필요 |
| 동의 화면 의미 설명 | 3가구 중 2가구가 "자녀가 본다"를 말로 설명 | 이해 못 하고 "좋아요" 누름은 높음 기록 |
| 5초 이상 멈춤 | 화면당 평균 1회 이하 | 같은 화면에서 3가구 중 2가구 멈춤 → 설계 결함 |
| 내일 또 쓰겠다는 의사(질문 8) | 3가구 중 2가구 긍정 | 0가구는 PM 전달 |
| 부정적 감정 표현("바보가 된 것 같아") | 0건 | 1건이라도 출시 전 문구·흐름 재검토 |
**5-8 결과 정리 양식**
```
가구 N / 일자 / 기기·OS / 글자 크기 설정 / 동의 항목 허용 범위(관찰·녹화·얼굴)
완료도: 연결(Y/N, 도움단계) / 동의 이해(Y/N) / 3단계 완료(Y/N) / 총 소요(분)
헤맨 지점 Top3: (화면, 상황, 어르신 말 인용, 원인 추정, 심각도 §6)
잘된 점 2개
질문 8개 답변 요약(인용 우선)
발견 이슈 → 버그 ID 연결
다음 행동(문구 수정 / 화면 수정 / 보류) + 담당
```
결과는 가구별 1장 + 종합 1장. 어르신 이름·주소는 적지 않는다.

## 6. 버그 보고 양식·심각도·회귀 목록
**양식**
```
ID / 보고일 / 보고자
제목(한 줄, 증상 중심)
심각도: 출시 차단 / 높음 / 보통 / 낮음
환경: 기기·OS·앱 버전(빌드 번호)·네트워크·글자 크기·TalkBack 여부
역할: 어르신 / 자녀 / 서버 (관련 시나리오 ID S1~S13)
재현 절차(번호 목록) / 기대 / 실제
재현율: N회 중 M회
증거: 화면 녹화·스크린샷(개인정보 가림), 시각(KST), uid 말 4자리
어르신 영향: 어르신이 읽은 문장 그대로
추정 원인(선택) / 담당 / 수정 빌드 / 회귀 확인
```
**심각도**
| 등급 | 기준 | 예 |
|---|---|---|
| 출시 차단 | 보안·데이터 유출, 완료 조건 10개 중 하나 불합격, 크래시로 코스 불가, 어르신이 연결 자체를 못 함, 동의 거부인데 저장됨, "치매 예방/치료" 문구, reason 원문·영문 오류 노출 | 다른 가족 답변 노출, 6번째 시도에 영구 잠금 |
| 높음 | 우회 가능하나 어르신이 도움 없이 못 넘김, 연속일 오계산, 1분 초과 반영 지연이 빈번, 문장이 어르신 탓·실패 단어 사용, 20sp 미만 | 5회 잠금 문장이 이해 불가 |
| 보통 | 불편하지만 혼자 해결 가능, 접근성 150% 외 깨짐, TTS 불가 안내 어색 | 200%에서 글자 겹침 |
| 낮음 | 외관·오타·문구 톤 미세 | 간격 4dp 차이 |
**회귀 목록(매 빌드 실행, 약 30분, 가정)**
1. 코드 연결 성공(5초)과 reason 7종 문장 단위 테스트 통과
2. 5회 잠금과 10분 후 해제
3. 동의 거부·허용에서 answers 저장 여부
4. 코스 완료 → 자녀 홈 1분 반영
5. 같은 날 2회 완료 연속일 불변
6. 재설치 재연결 기록 유지
7. 푸시 거절 무오류
8. TTS 없음에서 코스 완료
9. 글자 150%에서 어르신 화면 6개 잘림 0
10. `npm run verify`, pgTAP 전체, 금지 문구 grep
11. 릴리스 빌드 콜드 스타트 10회 크래시 0
출시 차단·높음 버그를 고친 빌드는 해당 시나리오 + 위 11개 전체를 다시 실행.
