## 확인 결과

1. **'알겠어요'(ack)**: 1개·여러 개, 100%·200% 모두 닫는 버튼은 '알겠어요' 하나이고 주 버튼 모양이다. 하는 쪽 버튼은 없다. 누르면 닫히고 코스 홈으로 돌아간다.
2. **200%**: 1개는 넘치지 않는다. 4개는 본문이 넘쳐서 '더 있음' 띠가 뜨고, 버튼은 늘 카드 안에 남는다. 끝까지 올리면 띠가 사라진다.
3. **뒤로 가기 = 닫는 쪽(알겠어요) = 읽음 처리**
   - 기기에서 보이는 것은 '닫힘'까지다. fake 는 메모리에만 있어서 앱을 다시 열면 응원이 처음 상태로 돌아온다. 그래서 '읽음 처리'는 기기 캡처로 증명할 수 없다.
   - 읽음 처리는 jest 로 고정했다: `cheerArrive.test.tsx` '안드로이드 뒤로로 닫아도 읽음 처리'. 뒤로(onRequestClose)로 닫으면 `markCheersRead(['cheer-1','cheer-2'])`.
   - 실패 확인: CheerDialog 에 `onBack={() => setOpen(false)}`(뒤로 = 닫기만)를 넣으면 이 테스트가 FAIL → `Expected: ["cheer-1", "cheer-2"]`, 호출 없음.
4. **관찰(이번 PR 에서 고치지 않음)**: '읽어 주세요'는 응원 문장 **위**에 있다. CheerDialog 주석은 "응원 문장 바로 아래"라고 적혀 있다. 옛 ui/Dialog 와 ds Dialog 모두 children 을 body 앞에 그리므로 이행 전과 같은 배치다. 배치(위·아래) 결정과 주석 정정은 디자인 확인이 필요하다.
5. 못 본 것: TalkBack 초점 이동(열릴 때 제목, 닫힌 뒤 코스 홈 제목 — R12 는 jest 로 확인), 바깥 누르기, iOS, 실서버(real API) 읽음 처리.
