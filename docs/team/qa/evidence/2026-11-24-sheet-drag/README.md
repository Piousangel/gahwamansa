## 확인 결과

1. **끌기·닫기(손잡이·내용)**
   - 처음 실측에서 **손잡이 끌기가 Android 에서 무반응**이었다(jest 는 통과). 누르는 순간 응답자가 없으면 이동 사건의 '잡을까' 질문이 손잡이까지 오지 않았다(내용은 안의 선택지가 응답자라 됨). → 손잡이가 누르는 순간 응답자가 되게 고침 + 시험(sheetDrag '손잡이는 누르는 순간 응답자가 되고…', 고치기 전 코드에서 Expected true / Received false).
   - 고친 뒤: 응원 100% 손잡이 천천히 끌다 놓기 → 제자리, 빠른 쓸기 → 닫힘. 응원 100% 내용(넘치지 않음) 빠른 쓸기 → 닫힘. 200% 응원·호칭·유료 손잡이 빠른 쓸기 → 모두 닫힘. 천천히 끌다 놓으면 제자리.
2. **Android 내용 아래로 당기기(M1)**: 200% 로 넘치는 세 시트(응원·호칭 바꾸기·유료 안내) 모두 스크롤 맨 위에서 내용을 아래로 끌면 **시트가 움직이지 않고 네이티브 스크롤이 손가락을 가져간다**(늘어남 효과). 빠른 쓸기도 닫히지 않음. 손잡이·X·뒤로 가기·밖 누르기로는 닫힌다. 안쪽 위로 밀기(스크롤)는 정상.
   - 새 설치 없이 막는 길을 검토했으나 채택하지 않음(비교 메모 '남은 한계'): 스크롤 맨 위에서 스크롤을 꺼 두면 Android ScrollView 가 그 제스처의 누름을 못 봐서 **위로 미는 첫 제스처가 죽고**, JS 로 대신 스크롤하면 관성이 없어진다. → gorhom(RNGH 네이티브 제스처 동시 인식)로 옮길 조건에 넣음.
   - 넘치지 않는 시트(100% 응원·호칭 겹침 안내)는 내용 끌어 닫기가 된다.
3. 못 본 것: TalkBack 손잡이 두 번 누르기(실기기·QA 회차에서), iOS.
