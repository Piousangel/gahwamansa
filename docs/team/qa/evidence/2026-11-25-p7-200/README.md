# P7 200% 본문 첫 화면 실측 (대기열 33) · 2026-11-25

320×640 200%에서 P7(코스를 마친 화면)이 첫 화면에 제목만 보이던 문제를 고치기 전과 뒤에 찍었다.
#259 캡처([2026-11-25-five-steps-followup](../2026-11-25-five-steps-followup/README.md)) R2와 같은 장면이다.

## 찍은 조건

- **기기**: 에뮬레이터 gahwa_small(emulator-5556, `-read-only`, 창 없음). S25는 건드리지 않았다(모든 adb 명령에 `-s emulator-5556`).
  - 시작 때 화면 설정: 1080×2340, density 440, 글자 1.0, TalkBack 끔(`enabled_accessibility_services` = null)
  - 호스트 부하 1분 평균: 시작 때 4.3이었다. 찍는 동안은 3.9~11.6이었다(15를 넘은 때 없음). APK 빌드 중에는 20까지 올랐는데, 그때는 찍지 않았다.
- **빌드**: 설치돼 있던 staging APK에는 gesture-handler(#255) 네이티브 모듈이 없어 JS가 뜨지 않았다. 그래서 이 브랜치로 `assembleStagingDebug`(arm64)를 새로 빌드해 에뮬레이터에만 설치했다.
  - Metro는 8091에서 띄우고 `adb reverse tcp:8081 tcp:8091`로 연결했다. 맥의 8081은 건드리지 않았다.
- **임시 상태** (커밋하지 않았고, 끝난 뒤 모두 되돌렸다)
  - `config.local.ts`: 예시 파일을 복사했다(`API_MODE: 'fake'`). 끝난 뒤 지웠다.
  - `App.tsx`: 장면 파일(`scene.tmp.ts`)을 읽어 `createFakeApi({linked, consented, realImage, completedSteps, skippedSteps, passOnKey})`로 띄웠다. `restore`를 켰다.
    - 5단계 스위치는 #254 README 방식대로 시작 때 `setFeature('fiveSteps', …)`로 켰다.
  - `CourseHome`: 내용이 오면 P7로 바로 가게 했다(장면마다 단계를 손으로 누르지 않으려고). P7 화면은 세션 내용만 보고 그린다.
  - `useFoldGap`: 접힘 계산 값(창 높이·요소 높이·민 자리)을 `console.log`로 찍었다. 아래 실측 표가 그 값이다.
  - fake 사진 주소는 `http://localhost:8093/day-01.jpg`로 바꿨다(`content/photos`를 맥에서 띄우고 `adb reverse tcp:8093`).
- **크기**
  - 360×640dp 100%: `wm size 990x1760`, `font_scale 1.0`
  - 320×640dp 200%: `wm size 880x1760`, `font_scale 2.0`
  - 회귀용: 150%는 `font_scale 1.5`, 180%는 `font_scale 1.8`
- **끝난 뒤 되돌린 것**
  - `wm size reset`(1080×2340), `wm density reset`(440), `font_scale 1.0`, TalkBack 끔(null)을 확인했다.
  - reverse를 지웠다. 에뮬레이터·Metro 8091·사진 서버 8093을 껐다.

## 원인 실측 (고치기 전)

접힘 창은 모든 크기에서 446이다. 묶음 위 끝은 12, 요소 사이는 16이다.

| 크기·배율 | 마운트 | 제목 | 건넨 줄 | 본문 | 결과 |
|---|---|---|---|---|---|
| 320×640 200% 3단계 | 274.5 | 97.5 | — | 160 (4줄) | 본문 416~576이 접힘에 걸려 통째로 밀림 → 첫 화면에 제목만 |
| 320×640 200% 건넨 날 | 274.5 | 97.5 | 40 | 160 | 건넨 줄 416~456도 걸림 → 제목만 |
| 360×640 200% 3단계 | 274.5 | 97.5 | — | 120 (3줄) | 같은 문제 |
| 320×640 150% 3단계 | 220.4 | 42.2 | — | 96 | 본문까지 들고 43 남음(문제 없음) |
| 360×640 100% 3단계 | 274.5 | 42.2 | — | 64 | 들어감(문제 없음) |

- 마운트 274.5 = 위 여백 8 + 카드 244.5 + 아래 여백 22이다. 카드 안 캡션 3줄이 114.5(한 줄 38)다.
- 200%에서는 제목 뒤 남는 칸이 446 − 400 − 16 = 30이다. bodyLg 한 줄(40)도 들지 않는다.
- 캡션이 두 줄이 돼도 38만 늘어난다(68). 3단계 본문(160)은 여전히 통째로 밀린다. 그리고 200%에서 '실제 장소가 아니에요' 한 줄은 약 330이라 글 칸 244에 들지 않는다.

## 고친 뒤

글자 1.75배 이상이면 **제목 → (건넨 줄) → 본문 → 마운트** 순서다. 마운트는 R-15대로 통째로 접힘 아래로 간다.

| 크기·배율 | 순서·높이 | 민 자리 |
|---|---|---|
| 320×640 200% 3단계 | 제목 97.5 · 본문 160 · 마운트 286.5 | 마운트만 +146 |
| 320×640 200% 건넨 날 | 제목 · 건넨 줄 40 · 본문 160 · 마운트 | 마운트만 +90 |
| 360×640 200% 3단계 | 제목 · 본문 120 · 마운트 | 마운트만 +186 |
| 320×640 180% 3단계 | 제목 92.4 · 본문 110.2 · 마운트 276.7 | 마운트만 +201 |
| 320·360×640 150%, 360×640 100% | 고치기 전과 같은 값 | 고치기 전과 같음 |

마운트 높이가 12 늘어난 것은 본문 뒤에 올 때 위 여백(8 → 20) 때문이다. 처음에는 8 그대로 찍었는데, 밀린 마운트의 테이프 끝이 접힘선 위에 걸쳐 보였다. 그래서 여백을 늘리고 다시 찍었다.

## 캡처

파일 이름은 `{크기}-{배율}-{before|after}-{장면}.png`다. 장면 이름은 다음과 같다.

- `3steps`: 스위치 꺼짐 3단계
- `passed`: 5단계 ⑤에서 건넨 날
- `stop`: 5단계 '오늘은 여기까지'로 마친 날(⑤ 넘김, 건넨 줄 없음)
- `-end`: 끝까지 내린 화면

| 장면 | 전 | 후 | 본 것 |
|---|---|---|---|
| 3단계 P7 | `320-200-before-3steps.png`<br>`360-100-before-3steps.png` | `320-200-after-3steps.png`<br>`360-100-after-3steps.png` | 200%: 전에는 제목만 있었다. 후에는 제목과 본문 4줄이 모두 첫 화면에 있다. 테이프 끝도 접힘선에 걸치지 않는다.<br>100%: 전후가 같다(마운트 → 제목 → 본문 2줄). |
| 5단계 건넨 날 P7 | `320-200-before-passed.png`<br>`360-100-before-passed.png` | `320-200-after-passed.png`<br>`320-200-after-passed-end.png`<br>`360-100-after-passed.png` | 200%: 전에는 제목만 있었다. 후에는 제목, 「가족에게 건넸어요」, 본문 4줄이 첫 화면에 있다. 내리면 마운트(사진·家 인장·AI 고지 3줄)가 통째로 보인다.<br>100%: 전후가 같다(#259처럼 둘째 줄만 접힘 아래). |

- `AlbumMount`를 쓰는 곳은 `CourseDone`(P7) 하나뿐이다(`grep -rn AlbumMount app/src`). 그래서 다른 화면 회귀 캡처는 없다. 대신 P7의 세 장면과 다섯 배율을 찍었다.
- 미연결 P7은 장면 파일로 띄우면 역할 고르기 화면으로 시작해 찍지 못했다. 미연결도 같은 순서 규칙을 따른다(본문 요소 하나 + 마운트). jest `p7BodyFirst200`가 순서를 고정한다.
