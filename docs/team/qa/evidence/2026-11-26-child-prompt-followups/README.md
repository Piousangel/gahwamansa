## 발견
- **M1 복사 뒤 C3 줄에서 직접 켜면, 권한 창에서 돌아올 때 같은 질문이 다시 뜰 수 있다**
  - 흐름: 복사 → 줄 [알림 켜기] → OS 권한 창(GrantPermissionsActivity라 background → active) → AppState 판정이 `offer('wait')`를 부른다 → `childPromptState`가 `my_push_settings`를 읽는다.
  - 이 읽기가 줄의 `set_push_enabled(true)` 저장보다 먼저 끝나면 `enabled=false`라서 'ask'가 나오고, 방금 허용한 사람에게 '알려 드릴까요?' 한 장이 뜬다.
  - 두 호출은 거의 동시에 나간다(권한 결과 → 동의 저장, 복귀 → 읽기). fake는 즉시 응답이라 기기에서는 재현되지 않았다(a100-22). 탐침 P1에서는 40ms 지연으로 재현된다.
  - 제안: 줄의 [알림 켜기](`notify.open`)를 누르면 `didCopy`·`leftAfterCopy`를 끈다(누른 것 = 답함). 또는 offer 전에 `notify.consented`나 진행 중 상태를 본다.
- **M2 다른 화면(설정)에 있을 때도 복귀 판정이 동작한다**
  - 흐름: 복사 → [설정] → 앱 밖 → 복귀하면 설정 화면 위에 C3 한 장이 뜬다(a100-31). Wait 화면이 스택 아래에 마운트된 채 구독하고 있기 때문이다.
  - 사용자는 설정을 보던 맥락에서 갑자기 질문을 받는다. 뒤로를 누르면 화면이 아니라 한 장이 닫히고 '오늘은 넘김'(`skipChildPromptToday`)으로 기록된다(a100-32).
  - '설정 → 설정 열기(휴대폰 설정) → 복귀'처럼 앱을 떠나는 길이 실제로 있다.
  - 제안: 포커스(`useIsFocused`/`navigation.isFocused()`)일 때만 offer하고, 포커스가 아니면 `leftAfterCopy`를 남겨 두었다가 C3로 돌아온 뒤 처리하거나 버린다.
- **L1 구독 해제가 시험으로 고정되지 않는다**(위 '못 잡는 것'). 연결 후 Tabs로 reset하므로 실제로는 언마운트되며 해제된다.
- 받기 동의 전 getToken 0회: 복사 경로 시험에 `getToken not called`가 있다 ✅. 기기에서는 토큰 호출 수를 따로 재지 않았다.
