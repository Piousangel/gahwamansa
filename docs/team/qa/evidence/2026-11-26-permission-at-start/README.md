- 기기: emulator-5556 `gahwa_small`(API 35, Android 15), 맥 1분 평균 부하가 15 이하일 때 진행했다.

### 접근성 (uiautomator 계층 = TalkBack이 읽는 순서)
TalkBack 앱이 없는 이미지라서 소리 확인 대신 계층을 확인했다. 대화상자 안의 노드만 노출되고 뒤 화면은 노출되지 않는다(accessibilityViewIsModal).

- **100% 읽는 순서**
  1. 제목 '엄마 폰과 연결되면 알려 드릴까요?'
  2. '연결될 때와 첫 답이 보일 때만 알려 드려요'
  3. '안 받아도 앱은 그대로 쓸 수 있어요'
  4. **버튼 '알림 켜기'**(힌트 '휴대폰이 한 번 더 물어봐요')
  5. 힌트 줄
  6. **버튼 '안 받을게요'**
- **200%**: 순서는 같다. 힌트 줄만 본문 스크롤 끝(3과 4 사이)으로 옮겨진다.
- 누를 수 있는 영역: 버튼 높이는 100%에서 168px(56dp), 200%에서 168px와 176px이다. 48dp 이상이다.

## 못 한 것
- **연결 직후 화면(`title_done`) 캡처**: 한 기기 fake에서는 역할을 전환하면 앱이 처음부터 다시 열린다. 그래서 자녀가 C3를 보고 있는 동안 연결되는 상황을 만들 수 없다. 이 경우는 단위 시험 `pushPermissionAtStart` '번호를 보내지 않았으면 연결 직후 한 장'으로 덮는다.
- 12 이하 이미지와 '안 받을게요' 후 재실행: 단위 시험으로 덮는다(`gahwa_small`은 API 35뿐이다).

## 발견 (모두 L)
- **L1 공유 창 오탐**: Android `Share.share`는 공유 창이 열리는 순간 `sharedAction`으로 끝난다(RN Android). 그래서 앱을 고르지 않고 뒤로 나와도 '보냈다'로 처리돼 한 장이 뜬다(a100-03).
  - PR 본문도 '돌아온 것을 기준'이라고 적고 있다. 이미 있던 U12 `sent` 판정을 그대로 물려받은 것이다.
  - 문구가 '연결되면'이라서 보내지 않은 사람이 봐도 틀린 말은 아니다.
- **L2 복사 직후 한 장**: 복사한 사람의 다음 걸음은 메신저로 가서 붙여 넣는 것이다. 그 사이에 한 장이 끼어든다. 화면 안의 '복사했어요' 띠도 이 한 장에 가린다(a100-11).
  - 대안: 복사 경로는 빼고, 공유 경로와 연결 직후 화면 두 자리만 남긴다. 판단은 디자인에 맡긴다.
- **L3 열린 채 연결됨**: 'wait' 한 장이 떠 있는 동안 확인 주기에서 연결이 잡히면, 화면은 '연결됐어요'로 바뀌는데 한 장 제목은 '…연결되면 알려 드릴까요?'로 남는다. 흔하지 않은 경우다.
- **L4(이 PR 밖, ds Dialog)**: 320×640·200%에서 대화상자 카드 위 끝(y=96px)이 상태 표시줄 시계·아이콘과 겹친다(b200-03). `statusBarTranslucent`로 생긴 문제이며 N1도 같다.
