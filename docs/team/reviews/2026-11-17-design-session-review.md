# 설계 세션 A·B·C 독립 검토 (시니어·접근성 UX + 개인정보·정책)
대상: docs/team/board/2026-11-17-design-session/A.md·B.md·C.md. 대조: DECISIONS 마지막 항목들, copy-v3-confirmed, migrations 0003·0004·0012·0014, Screen.tsx·AndroidManifest. 검토만, 코드 수정 없음.

## A. 자녀 연결 대기 화면(C3)
- **높음 — 연결 후 남은 번호가 계속 살아 있음.** `issue_invite_code`는 가족당 미사용 번호를 5개까지 두고, `redeem`은 쓴 번호 1개만 소모. "새 번호 받기"나 재발급 뒤 옛 번호가 7일간 유효해, 카톡으로 보낸 번호를 다른 사람이 쓰면 '부모'로 가족에 들어옴. 제안: 새 번호 발급 시 같은 가족의 기존 미사용·대상 없는(target null) 번호 무효화, 첫 연결 성공 시 남은 번호도 무효화. pgTAP 추가.
- **높음 — "부모님이 이미 쓰는 중에 새 번호" 엣지 미정.** 위를 적용하면 부모가 옛 번호를 받아 적는 사이 무효화돼 "invalid"를 봄. 제안: 만료 전에는 "새 번호 받기"를 감추고(만료 때만 노출), 만료 후 재발급 시 화면에 "전에 보낸 번호는 이제 안 돼요" 한 줄.
- **중간 — 남은 기간 표시가 서버와 어긋남.** `expires_at = 발급 시각 + 7일`이라 17일 오후 3시 발급분은 24일 오후 3시에 끝나는데, "24일까지"는 그날 밤까지로 읽힘. 제안: 날짜+오전/오후("24일 오후 3시까지") 또는 하루 내려 표기. 기기 시계가 아닌 응답 `expires_at`로 계산.
- **중간 — 3단계가 실제 흐름과 다름.** ② 실제 버튼은 "부모님 휴대폰이에요", ③ "번호 6개"는 "숫자 6개", "쓰면 끝이에요"인데 그 뒤 P2 동의가 있음. 제안: ②는 버튼 글자 그대로 인용, ③ "숫자 6개를 쓰고, 답을 보여 줄지 고르면 돼요". "번호 보내기" 공유 문구에 스토어 링크·3단계를 함께 넣기(부모가 전화 없이도 따라 하게).
- **중간 — 미리보기가 실제 가족 데이터로 오인될 위험.** "{호칭}께 매일 이런 사진이 가요"에 호칭이 들어가고 폴라로이드가 C4와 같은 모양이면 '이미 연결돼 보이는 화면'으로 읽힘. 제안: 카드마다 "예시" 띠, 미리보기 안에 {호칭}·날짜·고른 답 넣지 않기, 고르기 화면은 선택 불가 상태로(A의 보기 전용 유지). 하루 코스 3장 넘김은 빌드1 범위에서 과함(3h) — 사진 1장+질문 1줄로 충분, 3장은 빌드2 후보.
- **중간 — 알림 권한 순서.** Android 13+ 시스템 창은 거절 2회면 다시 못 띄움. 제안: 앱 안 안내(한 줄+[알림 켜기]) → 누를 때만 시스템 창, 거절 후엔 "설정에서 켜기"로 바꿈, 처음 진입에 자동으로 띄우지 않음. 연결 감지는 푸시만 믿지 말고 앱 포그라운드 복귀·화면 진입 시 상태 조회(폴링 또는 Realtime)를 명시.
- **낮음** — 상태 칩 점 애니메이션은 이득 적음(동작 줄이기 대응까지 필요) → 정지 칩으로. 화면이 150%에서 3~4화면 길이: 번호 카드·3단계를 첫 화면 높이 안에, 미리보기는 그 아래로 확인.

## B. 한글 단계 → 자판으로 낱말 쓰기(P6)
- **높음 — `autoCorrect=false`가 추천을 끔(결론과 모순).** RN Android는 autoCorrect=false를 `TYPE_TEXT_FLAG_NO_SUGGESTIONS`로 넘겨 삼성·Gboard의 추천 줄을 끔. "추천은 기기 설정 그대로"와 반대. 제안: 둘 중 하나로 결정 후 실기기 확인. 추천을 살릴 거면 autoCorrect 지정 안 함.
- **높음 — 금지어 계열 문구.** 보조 "틀려도 괜찮아요"는 금지어 "틀렸" 계열, 시트 "한 글자가 달라요"는 실제 차이가 여러 글자여도 '한 글자'로 말하고 채점처럼 읽힘. 제안: "천천히 써 봐요" 단독, 시트 "낱말을 한 번 더 볼까요?" [다시 써 볼게요]/[이대로 마칠게요]. "쳐 볼게요"는 라이터 원칙(쓰다)과도 불일치.
- **높음 — 제어형 TextInput과 한글 조합.** `value`를 매 입력마다 다시 넣으면 Android 삼성 키보드에서 조합이 깨지거나 글자가 두 번 들어가는 문제가 알려져 있음. 제안: 비제어(defaultValue)+onChangeText로 읽기만, 입력값을 가공해 되돌려 넣지 않기. RN에는 조합 시작·끝 이벤트가 없으니 "조합 중 음절 판정 안 함"은 구현 불가 — "목표와 같아지면 채움"만 남기고 문장 삭제.
- **중간 — 자동 완료 0.6초.** 마지막 글자가 맞는 순간(천지인은 받침 전 중간 상태도 거침) 바로 칭찬으로 바뀌고, 자판이 열린 채면 칭찬이 자판에 가려짐. 제안: 일치 시 자판 닫기(Keyboard.dismiss)→칭찬, 다음 화면 이동은 [마치기]로만. 지연 1.2초 이상.
- **중간 — 키보드 회피 방식 충돌.** B는 `adjustResize` 전제, DECISIONS·Screen.tsx는 edgeToEdge라 adjustResize가 창을 줄이지 않아 `behavior=padding` 사용. 제안: 공용 Screen 방식 그대로, 320폭·200%·천지인(키보드 높이 큼)에서 카드+입력칸+버튼이 보이는지 QA 항목에 넣기.
- **중간 — '넘어갈게요'가 너무 쉬움.** 자판 열기 전부터 같은 무게의 출구가 3개(다 썼어요·이대로 마칠게요·넘어갈게요). 제안: '넘어갈게요'는 입력칸을 한 번 누른 뒤나 10초 뒤에 노출, 이벤트로 넘김 비율을 보고 50% 넘으면 재설계. 도장은 그대로(평가 안 함 원칙).
- **중간 — 판정 규칙 빈칸.** 음절 칸 채움이 '앞에서부터 일치'인지 '자리별 일치'인지 미정. 자동 띄어쓰기·추천 뒤 붙는 공백은 제거로 해결되나, 추천이 "가을에"처럼 조사를 붙이면 불일치 → 앞부분 일치 시 칸은 다 채우고 시트 대신 칭찬 허용 검토. 낱말은 한글만(숫자·영문·띄어쓰기 없음), 2~4음절, 쌍자음·겹받침은 천지인 난도 높아 첫 주엔 제외.
- **낮음** — 화면 읽기: TalkBack 사용자는 자판 입력 자체가 어려움 → 카드 라벨에 "자판으로 쓰거나 넘어갈 수 있어요" 안내. 이벤트 `attempts` 정의(다 썼어요 누른 수) 명시.

## C. 자녀 "지난 답" 범위(C5)
- **높음 — 어르신이 2명 이상이면 답이 섞임.** 서버는 번호마다 새 parent 프로필을 만들고(0004), `child_summary`도 parents 배열. "빌드1은 한 목록, 행에 구분 없음"이면 엄마 답이 아빠 답으로 보이는 오표시. 제안: RPC에 parent_id(또는 순번) 포함, 2명 이상이면 행에 구분 표시. 안 되면 빌드1에서 어르신 1명 제한을 서버에서 강제.
- **높음 — 재동의 게이트가 과하고 실패 경로 미정.** v1 문구 "고른 답과 날짜가 가족에게 보여요"는 기간 제한이 없어 30일 목록을 이미 포함. 범위를 넓히는 게 아니라 좁히는 변경이라 재동의보다 고지로 충분하다고 봄(법률 확인 §4-5에 이 판단 추가). 출시 전 테스트 기기뿐이면 게이트를 만들지 말고 스테이징 데이터 초기화 + 출시 버전부터 v2. 굳이 게이트를 두면 "싫어요"가 철회(답 삭제)로 처리되지 않게, 코스 진입을 막지 않게 명시.
- **중간 — 동의 기록이 버전별로 남지 않음.** `give_consent`는 `consented_at = coalesce(기존, now())`라 v2로 바꿔도 시각이 v1 그대로. 제안: 버전 바뀔 때 시각 갱신 또는 동의 이력(버전·시각) 행 추가 — 증빙용.
- **중간 — 30일 지난 답 보관 근거.** "노출만 안 함, 연결 기간 동안 저장"은 목적(가족에게 보여 주기) 달성 뒤 보관이라 최소 보유 원칙과 충돌 소지. 어르신 본인 화면(앨범 등)에서 쓰지 않으면 31일 지난 답 파기(일 배치). 쓴다면 그 목적을 처리방침에 적기.
- **중간 — 날짜 기준.** `answered_at`은 답을 바꾸면 now()로 갱신됨(0014). 목록·30일 경계는 `session_date` 기준으로. 기존 `child_summary`도 같은 문제.
- **중간 — 감시 느낌 완화.** 날짜 목록은 빈 날을 역산하게 함. 집계 금지는 좋음. 추가로 어르신 설정에 "가족에게 이렇게 보여요" 미리보기(자녀 화면과 같은 RPC 결과) — 무엇이 보이는지 본인이 확인. 보조 문구 "최근 한 달 동안 고른 답이에요"는 유지.
- **낮음** — RPC: 동의 철회·프로필 삭제 시 즉시 0행은 답 삭제+`consented_at` 확인으로 충족, `my_family_id()` 범위 확인만 pgTAP에. "A와 B 중" 생성은 받침에 따라 와/과("바다와") 처리 필요. limit 30은 어르신 2명이면 부족 → 어르신별 30.

## 우선 처리 순서
A 남은 번호 무효화 → C 어르신 여러 명 구분 → B autoCorrect·조합·금지어 → C 재동의 게이트 단순화.
