## A. privacy-v2.html
- **높음** 4절 보관 기간 `[팀 결정 필요]` 4건은 이미 결정됨(DECISIONS "코스 기록 31일, 응원 31일, 초대 번호 30일, 입력 시도 기록 30일, 파기 배치는 0023과 함께"). 확정값으로 바꾸고 상태는 "0023 구현 후 게시"로. 서버 현황: redeem_attempts는 지우는 코드 없음, invite_codes는 사용된 번호를 안 지움(미사용 만료분만 발급 시 정리, 0018) → 0023 전에는 문장이 거짓. 검토 요청 4(도장 충돌): 이번 주 도장은 최대 7일분이라 31일과 충돌 없음. 단 record_session_step의 streak 값은 31일 파기 뒤 31 이상 못 셈 — 앱이 안 보여 주면 무관(확인만).
- **높음** 1·3절 "가족에게는 최근 30일 동안 고른 답만 보입니다"에 불확실 표시가 없음. 현재 child_summary(0012)는 **가장 최근 답 1건**만 돌려줌. 30일 목록은 0021 예정 → 게시 조건에 0021 추가.
- **높음** 검토 요청 5: DECISIONS가 "마지막 자녀 탈퇴 시 부모님 익명 auth 계정도 삭제(서버 큐)"로 결정. 0017 현재 코드는 안 지움. 방침은 "함께 지웁니다"로 쓰고 서버 큐 구현을 게시 조건으로.
- **중간** 3절 마지막 줄(동의 v1→v2 재동의 생략): 운영 서버는 새 Pro 프로젝트(DECISIONS 운영 결정)라 운영에 v1 동의자가 없음. 게시본에서는 문장 자체를 빼는 것을 권함(앱 CONSENT_VERSION='v2' 확인). staging 테스터에게만 별도 안내.
- **중간** 국외 이전(제28조의8 고지 항목): ① Google 행 "전 세계"는 **이전 국가**로 부족 — "미국 등 Google 데이터센터 소재국(목록 링크)"처럼 국가를 적을 것 ② Supabase 로그 "EU"도 국가명 확인 ③ Google 연락처 TODO ④ 이전 방법 "네트워크로"→"인터넷으로 보냄"(쉬운 말). 검토 요청 1: EU 로그 저장은 실제 국외 보관이라 고지가 맞고, 지원 인력 접근은 보수적 고지로 과하지 않다고 봄. 같은 이유로 1절에 "일부 정보는 해외 서버에서도 처리" 한 줄 추가 권함.
- **중간** 법정 기재 대조(제30조·시행령 제31조): 처리 목적·항목·보유 기간·위탁·국외 이전·권리 행사·보호책임자·구제 방법·변경은 있음. 보강할 것 ① **파기 절차·방법**: "되살릴 수 없게" 한 줄뿐 → "매일 정해진 시각에 자동 삭제, 백업은 7일 뒤 덮어씀, 전자 파일은 복구할 수 없는 방법으로 삭제" ② **처리 근거**(동의/서비스 제공 계약) 표에 열 추가 권장(2023 개정 작성지침) ③ 자동 수집 장치: 앱이 휴대폰 안에 로그인 상태를 저장한다는 점과 웹 쿠키 없음 함께 ④ 안전성 확보 조치에 "접근 권한 관리·접속 기록 보관" 표준 항목 맞춤 ⑤ 제3자 제공 "없음" 명시 문장(지금은 "넘기지 않습니다"로 갈음, 법정 용어 괄호 병기 권함 — 검토 요청 9).
- **중간** 9절 처리 기한: 11-backoffice 결정 "목표 7일·상한 10일"과 맞춰 "10일 안에(보통 7일)"로. 시행령상 열람·삭제 통지 10일과도 맞음.
- **중간** 6절 "만 14세 이상만 만들 수 있습니다": 앱에 나이 확인이 없어 과장. "만 14세 이상만 쓰실 수 있습니다. 가입 때 나이를 따로 확인하지 않으니…"로. Play 18+ 대상과는 법적 모순 아님(스토어 타깃 vs 이용 하한) — 검토 요청 8은 낮음.
- **중간** 1절 "계정을 지우면 바로 지워집니다": 백업 7일·접속 기록·Crashlytics 90일이 남음 → "바로 지워지고, 백업에서는 7일 안에 사라집니다".
- **낮음** 10절 "서버에 들어갈 수 있는 사람은 운영자 1명"은 5절 Supabase 지원 인력 접근과 어긋남 → "운영자 1명(Supabase 지원 담당자는 요청·사고 때만)".
- **낮음** 2절 누락 행: 자녀 "번호 만들기(만든 번호·만든·쓴 시각)". 푸시 토큰 "로그아웃 때 지움"은 서버·앱에 구현 없음(계정 지우기 때만 확인) → 불확실 표시.
- **낮음** 검토 요청 2(카카오·구글 분류): 실무상 흔한 분류로 무리 없음. 검토 요청 6: HangulStep은 현재 입력칸이 없어 "보내지 않음"이 사실상 참이나 P6 구현 뒤 재대조 필요. events(0022)·Firebase SDK는 아직 없음(package.json) → 표시 유지가 맞음.
- **낮음(라이터)** 어르신이 모를 말: "익명 로그인", "토큰", "Firebase 설치 번호", "행 단위 접근 제어", "AWS ap-northeast-2" → 괄호 풀이 또는 표 밖 설명으로. 주어는 대체로 "운영자"로 일관, 합니다체 일관됨.

## B. delete-account-v2.html
- **높음** 2절 부모님 항목 "자녀가 지우면 됩니다(위 1번)": **다른 자녀가 남아 있으면 부모님 기록은 안 지워짐**(0017, 이 페이지 1절과도 모순). 또 자녀는 성인 부모의 법정대리인이 아니므로 부모님 본인 요청이 1순위여야 함 → 순서: ① 부모님 앱 설정 → 모두 지우기 ② 메일(기종·연결 날짜) ③ 자녀 대신 요청은 부모님 뜻을 확인한 경우. DECISIONS "앱 안 코드 발급"은 백오피스 v2라 출시 시점엔 없음 → 그때까지 메일 확인 방법을 운영자가 정해 적을 것.
- **높음** 3절 마지막 불확실 줄: A의 결정(부모님 익명 계정도 삭제)으로 교체, 서버 큐 구현이 게시 조건.
- **중간** 처리 기한 "제안 10일" → DECISIONS "7일 내 수동 처리"·11 "상한 10일"과 통일.
- **중간** 1절 확인 단계 불확실 표시는 해소: 앱은 설정 "모두 지우기" → 대화상자 "모두 지울까요?" → "모두 지우기" 1번(DeleteAccountScreen 주석·copy.ko.json). 단 자녀 메뉴 이름은 앱 문구가 **"내 계정 지우기"**(delete_link·keep_title) → 2단계 라벨 맞출 것.
- **낮음** 검토 요청 7: realApi.deleteMyAccount가 카카오 unlink를 실제 호출(실패 무시) → "함께 시도"는 과장 아님. Play 3요건(앱 밖 요청·앱/개발자명·지우는/남는 데이터와 기간)은 TODO만 채우면 충족.
- **낮음** 카카오 가입자 확인: 닉네임은 선택 동의라 없을 수 있음 → "카카오 회원번호는 앱 설정에 표시" 같은 수단 없으면 "앱 안 지우기 우선" 문구를 더 강하게.
