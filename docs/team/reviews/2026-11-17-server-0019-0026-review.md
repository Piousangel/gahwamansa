## 중간
**M1. 심사 재사용 번호에 상한·끄기·정리 없음** — `20261116000025_review_access.sql:139`, `:174-175`
- 재사용 번호는 `expires_at = infinity`, 사용 처리 안 함, 연결 수 제한 없음. 정책 리뷰(policy-docs-review 32행)가 요구한 "연결 수 상한·심사 종료 후 정리·번호 비활성 기본값"이 빠졌다.
- 재현: 익명 로그인 N번 → 같은 번호 redeem N번 → 심사 가족에 어르신 프로필 N개(review_access 테스트 '기기마다 따로 생긴다'가 무제한을 그대로 확인함).
- 만료가 없어 6자리 추측 창도 무기한: 전역 한도 300회/10분 = 하루 4.3만 회 → 평균 약 12일이면 맞힌다. 그동안 일반 사용자는 `busy`를 받는다.
- 제안: `invite_codes.max_uses`(예 5)와 `disabled_at`(기본 비활성, 심사 제출 때만 켬) 추가, redeem에서 `count(profiles where family_id=심사가족 and role='parent') >= max_uses`면 `invalid`. 심사 종료 정리 함수(서비스 역할: 심사 가족 어르신 프로필·익명 계정 삭제, 번호 비활성). 테스트: 상한 초과 거부, 비활성 번호 거부.

**M2. 게시 콘텐츠 수정 금지가 삭제+재삽입으로 우회됨** — `20261116000024_content_cursor.sql:59-62`
- 트리거는 `before update`만. `content_photos`는 참조 FK가 없고, `content_questions`도 0023이 31일 지난 답을 지우면 FK가 풀린다(로컬: 답 없는 문항 14개 전부 삭제 가능).
- 재현(롤백 트랜잭션): `delete from content_photos where day_index=1; insert … (1, …, '바뀐 캡션', …)` → 성공. 같은 day_index에 다른 뜻의 문항을 넣으면 커서·지난 답 화면의 의미가 바뀐다.
- 제안: 두 테이블에 `before delete` 트리거로 삭제 금지(고칠 땐 retired_at만), 또는 `retired_at is not null`이고 day_index가 어떤 커서보다 작을 때만 허용. 테스트 1건 추가.

**M3. 로컬 마이그레이션 이력이 파일과 어긋나 "깨끗한 순차 적용"이 검증되지 않음**

- 346건 통과는 "지금 DB 상태"에 대한 결과이지 0001→0027 재생 결과가 아니다.
- 제안: 별도 스택(다른 project_id/포트)이나 CI에서 `supabase db reset` 후 `test db` 1회. 원격 staging에 옛 번호 0026~0028이 이미 푸시되지 않았는지 `migration list --linked`로 확인 후 push.

## 낮음
- **L1 events 보관·남용** `20261116000022_events.sql:25-57`: 파기 대상(0023)에 없고 보관 기간 결정(DECISIONS 275행)에도 없음. 프로필 없는 익명 기기 이벤트(family_id null)는 cascade로도 영원히 남음. 호출 한도 없음(익명 가입 30회/시간/IP × 무제한 호출). 0026으로 지워진 계정의 남은 JWT도 `auth.uid()`가 있어 기록됨. 제안: 보관 기간 결정 후 purge에 추가, uid당 분당 상한.
- **L2 자유 텍스트 잔여 경로**: 문자열 토큰 `^[a-z0-9][a-z0-9_.-]{0,31}$`은 로마자 문장("mom-is-sick")은 막지 못함. 키별 허용값 목록(result·reason·channel 등 enum)으로 좁히길 권장.
- **L3 `choice_pair_prompt`** `20261116000021_answer_history.sql:12-14`: 숫자·영문 끝은 무조건 '와' → `('3','4')` = "3와 4 중"(맞는 말: 3과). `between '가' and '힣'`은 정렬 규칙(en_US.UTF-8) 의존 → `ascii(...) between 44032 and 55203`로. 실행 권한이 public 기본 그대로(무해, 일관성만).
- **L4 동의 이력 cascade** `20261116000019:19-20`: 마지막 자녀가 가족을 지우면 어르신의 동의 증빙도 같이 사라짐. "모두 지워져요"와는 맞지만 증빙 목적과 충돌 → 정책 결정으로 DECISIONS에 한 줄 남길 것.
- **L5 시드 `on conflict do nothing`**: 재적용은 안전하나 문구 수정이 조용히 무시됨. 시드 머리말에 "고칠 땐 새 day_index + retired_at" 절차 링크.
