### 만료와 재발급 흐름
- 판정은 이전과 같다: `expired = state && !code && hadExpired`. 만료 전에는 새 번호 만들기가 없다(Dock은 보내기·복사).
- '새 번호 만들기'를 누르면 다음 순서로 진행된다:
  1. `issueInviteCode`
  2. `invite_code_issued{purpose:'parent_code'}`
  3. `hadExpired`면 `renewed` + 토스트 '새 번호를 만들었어요'
  4. `check(true)`로 새 번호 반영
  5. 카드에 '앞 번호는 쓸 수 없어요'(old_invalid) 줄
- 실패하면 오류 묶음(live region) + 다시 확인 버튼이 나온다. 누르는 중에는 `busy`로 다시 누르기를 막는다(Dock loading).
- 받은 적 없는 상태(`!code && !hadExpired`)는 '번호 만들기'(make_code)다. 이전과 같다.

### 읽기 이름과 보이는 글(R-14)
- Dock 주·보조, '설정', '알림 켜기', 오류 버튼은 모두 보이는 글 그대로 읽는다.
- 번호는 카드 안 한 덩어리 `accessible`로 읽는다. 라벨은 `show_a11y`(숫자를 한 자씩) + 기한이고, 보이는 내용(번호·기한)과 같다. '연결 번호' 라벨은 따로 읽힌다.
- 단계 번호 원은 숨기고 단계 글만 읽는다. 순서가 바뀌지 않는다.
- BackLink 없음은 R-14 예외(가입 끝)로 주석에 근거가 있다.

### 측정 이벤트
- `invite_code_issued{purpose:'parent_code'}`, `invite_share_tapped{channel:'share_sheet'|'copy'}`는 v3와 같은 자리·같은 값이다.
- 다른 track 호출은 v3에도 없었다(main 파일과 대조).

### dockReleaseOnKeyboard를 켜지 않은 화면
- Dock 풀림: `setUndock(true)`는 `dockReleaseOnKeyboard && !isSocialGroup`에서만 일어난다. `releasedFor`에도 그때만 들어간다.
  - 끈 화면에서는 조건 변화 effect가 늘 `known=false`라서 `spill 0`, `undock false`로 되돌린다. 예전 effect와 같다.
  - 끈 화면이 넘치면 예전처럼 Dock 안 스크롤(40% 상한)에 남는다. P6 '다 썼어요'를 Dock에 두려는 의도와 맞다(테스트 추가됨).
  - DsScreen 사용처는 지금 `ChildLogin`(C0-a 소셜·C0-b 이메일)과 `ChildWaitScreen`뿐이다. 플래그는 C0-b에만 켰다. C0-a는 소셜 묶음이라 원래 풀리지 않았다. 그래서 지금 동작이 바뀐 화면은 없다.
- 넘침 단계(spillRef, PR #82 L4)는 모든 DsScreen에 적용되어 예전과 정확히 같지는 않다(L4 참고).

### '한 번 풀린 조건 기억'이 굳어 버리는가: 아니다
- 키가 `width|height|fontScale|kb|dockKey`다. 화면 회전·창 크기·글자 배율·자판 높이·Dock 문구(로딩 표시 포함) 중 하나만 바뀌어도 새 키가 된다. 새 키면 다시 Dock에 넣고 잰다.
- 같은 조건으로 돌아오면 그때 바로 푼다. 이는 같은 조건에서 이미 넘친다고 잰 결과라 맞다.
- 자판이 닫힌 상태(kb 0)는 기억하지 않는다. 그래서 닫히면 늘 Dock으로 돌아온다.
- 기억은 화면 마운트 동안만 유지된다(ref). 화면을 다시 열면 비어 있다.
- 남는 틈(L3): 같은 키인데 Dock 실제 높이를 바꾸는 요인이 키에 없으면, 기억된 풀림이 그대로 쓰인다. 예: 아이콘·kind만 바뀜, 보조·note의 내용 말고 존재만 같음. 지금 C0-b에는 해당 요인이 없다.

## 중간

### M1. 번호가 화면을 보는 중에 만료되면 화면 읽기에 알리지 않는다(v3에는 있었음)
- 위치: `ChildWaitScreen.tsx:136`(`<Card tone="notice" testID="wait-expired">`, live region·announce 없음)
- v3는 만료 띠에 `accessibilityLiveRegion="polite"`가 있었다. v4 ds Card에는 없고 announce도 없다.
- 대기 화면은 상태를 다시 확인하므로(앞으로 돌아올 때 `check`), 보고 있는 동안 번호 카드가 사라지고 만료 띠·'새 번호 만들기'로 바뀔 수 있다.
- TalkBack 사용자는 아무 알림 없이 포커스하던 카드가 없어진다. R11('나타날 때 한 번 읽음')과도 어긋난다.
- 고칠 방향: 만료 띠를 감싸는 View에 `accessibilityLiveRegion="polite"`를 두거나, 만료로 바뀔 때 `announce(expired_title)`를 부른다(ds Banner처럼 한 번).
- 테스트: 코드 있음 → 만료 상태로 바뀔 때 `announceForAccessibility`가 불리는지를 넣는다.

## 낮음
- L1. 공유 창에서 돌아왔을 때의 안내(`wait-after-share`, `:161`)도 v3에는 live region이 있었는데 빠졌다. 주 버튼이 '다시 보내기'로 바뀌는 것과 같이 읽어 주면 좋다.

- L3. 풀림 기억 키에 Dock 높이를 바꾸는 모든 요인이 들어 있지는 않다(위 "굳어 버리는가" 참고). 지금 쓰는 곳은 문제없다. 다른 입력 화면이 플래그를 켤 때 dockKey에 icon·kind를 더할 것.
- L4. `spillRef`(PR #82 L4)는 렌더 전에 Dock onLayout이 두 번 오면, 두 번째(아직 옛 배치로 잰 값)를 새 단계 기준으로 판단해 한 단계 더 넘긴다.
  - 테스트 'onLayout 두 번 → note·보조 모두 본문'이 바로 이 동작을 기대값으로 고정한다.
  - 두 번째 측정은 아직 단계 1을 그리기 전의 높이라, 단계 1에서 들어갈 수도 있었던 보조가 본문으로 갈 수 있다(과하게 넘김). 결과는 덜 나빠지는 쪽이고 드물다.
  - 확실히 하려면 Dock이 `onContentHeight(h, spillRendered)`로 그린 단계를 함께 알리고, 그 단계가 지금 단계와 같을 때만 다음 단계를 고른다(P1 M9와 같은 원칙).
- L5. 복사 띠(`:145`)는 2초 안에 다시 누르면 타이머는 다시 세지만, 문구가 같아 ds Banner가 다시 읽지 않는다. 연달아 누른 것을 알리려면 `key={copied}`로 다시 마운트할 것.
- L6. 상태를 받기 전의 Dock(`disabled`, onPress 없음)에는 `disabledReason`이 없다. 잠깐이지만, 화면 읽기에서는 이유 없는 비활성 버튼으로 읽힌다. `loading` 표시가 더 맞을 수 있다.
