## 중간

**M1. 자녀의 약관·방침 동의는 기록되지 않는다**
- 위치: `app/src/features/link/useConnectFlow.ts:18-26`(유일한 호출부). 자녀 로그인 흐름에는 호출이 없다(`git grep recordTermsAgreement`).
- 근거: dev-server-notes §2 record_terms_agreement 첫 줄 "자녀: 로그인 화면의 약관 줄에 동의할 때(가족 만들기 전이어도 됨). 어르신: 연결 화면…". 법률 Q2 증빙은 두 역할 모두 대상이다.
- 영향: 자녀 계정은 `terms_agreements`가 비어 `my_terms_status.needs_reagree`가 늘 true다. 출시 뒤 재동의 게이트를 켜면 모든 자녀가 걸린다. 동의 증빙도 없다.
- 고칠 방향: 자녀 로그인(소셜·이메일) 성공 직후, 약관 줄이 보인 그 로그인에 한해 같은 `recordTerms`를 부른다. 공용 함수는 `shared/`나 `push/runtime`처럼 기능 밖으로 올린다(기능 간 import 금지). 이 PR 범위가 어르신뿐이라면 PR 설명과 로드맵에 "자녀 몫 남음"을 적는다.

**M2. 연결 전 계정의 삭제 확인(P9)이 'none'을 받아도 틀린 안내를 보인다**
- 위치: `app/src/features/account/DeleteAccountScreen.tsx:36-54`, `DeleteDoneScreen.tsx:16-21`, copy `delete.child.keep_body`.
- 근거: 이번 PR로 `deleteScopePreview`가 'none'을 돌려준다(전에는 no_profile 예외 → `setScope('family')`). 가족 연결 전 자녀(ChildSettings `delete_link`는 연결 여부와 상관없이 보인다)는 'none' → `strong=false` → "내 계정만 지워져요. 부모님의 고른 답과 기록은 남아요"를 본다. 남는 가족 기록이 없으므로 틀린 말이다. dev-server-notes 0049 "앱 할 일: P9가 none을 받으면 '가족 기록은 없고, 로그인 정보와 약관 동의 기록만 지워져요' 같은 안내"(방침 게시 조건 P20)가 아직 없다. 어르신은 `linked`일 때만 삭제 행이 보이므로 해당 없음.
- 영향: 삭제 범위를 안내하는 법률 고지 화면에서 사실과 다른 문구가 나간다. 예외였던 것이 바뀐 것이라 퇴행은 아니지만, 이 PR이 'none'을 화면까지 흘려보내기 시작했다.
- 고칠 방향: `scope === 'none'` 분기와 새 copy 키(`delete.child.none_body`·`done_none`, 라이터 확인)를 둔다. fetchChildSummary 호칭 조회도 'none'이면 하지 않는다. 테스트: `createFakeApi({deleteScope:'none'})` 자녀 P9 문구.

**M3. 통합 테스트 terms.test.ts가 기본 실행에서는 핵심 단언을 하나도 하지 않는다**
- 위치: `app/__integration__/terms.test.ts:14-31`.
- 근거: 공유 로컬 DB를 읽기로 확인해 보니 `public.terms_versions`가 0행, `terms_agreements`가 0행이었다. `test:integration`은 서비스 키를 주지 않으므로 `else` 쪽만 탄다. 이때 확인하는 것은 `unknown_version` 파싱과 `deleteScopePreview()`뿐이다. `{ok:true, recorded}` 모양, 같은 쌍을 다시 기록하지 않음, `my_terms_status` 파싱은 실행되지 않는데도 테스트는 "통과"로 표시된다. 단위 테스트는 가짜 응답으로 검증기만 보므로, 서버의 실제 ok 모양을 확인하는 곳이 없다.
- 고칠 방향: ① `myTermsStatus()`는 게시 여부와 상관없이 부를 수 있다(기록 없음 → needs_reagree true). else 분기에서도 `expect((await parent.myTermsStatus()).needsReagree).toBe(true)`를 단언한다. ② ok 경로는 서비스 키가 없으면 `test.skip`(또는 `console.warn` + 별도 test로 나누어 skip 표시)으로 분명히 건너뛴 것으로 보이게 한다. ③ 서비스 키 경로는 `admin_publish_terms_version`이 되돌릴 수 없는 전역 게시(감사 행)라 공유 DB에서는 쓰지 말고, 일회용 DB(`supabase db reset`을 한 CI)에서만 켠다. 또는 seed에 v1 게시를 넣어 모든 로컬 DB가 같은 상태로 시작하게 한다(출시 전 게시 규칙과도 맞음).

## 낮음

**L1. 동의 기록이 두 번 다 실패하면 영영 남지 않는다** — `useConnectFlow.ts:113-118`. 특히 환경에 버전을 게시하지 않으면 `unknown_version`이 조용히 되풀이된다(dev-server-notes "출시 전 게시" 규칙 위반을 앱이 알리지 않는다). 동의는 누를 때 이미 받았으므로, 실패하면 기기 기억에 'pending'을 두고 다음 실행 때 다시 보내는 것이 맞다. `unknown_version`/`invalid_version`이면 `__DEV__` 경고와 계측(이벤트 이름 추가는 서버 협의)을 권한다.

**L2. `deleteMyAccount`는 계약 검증을 거치지 않는다** — `realApi.ts:97-124` `return {scope: data.scope}`. preview는 `parseDeleteScope`로 검증하게 바뀌었는데 삭제 결과는 그대로라, 모르는 값이 DeleteDone까지 간다. 같은 검증기를 쓰고, 실패하면(이미 삭제됨) 'none'으로 대체한다.

**L3. 동의 기록의 role이 대부분 'none'으로 남는다** — 연결 요청과 동시에 부르고(연결 전), 같은 쌍은 다시 기록하지 않으므로 연결 뒤 재시도도 role을 바꾸지 못한다. role은 참고 값이라 증빙에는 영향이 없지만, 서버 줄이 "어르신 동의 수"를 role로 세면 틀린다. dev-server-notes에 "어르신 동의는 role 'none'(연결 전)으로 남음"을 적거나, 서버가 프로필 연결 때 갱신하도록 서버 줄과 협의한다.

**L4. 통합 테스트가 만든 익명 사용자를 지우지 않는다** — `terms.test.ts`. 실행할 때마다 공유 DB에 auth 사용자(와 ok 경로면 동의 행)가 쌓인다. realApi.test처럼 서비스 키가 있으면 정리하거나, 끝에 `deleteMyAccount()`(0049 'none' 경로를 함께 검증)를 부른다. 후자를 권한다.

**L5. 'none' 계약 주석과 PushHost 바쁜 화면** — 참고 수준. `types.ts`에서 `DeleteScope`가 contract로 옮겨졌는데, `fakeApi deleteScope` 기본값 'parent'는 연결 전 fake 시나리오에서도 'parent'를 준다. fake로 M2를 재현하려면 연결 여부에 따라 'none'을 주는 것이 실제 서버와 맞다.
