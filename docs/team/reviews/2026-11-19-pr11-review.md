## 중간

**M1. 미리보기가 자녀 화면과 같은 RPC 결과가 아니다. 마지막 답이 30일보다 오래되면 자녀와 다른 화면을 보인다**
- 위치: `app/src/features/account/ParentSettings.tsx` `FamilyPreviewScreen`(`api.parentHistory(30)` → `choice_label !== null` 거르기, `answerDate`, `pairShort`).
- 근거:
  - 자녀 C4의 최근 답은 `child_summary.latest`다(0021/0027). `answers`에서 **기간 제한 없이** 가장 최근 1개를 고른다(`order by session_date desc, answered_at desc limit 1`).
  - 미리보기의 최근 답은 `parent_history`의 최근 30일 안에서만 고른다.
  - 그래서 어르신이 한 달 넘게 답하지 않으면, 자녀는 "부모님의 최근 답 / 가을 / 9월 1일"을 보는데 미리보기는 "고른 답이 생기면 여기에 보여요"를 보인다. 미리보기의 목적(자녀에게 실제로 보이는 것)과 반대다.
  - 지난 답 줄도 다르다. 자녀 C5는 서버 `prompt_short`(`choice_pair_prompt`, 숫자 끝 '과' 규칙 포함)를 쓰고, 미리보기는 앱 `pairShort`(한글 받침만)를 쓴다.
  - 날짜 함수 `answerDate`는 `features/home/formatDate.formatAnswerDate`를 복사한 것이다(기능 간 import 금지 때문이라고 주석에 있음).
- 영향: 시안 주석 "자녀 화면과 같은 RPC 결과" 원칙과 어긋난다. 지금은 30일 안이면 결과가 같지만, 서버나 자녀 화면 규칙이 바뀌면 미리보기는 조용히 달라진다. 둘을 함께 확인하는 테스트도 없다.
- 고칠 방향:
  1. 최근 답 카드는 자녀와 같은 기준으로 맞춘다. 어르신용으로 자녀 계약과 같은 모양을 주는 서버 함수(예: `parent_preview()` — `child_summary.latest`·`child_answer_history` 본인 1명분 + 호칭)를 서버 줄에 요청하는 것이 가장 확실하다. 앱만으로 할 때는 30일 안에 답이 없으면 "더 오래된 답"을 따로 받아야 하므로 서버 협의가 필요하다.
  2. `formatAnswerDate`·짧은 질문 규칙은 `lib/`(예: `lib/childFormat`)로 올려 자녀·어르신이 같은 함수를 쓰게 한다. `pairShort`도 서버 `choice_pair_prompt`의 숫자 규칙을 맞추거나 서버 값을 쓴다.
  3. 같은 fake 데이터로 자녀 C4·C5와 미리보기의 표시 문자열이 같은지 확인하는 테스트를 둔다.

**M2. 불러오기에 실패하면 사실이 아닌 미리보기를 보인다**
- 위치: `FamilyPreviewScreen` useEffect — `parentHistory(...).catch(() => setAnswered([]))`, `parentFamilyList().catch(() => setTitle('부모님'))`.
- 근거: 오프라인·서버 오류이면 답 목록이 빈 배열이 되어 "고른 답이 생기면 여기에 보여요"(답이 없다는 뜻)가 나온다. 호칭도 자녀가 정한 값(예: '엄마') 대신 '부모님'으로 나온다. 코드 주석은 "실패하면 불러오는 중 줄을 그대로 둔다"고 하는데, 실제 코드는 그렇게 하지 않는다.
- 영향: 개인정보 노출 범위를 확인하는 화면에서 어르신이 "가족에게는 아무것도 안 보인다"고 잘못 알게 된다.
- 고칠 방향: 실패 상태를 따로 둔다. 어르신 Banner(offline·error, 다음 할 일 하나 = 다시 불러오기)를 쓰고, 기기 틀 안에는 카드를 그리지 않는다. 테스트: `failHistory` 옵션으로 실패 → 빈 상태 문구가 없고 오류 줄 + 다시 시도.

## 낮음

**L1. 미리보기 화면이 `ParentSettings.tsx` 안에 있다** — 이유(레이어 기준선: app/ import를 늘리지 않기)는 맞지만 설정 파일이 400줄을 넘고, `ParentStack`이 `features/account/ParentSettings`에서 화면을 import한다(ParentSettings는 ParentStack 타입을 import → 순환 모양). `features/account/FamilyPreview.tsx`로 나누고 session·BackBar import를 같은 기준선 예외 목록에 한 줄 더하는 쪽을 권한다.

**L2. 여러 어르신 가족의 호칭** — `parent_family_list.title` = `coalesce(본인 profile.parent_title, families.parent_title)`. 자녀 `child_summary.parents[].title`과 같은 식이라 지금은 맞다. 시안 주석("자녀가 여럿이고 호칭이 다르면 처음 연결한 자녀의 호칭")은 호칭이 자녀별이던 때의 규칙으로 보인다. 지금 서버는 어르신 프로필당 하나라 해당하지 않는다. 시안 주석을 정리할 것(디자인 레인).

**L3. 불러오는 중 줄에 live region이 없다** — `preview-loading`. 화면 읽기에서는 제목만 읽힌 뒤 바뀌는 것이 알려지지 않는다. 카드가 그려질 때 `accessibilityLiveRegion="polite"`나 카드에 초점을 옮기는 것을 권한다.

**L4. 정상 경로는 구조만 갖췄고 아직 실행된 곳이 없다** — 공유 DB `terms_versions` 0행(읽기 확인). replay-check는 앱 통합 테스트를 돌리지 않는다. 리드가 공유 DB에 `seed_terms_v1.sql`(멱등, 감사 없음)을 한 번 넣는 것을 허락하거나, replay-check에 terms 통합 테스트를 더하면 정상 경로가 실제로 돈다.
