## 판정

**높음 0 / 중간 2 / 낮음 3 → 합치기 가능(조건).**
- S25 기본 배율에서는 세 증상이 모두 풀린다고 본다. 열림 때 카드 높이가 약 100dp 줄고(칸 64→44, 읽어 주기 64 + 간격 숨김, 여백 14→8), 안내는 말줄임 없이 줄바꿈되며, 뒤로 링크는 64 이상이다.
- 엔터 때문에 낱말 판정이 깨지지는 않는다.
- 다만 이번에 새로 생기는 200% 문제(M1)가 있고, 320×640·200%에서 같은 종류의 잘림이 남을 수 있다(M2). 조건은 둘 중 M1을 고치거나, 합치기 전 에뮬레이터 320×640·200% 캡처로 M1·M2가 문제없음을 확인하는 것이다.

## 중점 확인

| 중점 | 결과 | 근거 |
|---|---|---|
| 여러 줄 입력에서 엔터 → 줄바꿈 → 판정 깨짐 | 깨지지 않음 | `multiline` + `blurOnSubmit` + `returnKeyType="done"`. ## 중간

**M1. 200%에서 안내가 4줄쯤으로 커지고, 자판이 열리면 한 번에 접혀 화면이 크게 점프한다**
- 위치: `KeyboardStep.tsx` TextInput(`placeholder={open ? undefined : k.placeholder}`, `multiline`, `styles.input` minHeight 72·fontSize 34·`maxFontSizeMultiplier={FONT_SCALE_MAX}`=1.5).
- 근거(추정): RN의 placeholder는 입력 글자와 같은 크기(34×1.5 ≈ 51dp)다. 320 폭에서 입력칸 안쪽 폭은 화면 여백 24×2와 칸 여백 18×2를 빼면 약 236dp다. 한 줄에 4~5자라 "여기를 누르면 자판이 나와요"(14자)가 약 4줄이 되고, 입력칸 높이는 약 250dp가 된다. 한 줄 말줄임을 여러 줄로 바꾸면서 생긴 새 상태다. 누르는 순간 placeholder가 빠지면서 입력칸이 약 76dp로 줄고, 카드(칸 64→44·읽어 주기 숨김)와 자판 올라옴이 한꺼번에 일어난다. S25 기본 배율에서도 2줄 → 1줄 점프가 있다.
- 영향: 닫힘 상태 200%에서는 큰 글자 안내가 본문 대부분을 차지해 사진·칸이 스크롤 위로 밀린다. 열 때 화면이 크게 한 번 뛴다. 반복 깜빡임은 아니지만 어르신에게는 "화면이 바뀌었다"로 보일 수 있다.
- 고칠 방향(최소): 안내를 placeholder 대신 입력칸 위 한 줄 글(이미 있는 `input_label` 자리, 22 이하·여러 줄 가능)로 옮긴다. 입력칸은 빈 칸 한 줄로 둔다. v4 2-8(placeholder 금지·hint는 칸 위, 자판이 열려도 보임)과 같은 방향이라 v4에서 다시 고칠 일도 줄어든다. 그대로 두려면 합치기 전에 320×640·200% 닫힘·열림 캡처로 높이를 확인한다.

**M2. 320×640·200%·높은 자판(천지인)에서는 열림 때 카드 윗부분이 다시 잘릴 수 있다(확인되지 않음)**
- 근거(추정): 640에서 상태 표시줄 약 24와 자판(추천 줄 포함) 약 300을 빼면 남는 높이는 약 316이다. 여기서 위(BackBar 64, 150% 이상이라 StepHeader 숨김)와 독(다 썼어요 200% 약 90~100)을 빼면 본문은 약 150~160이다. 본문은 카드(칸 44 + 여백 16 = 60), 간격 약 12, 입력칸(51dp 글자 + 여백 16 ≈ 76)을 합쳐 약 150이고, 본문 여백까지 더하면 경계이거나 조금 넘친다. 넘치면 ScrollView가 입력칸 쪽으로 밀려 같은 증상(카드 윗부분이 위 영역 밑으로 가려짐)이 남는다. 150% 미만에서는 열림 때도 StepHeader가 남으므로, 글자 130~140%에 작은 화면이면 같은 계산이 된다.
- 고칠 방향: 합치기 전 에뮬레이터 320×640·글자 200%·130%에서 열림 캡처를 확인한다(이 리뷰는 기기를 쓰지 못함). 넘치면 최소 수정으로 열림 동안은 배율과 상관없이 StepHeader를 숨긴다(v4 2-5 "자판이 열리면 위 영역을 BackLink 한 줄로 접는다"와 같은 방향, 단계 정보는 TalkBack 라벨로). 테스트는 jest로 높이를 잴 수 없으므로 v4 4절의 Maestro 캡처 회귀(1.3·1.5·2.0 × S25·320×640)에 P6 열림을 넣는다.

## 낮음

**L1. BackBar 변경이 모든 화면에 적용된다** — `BackBar.tsx`를 20개 파일이 쓴다. 글자 22→24, `minWidth 64`, `paddingRight 20`·`paddingVertical 4`가 P6만이 아니라 설정·연결·웹·자녀 화면 등 모든 '‹ 이전'에 들어간다. 방향은 맞다(v4 BackLink 24). 다만 위 영역 높이가 조금 늘어 다른 화면의 위 영역 고정 높이와 200% 계산이 바뀐다. 전체 jest는 통과했다. 실기기 캡처를 다시 볼 때 같이 확인한다.

**L2. 테스트가 고친 값보다 느슨하다** — 뒤로 글자 `fontSize >= 22`(고친 값은 24, 22는 고치기 전 값이라 되돌려도 통과한다). 열림 카드는 `padding 8`·칸 `44`의 정확한 값만 보고, "넘치지 않음"은 볼 수 없다(jest 한계). `>= 24`로 바꾸고, 높이 회귀는 Maestro 캡처에 맡긴다고 테스트 주석에 적는다.

**L3. 여러 줄 입력으로 바뀌면서 자판 입력 형태가 달라진다** — Android는 `TYPE_TEXT_FLAG_MULTI_LINE`이 붙는다. 삼성 키보드·Gboard에서 추천 줄·자동 띄어쓰기·완료 키 모양이 한 줄 칸과 다를 수 있다. 기존 TODO(QA 실기기: 천지인·두벌식·Gboard)에 "multiline에서 완료 키가 보이는지, 추천 낱말이 그대로인지"를 더한다.

## v4와 충돌하거나 v4에서 다시 고칠 점
1. **placeholder 유지** — v4 2-8 placeholder 금지(Field에 prop 없음, lint로 막음). 이 PR은 placeholder를 여러 줄로 살렸으므로 v4 Field(`kind:'word'`, label·hint) 교체 때 다시 고친다. 안내 copy(`course.keyboard.placeholder`)는 hint 키로 옮긴다. 이번에 칸 위로 옮기면(M1 방향) v4 작업이 줄어든다.
2. **접는 대상이 다르다** — v4는 자판이 열리면 **위 영역**(뒤로 + 단계 제목)을 BackLink 한 줄로 접고 카드는 통째로 보이거나 숨긴다. 이 PR은 위 영역은 그대로 두고(150% 미만) **카드를 납작하게** 만든다(칸 44·글자 28·여백 8). v4 step variant에서는 카드 축소 분기(`cardOpen`, `big` 크기 분기)를 지우고 variant 규칙으로 바꾼다.
3. **BackBar 64×64 vs BackLink 64×120** — v4는 화살표 아이콘 28 + 글자 24 + 알약 면 + 누름 64×120, 문자 '‹' 대신 아이콘, `ToCourseHomeLink` 흡수와 배율 숨김 제거다. 이 PR의 `minWidth 64`는 중간값이다. BackLink로 바꿀 때 `BackBar` 스타일은 지운다.
4. **숫자 크기 직접 지정** — 칸 44·글자 28·여백 8·BackBar 24는 v4 lint(`fontSize`·`height` 리터럴, Text20 `size` 금지)에 걸린다. v4 역할 토큰으로 바꾼다.
5. **읽어 주기 숨김** — 열림 동안 읽어 주기를 숨기는 것은 v4가 정하지 않았다. step variant 자판 정책에서 "열림 때 보조 버튼"으로 정할 것(듣고 쓰는 어르신은 열림 상태에서 다시 듣고 싶을 수 있다).
