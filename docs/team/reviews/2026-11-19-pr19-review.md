## 확인한 사실

1. **공급자 고정**: `package.json` 에 `27.1.0` 정확 고정(^·~ 없음). RNFB app 이 `firebase: "13.1.0"` 을 정확 고정으로 끌고 온다. 웹 묶음은 node_modules 에만 있고 Android JS 번들에는 들어가지 않는다(위 소스맵). RNFB 는 `package.json exports`→`dist/module/index.js`, 웹 구현은 `nativeModule.js`/`nativeModuleWeb` 의 플랫폼 분기 뒤에만 있어 Metro android 해석에서 빠진다.
2. **병합 매니페스트(stagingRelease)**: 권한 `INTERNET`·`POST_NOTIFICATIONS`·`WAKE_LOCK`·`ACCESS_NETWORK_STATE`·`c2dm.permission.RECEIVE`·`DYNAMIC_RECEIVER_NOT_EXPORTED`·`BIND_GET_INSTALL_REFERRER_SERVICE`. **AD_ID 0, 위치 0**. (debug 의 `SYSTEM_ALERT_WINDOW`·`ACCESS_LOCAL_NETWORK` 는 RN 개발용, release 에 없음.)
3. **firebase.json → meta-data 키**: RNFB messaging/app `build.gradle` 의 실제 키 이름과 일치(`app_data_collection_default_enabled`, `messaging_auto_init_enabled`, `messaging_android_notification_delivery_metrics_export_enabled`, `messaging_android_notification_delegation_enabled`, `messaging_installation_id_enabled`, `messaging_android_notification_channel_id`). 병합 결과 `firebase_messaging_auto_init_enabled=false`·`firebase_messaging_installation_id_enabled=false`·`delivery_metrics_exported_to_big_query_enabled=false`·`firebase_messaging_notification_delegation_enabled=false`·`app_data_collection_default_enabled=false`·채널 `daily`.
4. **Analytics·Crashlytics 없음**: 구성 요소 등록은 RNFB app·Messaging·Installations·Common·Datatransport 뿐. `firebase-measurement-connector` 는 인터페이스(interop) 라이브러리로 Analytics SDK 가 아니다.
5. **수신기 보호**: `ReactNativeFirebaseMessagingReceiver`·`FirebaseInstanceIdReceiver` exported=true 이지만 `c2dm.permission.SEND`(GMS 만 보유)로 보호, 서비스·provider 는 모두 exported=false.
6. **로그**: `src/push` 에 토큰·설치 ID 를 찍는 로그 없음(`console.warn` 은 권한 결과 사유 한 곳). dev-app-notes 의 토큰 시험 기록도 길이만 남김.
7. **게이트 범위**: `flavorName == production && !debuggable` 만 막는다. stagingDebug·stagingRelease·productionDebug 는 그대로 빌드됨(위 표). `preBuild` 에 붙어 있어 `assemble`·`bundle`·매니페스트 처리 모두 막힌다.
8. **FCM_WIRED=false 경로**: `pickTokenSource('real')` 가 `createFcmTokenSource()` 를 부르지 않아 JS 에서 `@react-native-firebase/messaging` 모듈 본문이 실행되지 않는다(번들에는 포함). jest 는 전역 모의로 `getMessaging` 이 던지게 해 "Firebase 앱 없음" 실제 상황과 같다.
9. **OSS**: 새 항목의 라이선스 표기는 원 패키지 메타데이터와 일치(RNFB·firebase·@firebase/*·@grpc/* Apache-2.0, @protobufjs/* BSD-3-Clause, http-parser-js MIT, datastore·datatransport·firebase-* Apache 2.0, gms·iid-interop·measurement-connector 는 Android SDK License). RNFB 두 패키지에는 NOTICE 파일이 없어 추가 고지 의무 없음. 빌드가 "오픈소스 라이선스 목록(JS): 최신" 으로 재생성 차이 없음 확인.

## 중간

**M1. 데이터 보안 양식(data-safety-form)이 병합 뒤 사실과 어긋난다**
- `docs/team/legal/data-safety-form.md` 15행 "Firebase 설치 ID — 예정(AU-02, **main 앱에 Firebase 없음 — `app/package.json` 사실**)" 은 이 PR 병합으로 거짓이 된다. 같은 문서 80행 점검 항목 2("알림 거부 기기에서 Firebase 설치 ID가 생기는지 → 필수/선택 결정")도 미확인 그대로다.
- 새로 들어온 `datatransport`(Firelog, `TransportRegistrar`·`CctBackendFactory`·`JobInfoSchedulerService`) 는 양식에 없다. 지금은 전달 지표 내보내기가 꺼져 있어 전송 대상이 없지만, 작성자 메모(dev-app-notes)도 "LG-05 확인 필요" 로만 남겨 둠.
- 권장: 15행을 "SDK 포함(이 PR), 수집은 FCM_WIRED·권한 허용 뒤 첫 getToken 부터"로 고치고, datatransport 는 "지표 내보내기 끔 → 수집 없음" 근거(firebase.json 키·병합 매니페스트 값)와 함께 한 줄 추가. 법률 담당 확인.

**M2. "FCM_WIRED=false 면 Firebase 가 안 움직인다"는 정적 근거만 있고, 네이티브 초기화 자체는 일어난다**
- json 이 있는 빌드(staging 전부, production release 는 게이트로 항상)에서는 `FirebaseInitProvider`·`ReactNativeFirebaseAppInitProvider` 가 **앱을 켤 때마다 FirebaseApp 을 초기화**하고 Messaging 구성 요소도 올라온다. FCM_WIRED 는 JS 에서 토큰을 요청하지 않을 뿐이다.
- 토큰·설치 ID 를 미리 만들지 않는 근거는 `firebase_messaging_auto_init_enabled=false`(Firebase 문서상 자동 토큰 생성 차단)뿐이고, 실행 증거가 없다. 작성자의 에뮬레이터 시험은 임시 real 모드에서 **발급되는지**만 봤다(그 기기는 `setAutoInitEnabled(true)` 가 이미 저장돼 이 확인에 다시 못 씀).
- 권장(리드 실기기·에뮬레이터 몫, 이 리뷰는 금지라 못 함): 새로 설치한 staging release(FCM_WIRED=false)에서 알림 거부 상태로 실행 → `firebaseinstallations.googleapis.com`·`fcmregistrations.googleapis.com` 요청 0, 앱 데이터의 `PersistedInstallation.*.json` 없음을 확인하고 M1 의 80행 점검을 같이 닫는다. dev-app-notes 에 "FCM_WIRED 와 무관하게 FirebaseApp 은 초기화된다" 한 줄 추가.

## 낮음

- **L1 JS OSS 목록이 실제 배포보다 넓다**: 웹 `firebase`·`@firebase/*`(44)·grpc·protobufjs·faye-websocket·http-parser-js 는 Android 번들에 없다(소스맵 확인). 과다 고지는 해가 없으나 목록이 "앱에 들어간 것"과 다르다. 생성기가 운영 의존성 전체를 쓰는 방식이면 그대로 두고 문서에 이유만 적어도 됨.
- **L2 게이트가 `android.applicationVariants`(AGP 9 에서 제거 예정 API)** 를 쓴다. 지금은 동작. AGP 올릴 때 `androidComponents.onVariants`+태스크 의존으로 옮길 것. 게이트는 존재만 보며 패키지 일치는 google-services 플러그인이 검사한다(문제 아님).
- **L3 npm install-scripts**: `@firebase/util`·`protobufjs` 의 postinstall 이 npm 승인 정책으로 실행되지 않는다. 둘 다 Android 번들 밖이라 영향 없음 — **승인하지 말 것**.
- **L4 FCM_WIRED 를 켤 때 문서 보강**: `getToken` 이 `setAutoInitEnabled(true)` 를 **영구 저장**한다. 앱 안에서 알림을 끄면(P13·C7 → `set_push_enabled(false)`) 서버 발송은 멈추지만 SDK 의 토큰 자동 갱신은 계속된다. 켜는 조건(C7 '가족 연결' 토글, DECISIONS 11-18)은 dev-app-notes 에 있으나 이 동작과 "끄면 `setAutoInitEnabled(false)`/`deleteToken` 할지" 결정은 없다.
- **L5 iOS**: `ios/Podfile.lock` 이 없어 iOS 쪽은 미설치·미검증(빌드 2, N6 Firebase iOS 앱 등록과 함께). 
- **L6 PR 설명 "createFcmTokenSource 연결"** 은 실제로 코드 변경이 없다(테스트 이름만 바뀜). 오해 없게 설명을 "기존 공급자 그대로, FCM_WIRED=false" 로.
