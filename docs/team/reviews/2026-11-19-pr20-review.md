# PR #20 디자인 리뷰 (v4 시안 묶음 1: C0 3화면·iOS·자판·응원 시트) — 2026-11-19
검토자: 디자인 리뷰어(작성자 아님), high. 기준: tokens-v4.json, RULES-V4.md(R-01~R-18), v4 SUMMARY. 두 시안을 Chrome headless로 직접 렌더해(C0 13보드, C4 3보드) 확인했다. 시안 소스의 색·굵기·aria-label도 grep으로 전수 점검. Dock 높이 수치는 렌더 모습과 산식으로 본 것이고 DOM 실측은 안 했다.

## 판정: 조건부 승인 (H 없음, M 5, L 5)

## M
1. **자판 열림 + 200%에서 입력 카드가 잘림(R-15 위반).** C0-b 320×200% 자판 열림: 이메일 두 줄 중 둘째 줄 `mail.com`이 주 버튼 밑으로 잘림. C0-c 320×200% 자판 열림: 인증번호 칸 6개 하단이 잘리고 안내문·링크는 안 보임. R-15는 "입력 카드는 통째로 보이거나 숨긴다"인데 200%에서 어느 쪽도 아님. PR 본문은 이를 '100%만 보장'이라 했으나 R-15·R-11(fontScale 2.0)은 배율을 제한하지 않는다. 200%에서는 입력 카드를 통째로 보이게 하려면 제목·본문 설명을 접거나(BackLink 한 줄 + Field) 주 버튼을 자판 위가 아닌 본문 끝에 두는 규칙을 시안에 명시해야 한다.
2. **C0-b 320×200% (자판 닫힘)에서 이메일 칸 두 줄이 주 버튼과 붙는다.** 렌더 확인: 입력 칸 아래 간격이 0에 가깝고 그 사이로 약관 문구가 흐릿하게 비친다(페이드 겹침). 규칙상 주 버튼과 링크 사이 24 이상(touch.rule), 간격 8 이상. 본문 맨 아래 여백(최소 16)을 Dock 위에 두거나 페이드를 입력 칸 아래에서 끊을 것. '스크롤로 해결' 서술은 붙어 있다는 사실을 면하지 않는다.
3. **R-04/R-17: 700 역할이 화면당 3개, 500 굵기 사용.** C0-a 100%에서 제목(700), 버튼 글자(700), 약관 링크 `이용약관`·`개인정보 처리방침`(700, typeRoles.link는 400 + 밑줄)이 함께 700이고, 축소 카드 제목(heading 700)이 더해진다. 링크를 400 + 밑줄로 내리면 2개로 정리된다. 소셜 버튼 글자는 font-weight 500인데 R-17은 400/700만 허용. 브랜드 규정 예외라면 R-17에 'SocialButton은 예외'를 문서화해 토큰 테스트가 예외를 알게 할 것.
4. **iOS 360×640 100%에서 Dock이 40%를 넘는 것으로 보인다(R-12 / Q1).** 소셜 3개(56×3 + 간격 24) + 이메일 링크 48 + 패딩·간격 ≈ 290~300dp = 약 46%. 시안에 `max-height:40%` 상한이 없다(Dock 8개 중 상한 선언 0). Android 100%는 약 232dp로 36%라 통과. iOS 200% 보드는 Dock 없이 한 스크롤이라 '40% 상한 확인'이라는 보드 제목이 실제와 다르다. 100%에서도 Apple 때문에 넘치면 R-12 순서(note → 보조를 본문 끝으로)에 따라 이메일 링크를 본문으로 보내거나 iOS는 처음부터 본문 배치로 확정하고 그렇게 명시할 것.
5. **'소셜 2~3개를 주 슬롯 한 덩어리'는 Q1 취지에는 맞으나 타입 제한이 무력화된다.** SUMMARY 4-1 표가 C0 Dock을 "카카오·구글·이메일 링크"로 이미 적어 소셜 묶음 해석은 회의 취지와 같다. 그러나 Q1의 핵심은 슬롯 초과를 타입 에러로 막는 것이다(주 1+보조 0~1+note). 주 슬롯이 ReactNode 한 덩어리가 되면 아무 것이나 들어간다. 조건: `SocialGroup`이라는 전용 컴포넌트(최대 3개, 같은 높이·폭, 높이 합 상한)만 주 슬롯에 허용하고, 이 예외를 RULES-V4에 R-12 단서로 추가. 그렇지 않으면 현 해석은 제안으로만 두고 승인하지 않는다.

## L
1. 위계(오너 지적 단조로움): 부분 개선. 좋아진 점: 본문 차콜 vs 보조(약관·연령) 회색 구분, 갈색은 링크·BackLink에만, BackLink 알약, 키 큰 화면에서만 가치 카드. 아쉬운 점: 100% 360×640 C0-a는 제목 26 / 설명 18 / 약관 16 / 연령 16 / 링크 17이 비슷한 크기로 이어지고 심볼은 작아(약 44) 시선이 머물 곳이 없다. 가장 큰 개선은 카드가 보이는 360×820 보드뿐이고 일반 폰(360×640·411×891 가운데 빈 면)에서는 여전히 중간이 휑하다. 가치 카드를 첫 화면 기본으로 올릴 수 있는지 PM과 확인.
2. allowed 조합: 글자색은 inkTitle·inkBody·inkSub 계열·action(paper·card 위)로 허용 범위 안. 소셜 버튼 내부색(#FEE500·#1F1F1F·#747775·#000)은 브랜드 규정이라 별도. 장식(심볼 일러스트 #6B4A33·#E9D8BC·#D9A15C·#FFFAF3, 자판 모형 #D9D5D0·#BDB8B2)은 allowed 표 밖이지만 일러스트·시안 틀 목적. 심볼 인장 #FFFAF3은 토큰에 없음(paper 계열로 정리하면 좋음).
3. placeholder 없음(Field label '이메일 주소'). BackLink: 어르신이 아닌 자녀 화면이라 56 높이가 맞고 card + line 테두리, 목적지 문구, 17개 aria-label이 보이는 글과 같다. 200%에서 BackLink가 사라지지 않는다. 확대 상한(backLink 1.5)은 렌더에서 200%로 보이지만(글자 36) 시안은 상한을 안 걸고 있다. 1.5 상한이 걸리면 27 정도로 보여야 하는지 확인.
4. C4 응원 시트: 규칙 위반 없음. Choice는 card + line 1.5(3.72), minHeight 56, 한 열, 하트·이모지 없음, 아이콘 action 색(누를 수 있는 것에 쓰는 갈색이라 R-06 합치). 200%에서 첫 선택지 세 줄만 첫 화면, 둘째는 페이드로 반쯤 보임 — PR 설명과 일치. 단 200%에서 시트 제목이 크게 늘어(40) 선택지 자리를 먹으므로, 시트 제목·보조 문장은 확대 상한(heading 1.5·보조는 접기)을 두면 첫 화면에 두 선택지가 보인다. 닫기 48×48은 자녀 min 48에 맞음.
5. 보드 이름: 200% iOS 보드 제목 정정(위 M4), 시안 주석의 '400/700 두 단계' 문장과 실제 500 사용 불일치.
