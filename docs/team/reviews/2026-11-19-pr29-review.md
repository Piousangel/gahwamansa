## 높음

**H1. `style?: LayoutOnlyStyle` 타입이 흔한 방식으로 우회된다. 런타임에서도 그대로 덮어써진다**
- 위치: `ui/ds/audience.tsx:18-22`, `Text.tsx:42`(`style={[r.style, style]}`), `Button.tsx:42`
- 근거: 아래 코드를 넣은 임시 파일이 `npx tsc --noEmit` 0으로 통과했다.
  ```tsx
  const styles = StyleSheet.create({x: {marginTop: 8, fontSize: 40, color: '#f00'}, y: {marginTop: 8, height: 30}});
  const s: TextStyle = {fontSize: 40, margin: 2};
  <Text role="body" style={styles.x}>…</Text>   // fontSize·color 우회
  <Text role="body" style={s}>…</Text>
  <Button label="x" onPress={f} style={styles.y} />  // height 우회(바깥 View)
  ```
  - 초과 속성 검사는 객체 리터럴에만 걸린다. `StyleSheet.create` 결과나 `TextStyle` 변수는 `margin*` 같은 겹치는 키가 하나만 있어도 대입된다.
  - `dsTypes.test`는 리터럴만 검사해서 이 구멍을 보지 못한다.
  - 런타임 배열에서 `style`이 마지막이라 역할 값을 이긴다.
  - #31 lint는 숫자·hex 리터럴만 잡는다. `color: color.ink`·`fontSize: fontSize.title`(v3 토큰)은 lint로도 잡히지 않는다.
- 영향: SUMMARY 3절이 "lint 우회 차단(r2 RN 소수 의견 채택)"을 위해 둔 타입 장치가 RN에서 가장 흔한 `StyleSheet.create` 패턴에서 뚫린다. 화면 이행 때 기존 `styles.title`을 그대로 넘기는 실수가 그대로 통과한다.
- 고칠 방향:
  - ① 런타임: Text·Button에서 `LAYOUT_KEYS`만 골라 쓴다. 예: `pickLayout(style)`, `__DEV__`에서는 버린 키를 경고한다.
  - ② 타입: `style?: LayoutOnlyStyle & {[K in Exclude<keyof TextStyle, keyof LayoutOnlyStyle>]?: never}`. 이렇게 하면 StyleSheet 결과와 TextStyle 변수도 에러가 난다.
  - ③ `dsTypes.test`에 StyleSheet·변수 사례 2줄을 추가한다.

## 중간

**M1. Text의 공개 `tone`에 `onAction`·`action`·`disabled`·`info`가 열려 있다 → R-01·R-06·R-08을 타입이 막지 못한다**
- 위치: `ui/ds/roles.ts:13`(`Tone`), `Text.tsx:10`, `index.ts:15`(`Tone` export)
- 근거: 아래 코드가 tsc를 통과한다(probe).
  - `<Text role="body" tone="onAction">`: 흰 글자가 종이 위에 놓인다. 허용 목록에서 onAction은 action 면 위만 허용된다.
  - `<Text role="body" tone="action">`: 누를 수 없는 갈색 글자다. R-06 "action 글자색은 누르는 것에만" 위반.
  - `tone="info"`: 면·아이콘 없이 쓰는 단독 글자색이다. R-08 위반.
- 고칠 방향: 화면용 `TextTone = 'default' | 'muted' | 'accent' | 'done' | 'danger'`과 컴포넌트 내부용 `InnerTone`을 나눈다. info는 Banner 안에서만 쓴다. `dsTypes.test`에 `@ts-expect-error tone onAction/action`을 추가한다.

**M2. Banner 행동 링크(action 글자)가 info·offline 면 위에서 어르신 7:1에 못 미친다. 테스트는 이 짝을 검사하지 않는다**
- 위치: `ui/ds/Banner.tsx:40`(`<Button kind="text">` → link 역할, tone action), `BANNER_LOOK`(info=infoSoft, offline=paperSoft) / `dsComponents.test.tsx:214-218`
- 근거: 같은 WCAG 공식으로 다시 계산했다.
  - action on infoSoft **6.63**, action on paperSoft **6.47**. 둘 다 어르신 7에 못 미친다.
  - 원본 `allowed.elderText.action = ["paper","card"]`이다.
  - 테스트는 `look.text`(inkBody)·icon·border만 보고 행동 링크 짝은 보지 않는다. 그런데 테스트 자체가 `<Banner tone="offline" action=…>`를 렌더한다.
  - 눌림 상태도 같은 문제가 있다. secondary·text·BackLink의 pressed 면은 actionSoft이고, 그 위 action 글자는 6.03이다(L6).
- 영향: 오프라인 띠의 '다시 하기'는 어르신이 실제로 누르는 행동인데, 규칙 R-01 밖의 짝으로 나간다.
- 고칠 방향(다음 중 하나):
  - Banner 행동은 띠 안에 흰 card 알약(테두리 line)으로 둔다. action on card는 7.80이다.
  - 또는 링크 tone을 inkTitle + 밑줄 + 화살표 아이콘으로 한다(R-06 아이콘 동반). inkTitle은 모든 옅은 면에서 허용된다.

  테스트에는 "Banner 행동의 글자 tone × look.surface가 어르신 허용 목록 안"을 더한다. 더 일반적으로는 Card·Banner가 `SurfaceContext`로 면 이름을 내려 주고, Text·Button이 dev에서 허용 목록을 확인하게 하면 #21 L4 구멍이 함께 닫힌다.

**M3. 자판이 열려도 Dock은 창 전체 높이의 40%를 그대로 쓴다 → R-15(320·200% 자판 열림에서 입력 카드가 잘리지 않음)를 화면이 지킬 방법이 없다**
- 위치: `ui/ds/Screen.tsx:63-99`(자판 정책은 header 접기만), `ui/Screen.tsx:172`(`maxHeight = height × ratio`, 자판과 무관)
- 근거: R-15와 RULES 11-19 정정은 "방법은 위 영역 접기, **Dock의 보조·주 버튼을 본문으로 보내기**"라고 정했다. DsScreen은 header만 접는다.
  - 320×640·200%를 추정하면 자판(약 280)을 빼고 남는 높이는 약 360이다.
  - 위 영역은 BackLink 64~80 + topSafe 52, 즉 약 130이다.
  - Dock(주 1 + 패딩)은 약 110이다.
  - 본문은 약 120만 남는다. Field 하나는 label 60 + hint 60~120 + 입력 약 90이라 들어가지 않는다.
  - Dock이 화면 밖으로 보낼 슬롯을 정하는 것은 variant의 몫이다(SUMMARY 2-6 "variant가 정하는 것: … 자판 정책"). 화면 파일은 Dock을 옮길 수 없다.
- 고칠 방향: form·step의 `collapsed`일 때 spill을 2로 올리고(보조·note를 본문으로), 필요하면 주 행동도 본문 끝으로 보낸다(`DockSpill`에 primary 포함). 또는 Dock 상한을 `(height - keyboardHeight) × ratio`로 계산한다. 정책을 정하기 어렵다면 최소한 RULES-V4 열린 항목과 이 컴포넌트 주석에 "자판 열림 Dock 정책 미구현"을 적고, Maestro 자판 열림 assertVisible로 확인한다.

**M4. intro variant(0.6)가 SocialGroup Dock에도 적용된다. R-12 단서 "그룹이 들어가도 Dock ≤ 40%"와 어긋난다**
- 위치: `ui/ds/Screen.tsx:15-21`(`INTRO_DOCK_RATIO = 0.6`, variant만 보고 정함)
- 근거: C0 고르기 구성(카카오·구글 + 이메일 링크, 실제 copy)을 `planDock`으로 추정했다.
  - 320×640·200%에서 Dock은 **372dp(58%)**이다.
  - 0.6 상한 384 안이라 이메일 링크도 Dock에 남는다. 원래 B1 버그 구성(350~400dp, 하단 과적)과 같은 모양이 된다.
  - 0.4를 쓰면 이메일 링크가 본문으로 가서 240dp로 들어간다.
  - #31의 예산 테스트도 C0를 intro 0.6으로 넣어서 이를 통과시킨다(#31 M1).
- 고칠 방향: Dock이 SocialGroup이면 variant와 관계없이 `ds.dock.maxHeightRatio`(0.4)를 쓴다. 또는 C0를 form/step으로 둔다. 디자인 판단이 필요하면 RULES R-12와 SUMMARY 2-6(intro 40% 예외) 중 어느 쪽이 이기는지 디자인 레인에 확인한다.

## 낮음

**L1. spill이 창 크기·글자 배율이 바뀔 때만 0으로 돌아간다** — `ui/ds/Screen.tsx:67`. `dock` 내용이 바뀌어도(loading 문구 → 원래 문구, disabledReason이 사라짐) 이미 본문으로 보낸 note·보조가 돌아오지 않는다. 의존성에 `dock` 슬롯 문구(예: `dock?.primary` label·disabledReason, secondary·note 존재)를 넣거나, Dock 높이가 `cap - 여유`보다 충분히 작아지면 한 단계 되돌리는 hysteresis를 둔다.

**L2. '더 있음' 띠가 끝에서 사라질 때 본문이 24dp 튄다** — `ui/Screen.tsx:151`. 띠가 sibling이라 사라지면 ScrollView가 24 커지고, 끝 위치에서 offset이 다시 잡힌다. 실기기에서 거슬리면 띠 자리를 항상 확보하고 화살표만 숨긴다(불투명도 0). 이 경우 R-19 "넘치지 않으면 띠도 없다"와 충돌하는지 디자인에 확인한다.

**L3. Dock 넘침 판단의 padding이 추정과 다르다** — 런타임은 `DOCK_PAD_TOP 6 + max(28, 16+insets.bottom)`(`Screen.tsx:74`)이고, `estimateDock`은 `padding.top 12 + bottomMin 28`(`dockLayout.ts:86`)이다. 제스처 내비(insets 약 24~48)에서는 추정이 최대 약 30dp 작다. 상수 하나로 묶고, 예산 추정에 insets 48 사례를 하나 더한다.

**L4. SocialGroup 타입이 순서·중복을 막지 않는다** — `Dock.tsx:27`. `[kakao, kakao]`가 tsc를 통과하고(probe), `key={s.provider}`가 중복된다. R-12 순서(카카오 → 구글 → Apple)도 타입 밖이다. `readonly [Kakao, Google?]`처럼 자리별 provider 타입으로 고정할 수 있다.

**L5. 주석과 값이 다르다** — `Dock.tsx:48` "글자 확대 1.3(브랜드 예외)"이지만 실제는 자녀 button 상한 1.5다(`SocialButton.tsx:18`). `Text.tsx:20` "위반 수는 dsBaseline 테스트가 센다"도 #31 lint에 `ellipsisException` 규칙이 없어 사실이 아니다(#31 M2).

**L6. 눌림 면 actionSoft 위 action 글자 6.03** — secondary·text Button, BackLink의 pressed. 순간 상태지만 R-01 허용 목록 밖이다. pressed 면을 paperSoft(6.47)로 바꿔도 어르신 7에 못 미친다. 테두리를 굵게 하는 것으로 눌림을 표시하고 면은 card로 유지하는 방안을 디자인에 확인한다.

**L7. 비활성 버튼 글자 disabledInk on disabledBg 5.29** — 허용 목록에 disabledInk가 아예 없다. WCAG는 비활성 컨트롤을 예외로 두지만, RULES R-01은 "allowed 표에 있는 것만"이다. tokens-v4 colorRules가 '제안, 어르신 확인 대상'이라 적었으니 열린 항목으로 남긴다.

**L8. SocialButton 글자에 `keepAllChildren`이 없다** — `SocialButton.tsx:47`. 다른 ds 글자는 모두 한국어 어절 줄바꿈(WJ)을 쓴다. 200%에서 '카카오 로그인'이 글자 단위로 끊길 수 있다. 비활성 `opacity 0.6`도 브랜드 레이블 대비를 낮춘다.

**L9. Field 오류가 나타날 때 읽어 주지 않는다** — `Field.tsx:69-73`. 오류는 hint에 붙어 다음 포커스 때만 읽힌다. Banner·StateView처럼 오류 문구가 바뀌면 `announce` 하거나 `accessibilityLiveRegion="polite"`를 둔다.

## 좋았던 점
- 컴포넌트와 테스트가 모두 기대값을 `tokensV4`에서 읽는다. 원본 값이 바뀌어도 코드를 고칠 일이 없다.
- Dock 넘침이 한 방향으로만 움직이는 상태 기계라 onLayout 재렌더 루프가 생기지 않는다. 주 행동은 항상 Dock에 남긴다.
- `moreBand`를 선택 prop으로 둬서 기존 화면은 바이트 단위로 같은 경로를 탄다.
- `ellipsisException`에 이유 enum을 강제해서, 예외 3종이 코드에 이름으로 남는다.
