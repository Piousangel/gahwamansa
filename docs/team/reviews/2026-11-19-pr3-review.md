## 중간

**M1. 기본 실행에서는 여전히 정상 경로를 확인하지 않는다(PR #1 M3가 절반만 풀림)**
- 위치: `app/__integration__/terms.test.ts:22-47`.
- 근거: `npm run test:integration`은 서비스 키를 주지 않는다(dev-app-notes: 선택 환경변수). 공유 DB는 reset 금지라 seed가 들어가지 않았다(직전 PR #1 리뷰에서 `terms_versions` 0행 확인). 그래서 두 번째 test는 `skipped`이고, `{ok:true, recorded}` 실제 모양과 같은 쌍을 다시 기록하지 않는 동작을 앱 계약으로 확인하는 곳이 없다. skip으로 표시되는 것은 나아진 점이지만, 실제로 확인하는 사람이 없는 상태는 그대로다.
- 고칠 방향(하나 이상):
  1. 첫 test에서 `r.ok`이면 그 자리에서 정상 경로를 단언한다(`recorded: true` → 다시 부르면 `false` → needs_reagree false). 게시 여부는 서비스 키 없이 이 결과로 알 수 있으므로 두 번째 test의 키 조건이 필요 없어진다.
  2. 공유 DB에 v1을 넣는 것(reset 없이 `psql -f supabase/seed_terms_v1.sql`, 멱등·감사 없음)을 리드가 한 번 허락하면 기본 실행에서도 정상 경로가 돈다. 출시 전 "버전 게시" 규칙과도 같은 상태다.
  3. 또는 `replay-check.sh`가 임시 스택의 서비스 키로 `terms.test.ts`도 돌리게 한다(seed가 확실히 들어간 DB).

## 낮음

**L1. seed를 원격에 쓰지 않는다는 규칙이 문서·도구에 없다** — seed 파일 머리 주석에만 있다. 나중에 누군가 `db push --include-seed`를 쓰거나 원격 SQL 편집기에 `supabase/*.sql`을 붙여 넣으면, 감사 없이 약관이 게시된다(production 증빙 공백). RELEASE.md `db push` 절차에 "`--include-seed` 금지(시드는 로컬 전용)" 한 줄을 넣거나, 예정된 `scripts/db-push.sh`가 그 플래그를 거부하게 한다.

**L2. 다시 그리기 횟수를 정확히 같은지로 비교한다** — `p6Keystroke.test.tsx:56` `expect(commits).toBe(N)`. 회귀(글자당 두 번 이상)만 잡으면 되므로 `toBeLessThanOrEqual(N)`이 맞다. React가 묶어 그리기를 바꾸거나 입력과 상관없는 일회성 다시 그리기(예: 20초 `SKIP_STRONG_MS` 타이머, 실제 시간)가 끼면 성능과 무관하게 깨진다. 지금은 테스트 제한 시간이 KeyboardStep이 뜬 뒤 20초보다 먼저 끝나서 걸리지 않는다. 진입 뒤 `setTimeout(500)` 실제 대기도 가짜 시계로 바꾸면 부하에 덜 흔들린다.

**L3. 가드 범위의 빈틈** — 소리 엔진(`audio/engines.loadSound`)과 진동(Vibration)은 감시 목록에 없다. speech는 `.mock`이 있는 함수만 걸러서 보므로, jest 대역이 바뀌어 `.mock`이 없어지면 조용히 감시 0개가 된다. `expect(watched.length).toBeGreaterThan(apiSpies.length + 5)` 같은 하한선을 두면 가드가 비는 것을 막는다.
