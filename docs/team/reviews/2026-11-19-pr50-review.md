## fail-closed
- 스크립트 비정상 종료·크래시(스택)·exit≠0 은 모두 GradleException 으로 변환(`runAppEnv`), 경고만 있으면 logger.warn 후 계속. 설정 단계 `load-json`, preBuild `check`, 번들 doFirst `write`, 번들 doLast `verify-bundle` 어느 곳이든 실패하면 빌드 중단. 파싱 실패(JSON)도 설정 단계 예외.
- 번들 doLast 검사는 이전과 같은 위치, `cleanGeneratedAppEnv` finalizedBy 유지.

## 지적
- **M1 node 없는 환경이 설정 단계에서 막힘.** 이전엔 env 규칙이 순수 Groovy 라 node 없이도 `help`·IDE 동기화가 되었는데, 이제 `:app` 평가 때 `load-json` 이 `node` 를 실행해 PATH 에 없으면(macOS Dock 에서 연 Android Studio 는 nvm·셸 PATH 가 없음, node 없는 CI 잡) 동기화·`./gradlew tasks`·lint 같은 무관 작업도 실패. 메시지도 영어 IOException. 권고: `execute()` 를 try/catch 해서 "node 를 찾지 못했어요(PATH). Android Studio 는 터미널에서 열거나 …" 한국어 한 줄로 바꾸고, RELEASE.md·CI 문서에 "빌드 환경에 node 필수(이미 JS 번들 때문에 필요)"를 명시. 동기화에서만 node 를 건너뛰는 것은 fail-closed 를 약화하므로 권하지 않음.
- **M2 iOS Build Phase 예시 보완 필요.** `cd "$SRCROOT/.." && node scripts/appEnv.js write …` 자체의 경로(app/ios 기준)와 configuration 분기는 맞지만 ① Xcode Run Script 는 최소 PATH 라 node 를 못 찾음 — RN 템플릿은 `.xcode.env`(`NODE_BINARY`)를 source 하므로 예시 앞에 `. "$SRCROOT/.xcode.env"` 와 `"$NODE_BINARY"` 사용을 넣어야 함 ② 출시 경로에 `--require-real-env` 가 없음(없어도 예시 값은 release 에서 실패하지만 Android 출시 경로와 같게 맞추는 편이 안전) ③ `verify-bundle` 은 번들 경로(`$CONFIGURATION_BUILD_DIR/$UNLOCALIZED_RESOURCES_FOLDER_PATH/main.jsbundle`)와 Bundle React Native 단계 뒤에 두는 순서를 명시해야 함 ④ Run Script 는 출력 파일 없이 매번 실행되므로 "Based on dependency analysis 끔" 문구. 아직 iOS 프로젝트에 넣지 않았으므로 빌드 2 착수 전에 고치면 됨.
- **L1** `write` 에 `--version-name` 만 주고 `--version-code` 를 빼면 조용히 기본값(package.json·git)으로 대체됨. 둘 중 하나만 오면 실패시키는 편이 안전.
- **L2** 스크립트 크래시(비 EnvError)는 스택 전체가 GradleException 메시지로 올라가 길어짐. 동작엔 영향 없음.
- **L3** iOS 기본 versionCode 가 git 커밋 수라 shallow clone CI 에서는 작은 값 — Android 와 같은 한계(release-versions.txt 확인 단계가 있으므로 허용).
