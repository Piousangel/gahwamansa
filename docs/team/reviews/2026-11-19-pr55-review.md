### 'AI 음성' 표기 판단
- 미리 생성 음성은 **우리가 생성형 AI(Google Chirp 3 HD)로 만들어 앱에 넣어 배포하는 결과물**이다. 사진(AI 그림)·배경 음악(Lyria)과 같은 종류라 같은 고지 묶음에 넣는 것이 맞다. 그러니 파일이 있을 때만 표시하는 것은 맞다.
- 기기 TTS는 사용자 휴대폰의 OS 기능이 실시간으로 읽는 것이다. 우리가 만든 AI 결과물이 아니고, 기계 음성임도 분명하다. 기존 앱 정보에도 기기 TTS 고지는 없었다. 그래서 기기 TTS만 쓸 때 고지하지 않는 것은 일관된다.
- 문구 "읽어 주는 목소리는 AI가 만든 목소리예요"는 파일과 기기 TTS가 섞여 쓰이는 경우(일부 글만 파일)에도 거짓이 되지 않는다. 다만 표기 범위의 법적 판단(AI 기본법 생성물 표시 범위)은 법률 레인 확인 대상으로 남긴다.

## 낮음
- **L1. 낱말 음절 나누기가 스크립트에 복제돼 있다** — `lines.mjs`의 `syllables`가 앱 `keyboardMatch.syllables`(NFC·공백 제거·글자 단위)를 따라 만든 것이다. 지금은 규칙이 같지만, 앱 쪽이 바뀌면 낱말 문장("학교종. 한 글자씩, 학, 교, 종.")의 파일이 조용히 안 맞게 된다. 이때는 기기 TTS로 폴백하므로 해는 없다. `keyboardMatch.ts`도 import가 없는 순수 함수라면 readText처럼 직접 import하거나, `syllables`를 readText.ts로 옮겨 한 곳에서 쓰기를 권한다.
- **L2. 첫 파일부터 실패하고 기기 TTS도 쓸 수 없으면 아무 안내 없이 조용하다** — 파일 경로에서는 `speak`가 곧바로 'spoken'을 돌려준다. 그래서 첫 파일이 안 열리고 한국어 기기 음성이 없으면, 화면에 '지금은 읽어 드릴 수 없어요'가 뜨지 않고 버튼만 원래대로 돌아간다. 자산 손상처럼 드문 경우다. 첫 문장의 로드 결과를 기다린 뒤 'spoken'을 돌려주거나, 폴백이 실패하면 읽기 실패를 알리는 콜백을 두면 된다.
- **L3. 'AI 음성' 표기 범위는 법률 레인 확인** — 위 판단대로 코드 조건은 타당하다. in-app-notices §3 4번(AI 안내)에 "읽어 주는 목소리(미리 생성 음성이 있을 때)"를 한 줄 더할지 법률 레인이 정할 것.
- **L4. 앱 크기 예산이 숫자로 정해져 있지 않다** — 런북 A13은 "기록"뿐이다. 음성 2.1MB가 처음으로 큰 자산이 되므로, 설치 크기 상한(예: 릴리스 AAB +N MB)을 정해 `synth.mjs` 설치 단계에서 넘으면 경고하게 하기를 권한다.
- **L5. 개인정보 검사의 숫자 4자리 규칙** — 회상 질문에 연도("1988년 올림픽")가 들어오면 파이프라인이 멈춘다. 막히는 쪽(안전한 쪽)이라 해는 없다. 걸리면 연도 예외 목록을 두면 된다.
- **L6. 스크립트의 Node 버전 조건** — `.ts`를 그대로 import하려면 Node 타입 지우기(22.18+/23.6+ 기본)가 필요하다. README 1단계에 최소 버전을 적는다(이번 확인은 v26.13.0, MODULE_TYPELESS 경고만 남).
