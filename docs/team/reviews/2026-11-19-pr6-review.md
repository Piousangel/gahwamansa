## M (수정 필요: M1·M2) / 해소 확인
- **M1. "연결(linked)" 정의가 Apple 정의와 다르다**(app-privacy-label.md §0). 문서는 "개인정보 보호법상 개인정보에 해당하면 연결"이라 적었는데, Apple 기준은 계정·기기·신원 등에 **연결되어 수집되는지**이다(식별자를 수집 전에 떼어 다시 잇지 않을 때만 연결 안 됨). 같은 오류가 #15·#16(Firebase 설치 ID·충돌 로그 "연결 아니오(추정)")의 조건("`setUserId` 0건이면 연결 안 됨")에 이어진다 — 설치 ID는 기기 수준 ID라 Apple 정의로는 연결로 보는 쪽이 안전하다. 고칠 방향: 정의 문장을 Apple 원문대로 바꾸고, #15·#16·진단 2행을 "연결 예"를 기본으로(연결 안 됨은 Crashlytics 설정 확인 뒤에만), #12 해시 판단은 그대로.
- **(해소 6c4f55f) 리드 위임 결정 반영.** 원래 지적: 결정이 문서에 반영되지 않았다.

- **M2. Apple 토큰 보관 문장이 설계와 어긋날 수 있다**(부록 §1-2, 라벨 i3, A-2). 4절 행은 토큰을 "계정을 지우실 때 해제 요청하는 데만 쓰고 해제되면 바로, 안 되어도 30일 안에" 지운다고 읽혀 **삭제 뒤에만** 보관하는 것처럼 보인다. Apple 해제(revoke)에는 로그인 때 받은 refresh token(또는 삭제 때 새로 받는 authorization code)이 필요하다. 로그인 때 저장해 두는 설계라면 "계정이 있는 동안 보관 + 삭제 뒤 30일 상한"이므로 4절 문장·삭제 안내 3절·i3 수집 판단이 모두 달라진다. 30일은 삭제 뒤 큐에만 해당한다. 고칠 방향: B2 설계(삭제 때 재인증으로 새 코드 받기 vs 로그인 때 저장) 중 하나를 부록에 적고 문장을 그에 맞춘다. 재인증 방식이면 30일 문장 유지, 저장 방식이면 "계정이 있는 동안"을 추가.

## 재확인 (4c75d59 대조)

### 판정: 조건부 통과 — H 없음, M 1건(방침·삭제 안내 문장 범위), L 3건. 이전 M1·M2는 해소.

### 해소 확인
- **M1(연결 정의)**: 정의가 Apple 방식(계정·기기·신원에 연결되어 수집되는지, 연결 안 됨은 수집 전 식별자 제거와 수집 뒤 재연결 금지)으로 바뀌었고 #15·#16·입력표의 기기 ID·충돌·기타 진단이 "연결 예"로 정리됐다. #17 Apple 원문 인용도 들어갔다(원문 일치 여부는 리뷰어가 따로 열어 보지 못했음 — 입력 전 대조).
- **M2(토큰 설계)**: "로그인 때 저장 안 함 → 삭제 때 재인증으로 새 authorization code → 서버가 즉시 교환·해제·폐기 → 실패 때만 큐 30일"은 Apple 해제 절차(코드 교환 → revoke)와 맞고, 30일이 큐에만 걸린다는 점이 분명해졌다. 방침 4절 행·6절 문장·삭제 안내 3절·i3·A-2·lawyer-packet이 같은 설계로 맞춰졌다. 코드가 몇 분 안에 만료되어 큐에 못 둔다는 설명(추정 표기)도 타당.
- 리드 결정(실패해도 "확인 없이 계정 지우기" 채택, 삭제를 막지 않음)은 안내 초안에 반영됐고, 삭제 안내 1절 문장과 뜻이 같다.

### 새 지적
- **M3. 공개 문장이 "항상 확인을 받고 해제한다"로 읽힌다.** 방침 6절 로그인 회사("Apple 확인을 한 번 더 받은 뒤 Apple에 연결 해제를 요청합니다")·4절 행("그 자리에서 Apple에 연결 해제를 요청하고 버립니다")·삭제 안내 3절은 확인 없이 지우기를 고르면 해제 요청이 가지 않는다는 점을 말하지 않는다. 그 경우 Apple 쪽 연결은 이용자가 직접 끊어야 한다(삭제 안내 1절과 안내 초안에만 있음). 고칠 방향: 6절·4절·3절에 "확인을 마치시면 … 요청하고, 확인 없이 지우시면 Apple 설정에서 직접 끊어 주셔야 합니다"를 한 번 넣는다(문구는 라이터).
- **L6. 메일로 받은 삭제 요청(운영자 처리)에는 재인증이 불가능** — 토큰을 저장하지 않으므로 이 경로에서는 Apple 해제를 서버가 할 수 없다. 삭제 안내 2절 Apple 가입자 항목에 "Apple 연결은 아이폰 설정에서 직접 끊어 주세요"를 같이 안내하고, 5.1.1(v)이 앱 안 삭제 요건임을 근거로 적는다(추정).
- **L7. 새 비밀값**: 코드 교환·해제에 Apple 개발자 키(.p8)·팀 ID·클라이언트 시크릿 생성이 필요하다. 내부관리계획 §3 비밀값 대장·키 교체 절차에 추가하고, B2 확인 항목에도 넣는다.
- **L8. 재인증 실패 안내 초안에 `{Apple로 로그인 메뉴 경로}` 자리표시**가 앱 문구 안에 있다. 앱 copy로 옮길 때 `{}` 0건이 되도록 출시 기기 확인(P10 계열) 뒤 확정. 연결 정의 문장 끝의 "개인정보 법령상 개인정보는 연결된 것으로 본다"는 Apple 기준이 아닌 팀 보수 기준이므로 그렇게 표기하면 혼동이 없다.
