# PR #8 리뷰 — 보안 회의 E5 백업·기기 이전 제외 (de10f96) · 2026-11-19

리뷰어: 독립 리뷰어(작성자 아님). 판정: **통과(승인 가능)**. H 0 · M 0 · L 3.

## 확인한 것
- **적용 범위**: Android 12+(API 31+)는 `dataExtractionRules`(cloud-backup·device-transfer), 11 이하는 `fullBackupContent`. 두 속성 모두 `<application>`에 연결. 31+ 에서는 fullBackupContent 가 무시되고 dataExtractionRules 가 쓰이므로 겹침·충돌 없음. minSdk 24 → 전 구간 커버.
- **allowBackup=false 와의 관계**: 유지(`android:allowBackup="false"`). false 는 클라우드 백업을 끄지만 일부 제조사 D2D 가 따르지 않을 수 있어(SUMMARY D7) 규칙은 이중 안전으로 타당. 규칙이 allowBackup 값을 바꾸지 않음.
- **XML 문법**: data-extraction-rules 의 도메인은 root·file·database·sharedpref·external·device_root·device_file·device_database·device_sharedpref — 공식 허용값과 일치(오타 0). full-backup-content 는 root·file·database·sharedpref·external 만 사용(device_* 는 12+ 전용이라 11 이하 파일에 없는 것이 맞음). 두 파일 모두 well-formed(파싱 확인). exclude-only 구조는 "기본 전체 포함 후 전부 제외"로 결과가 빈 백업.
- **매니페스트 병합**: 기존 빌드 산출물(main 체크아웃 stagingDebug/release 병합본)에서 라이브러리 유래 allowBackup·fullBackupContent·dataExtractionRules 는 없음(allowBackup="false" 한 건, node_modules 의 AndroidManifest 에도 해당 속성 0). 또한 앱 매니페스트가 라이브러리보다 우선이라 `tools:replace` 불필요.
- **url-polyfill**: package.json·package-lock 루트 의존성 모두 `4.0.0`, lock 의 node_modules 항목도 4.0.0(integrity 포함) — 일치.
- **G-25 번호**: origin/main 에 G-25 없음, 열린 PR #2·5·6·7 에 release-gates 변경 없음 → 충돌 없음. 표 형식·열 수 일치. release 병합 매니페스트 usesCleartextTraffic="false"(release)·"true"(debug)는 기존 산출물로 확인, G-25 서술과 일치.

## 한계(검증 못 한 것)
- 이 워크트리에 node_modules 가 없고 gradle 프로세스 22개·load 34 상태라 `processStagingDebugManifest` 를 새로 돌리지 않음. 새 두 속성이 병합본에 실제로 찍히는지는 G-25 A 항목(릴리스 병합 매니페스트 grep)으로 확인 필요. 에뮬레이터·실기기 미사용.

## 지적
- **L1** data_extraction_rules.xml 의 exclude 에는 path 가 없고 backup_rules.xml 은 `path="."` 가 있음. path 생략 시 도메인 전체로 동작(공식 예시도 생략 허용)하나 두 파일 표기를 맞추거나 이유를 주석에 남기면 읽기 쉬움. 동작 영향 없음.
- **L2** G-25 가 백업과 평문 통신 두 주제를 한 행에 묶음. 실패 시 원인 구분이 어려우니 다음 정리 때 분리 고려.
- **L3** 첫 빌드에서 aapt 리소스 링크가 통과하는지(`res/xml` 참조 해석)는 위 한계와 같은 이유로 미확인 — 병합 매니페스트 확인 때 함께 보면 됨.
