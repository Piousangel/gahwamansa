## 확인
- **production 번들 개발자 메뉴**: `npm run check:dev-menu` → "release 번들에 테스트 계정·이메일 없음, production 에 개발자 메뉴 없음, staging 에는 있음(작업 트리 변경 없음)" 통과. 새 코드(`devResetTodayChecked`)는 `DevMenuHost`(production 에서는 stub)에서만 import 되어 같이 빠짐.
- **거절 사유 vs 서버 판단**: 앱 판단은 `hasSession`(getSession) → `whoAmI` → 서버 순서로, 서버 사유(disabled·not_test_family)는 그대로 통과시킨다. `realApi.whoAmI` 정의와 대조:
  - 세션 없음 → whoAmI 'none' 이지만 `hasSession` 이 먼저라 signed_out 로 정확히 구분됨.
  - 연결은 됐지만 세션 만료: supabase-js `getSession` 은 갱신을 시도하고, 실패하면 세션 null → signed_out(서버도 인증 없음으로 거절하므로 일치). 네트워크 오류로 갱신·프로필 조회가 실패하면 예외 → `failed`(서버 사유로 오해하지 않음).
  - 비익명(소셜 로그인) 사용자 = 'child', 익명 + parent 프로필 없음 = 'none'(not_linked), 익명 + parent 프로필 = 'parent' → 서버 `parent_required` 조건과 같은 기준이며, 앱이 'parent' 로 통과시킨 뒤 서버가 다르게 판단하면 서버 사유가 그대로 표시됨. 앱이 서버보다 엄격하게 막는 경우(앱 not_linked 인데 서버는 통과)는 찾지 못함.
- **L3 버튼 비활성**: `who === 'child'` 일 때만 비활성, 조회 실패·미확인(null)은 활성이라 실제 누를 때 `devResetTodayChecked` 가 새로 확인함(안전한 쪽). 역할 전환은 모두 `restart()` 로 메뉴를 닫으므로 다시 열 때 재조회됨.
- 실행: `jest devResetToday.test.tsx` 10 통과, `tsc --noEmit` 오류 없음.

## 지적
- **L1** `who` 상태를 메뉴를 닫을 때 null 로 되돌리지 않아, 자녀→어르신 전환 뒤 메뉴를 다시 열면 재조회가 끝나기 전까지 이전 값('child' 안내·비활성)이 잠깐 보임. 닫을 때 또는 effect 시작 때 `setWho(null)` 권고.
- **L2** `hasSession`(getSession)과 `whoAmI`(내부에서 getSession 재호출)가 같은 세션을 두 번 읽음 — 동작상 문제 없고 개발 도구라 허용.
