### M2. 자판 열림 200%에서 '본보기 낱말 + 입력 칸 한 줄'이 폭 경계다 — 실측 캡처가 필요하다(`styles.wordCardOpen`·`inputOpen`)
- 열림 카드는 `flexDirection: 'row', flexWrap: 'wrap'`이고 입력 칸은 `flexBasis 140`이다. 낱말은 fieldInput 34 × 상한 1.5 = 51이다.
- 360dp에서 사용할 수 있는 폭(본문 여백·카드 안쪽 14×2·테두리를 뺀 값)은 약 300이다. 시드에서 가장 긴 낱말은 3음절(도시락·두레박·라디오·항아리)이고, 이때 필요한 폭은 약 145~153 + 12 + 140 ≈ **297~305**다. 경계라 줄이 바뀔 수 있다.
- 줄이 바뀌면 낱말이 칸 위로 올라간다. 그러면 r1/7 H가 지적한 현상(시스템이 입력 칸을 보이게 스크롤하면서 낱말이 잘림)이 200%에서 다시 생긴다.
- jest는 레이아웃을 계산하지 않아 `p6KeyboardOpen` 200% 테스트로는 확인되지 않는다.
- 고칠 방향:
  - 360×640 200%에서 3음절 낱말로 자판을 연 캡처를 PR에 붙인다.
  - 줄이 바뀌면 열림일 때 입력 칸 `flexBasis`를 줄이거나(예 100), 낱말을 `flexShrink` 없이 두고 입력 칸만 줄어들게 한다.
  - 콘텐츠 게이트(`content-gate.mjs`)에 낱말 최대 3음절 규칙이 있는지도 확인한다(없으면 4음절에서 확실히 줄이 바뀜).

## 확인한 것

- **넘어가기 위치**
  - 닫힘: Dock `secondary` 슬롯이다(평소 text, 두 번 시도·화면 읽기·늦은 넘어가기면 secondary 모양). Dock이 넘치면 본문 끝으로 간다(R-12).

  - 열림 200%: 카드 아래 본문이다.
  - 모두 `complete('skipped')`로 간다.
- **100%에서 입력 칸이 첫 화면에 보이는가**
  - 카드 아래 끝이 첫 화면 끝(viewport)을 넘으면 그 크기·배율(`fitKey`)에서 사진 띠를 접는다. 본보기 낱말은 카드에 남는다.
  - 접힌 뒤에도 카드가 걸치면 `foldPush`로 카드째 아래로 민다(200% 닫힘 = 스크롤로 닿음, 시안).
  - 렌더 중 `setPhotoOffFor`는 `fitKey`로 한 번만 참이 되게 막아 무한 갱신이 없다.
- **측정 이벤트**: `useFinishStep`이 `course_step_completed{step:'hangul', duration_sec, attempt_no, result}`를 보낸다. result는 '다 썼어요'·'이대로 마칠게요'·일치 뒤 '마칠게요'가 `finished`, 모든 넘어가기가 `skipped`다. 글자 내용과 맞았는지는 싣지 않는다. 저장 실패 뒤 '다시 하기'도 같은 결과를 쓴다(`lastResult`).
- **범위 밖 파일·삭제**
  - `git diff --name-status origin/main...HEAD`: 15파일, **삭제 0**. 모두 P6·Dock·Screen·문구·테스트·문서다.
  - 다만 `ui/ds/Dock.tsx`의 secondary·buttonRef 추가는 #138이 main에 넣은 것과 같은 변경이라 충돌한다(아래 L1).
- **화면 읽기**: 본보기 낱말 묶음은 '따라 쓸 낱말, {낱말}' 하나로 읽히고(`WordLine`은 숨김), 입력 칸은 라벨 + 힌트(placeholder 문구)다. 일치는 1회 알린다(R11).
