## Dialog
- **버튼 계약**: action 1 + dismiss 1, 닫는 말은 `Dismiss`(close·later·decline) 타입만 받음. danger 면 닫기가 위(주 버튼)·되돌릴 수 있으면 하는 쪽이 위. action 없으면 닫기만(주). 코드 배열 순서·kind 가 문서와 일치.
- **뒤로 가기 = 닫기**: `onRequestClose` → `onDismiss`, 단 `action.loading` 중에는 무시. **처리 중 잠금**: loading 동안 닫기 `disabled`·뒤로 무시. 밖 누르기로는 닫히지 않음(스크림에 onPress 없음).
- **두 번 누름 방지** `fired` 는 action/visible/error 가 바뀌면 풀림 — 부모가 매 렌더 `action` 객체를 새로 만들면 렌더마다 풀리지만 같은 틱 이중 호출은 막음(허용).
- **포커스·읽기**: `Modal` + `accessibilityViewIsModal`, 열리면 제목으로(`useModalFocus` onShow), 닫히면 연 버튼으로, 덮개는 `returnFocusRef=null`. 제목은 바깥 `View accessible header accessibilityLabel={title}` 하나만 읽히고 안쪽 글자는 별도 머리글 역할 없음 → 한 번만 읽음. 오류 줄은 `polite` 라이브 영역.
- **L1** `Dialog` 의 좌우 여백이 `ds.space.screenX.elder` 로 고정되어 자녀(audience child)에서도 어르신 값을 씀. 시각 차이뿐.

## 덮개 큐
- **사용자가 직접 연 대화상자는 막지 않음**: 큐는 `useCover`/`coverQueue.request` 를 거치는 덮개에만 적용되고, `Dialog` 는 `visible` 을 그대로 받으므로 버튼으로 여는 지우기 확인 등은 큐와 무관. 덮개가 떠 있을 때(active)에도 사용자 대화상자는 열림(큐가 가로채지 않음). 의도와 일치.
- **자정 경계**: 요청 시각의 KST 날짜(+9h)를 마지막으로 보인 날과 비교. 직접 실험: KST 23:59:59 에 하나 보임 → 같은 날 두 번째는 거절 → KST 00:00:01 에는 허용 — 정확.
- **저장소 오류**: `load` 실패는 null(처음)로 취급해 **보임 쪽(fail-open)**, `save` 실패는 무시. 직접 실험: 둘 다 던지면 첫 덮개 허용, 같은 실행의 두 번째는 거절(메모리 `shownDay` 로 지킴). 저장소가 계속 고장이면 매 실행 덮개 하나가 뜰 수 있으나(하루 하나 규칙을 못 지킴) 앱 동작을 막지는 않음 — **L2** 로 기록.
- **M1 첫 읽기 전 동시 요청이 둘 다 허용됨(경합)**: `request` 가 `active !== null || (await day()) === today` 에서 `active` 를 **await 전에** 읽고, 첫 `day()` 가 끝나기 전에 두 번째 요청도 같은 `load` 를 기다려 둘 다 `null` 을 받아 둘 다 `active = id` 로 진행. 직접 재현(`Promise.all([request('a'), request('b')])` → 둘 다 `true`) — 앱 시작 때 알림 안내와 새 연결 안내처럼 덮개 둘이 동시에 청하면 "겹쳐 뜨지 않음·하루 하나"가 깨짐. 권고: 큐를 Promise 체인으로 직렬화하거나 `await day()` 뒤에 `active` 를 다시 검사하고 `shownDay === today` 도 다시 확인, 또는 `active = id` 를 await 전에 선점. 동시 요청 단위 테스트 추가.
- **L3** `useCover` 는 `asked` ref 로 한 번만 청하고 cleanup 이 `alive=false` 로 만든 뒤 재실행에서는 early return — React StrictMode(개발) 이중 effect 에서는 첫 요청 결과가 버려져 덮개가 안 뜨고 `active` 만 잡힐 수 있음. 운영엔 영향 없음.
- AppRoot 연결: `configureCoverQueue({load, save})` 를 모듈 최상위에서 호출, `prefs()` 는 호출 시점에 평가(람다)라 테스트의 `setPrefsForTest` 와 호환. prefs `coverDay`/`setCoverDay` 는 저장소 오류를 삼킴(동작 확인).
