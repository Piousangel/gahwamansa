## 확인
- **직렬화**: `request` 가 `tail.then(run, run)` 으로 요청을 한 줄에 세워 앞 요청이 끝나(load·save 포함)야 다음이 시작 → 첫 읽기 전 동시 요청이 둘 다 `null` 을 보던 경합이 사라짐. `tail = p.catch(() => {})` 라 한 요청의 실패가 뒤를 막지 않음. 같은 id 의 동시 두 번은 둘 다 true(같은 덮개). `release` 는 줄 밖(동기)이라 순서 문제 없음.
- **수정 전 코드에서 실패하는지**: origin/main 의 `coverQueue.ts` 로 되돌려 같은 테스트를 돌림 → "M1 동시 두 덮개 하나만"과 "같은 덮개 두 번"이 **둘 다 실패**(2 failed, 11 passed), 수정본에서는 통과. 첫 테스트는 `load` 를 게이트로 막았다가 동시에 풀어 두 읽기가 같은 순간에 끝나는 최악 경우를 만들어 재현력이 있음.
- **fail-open**: load·save 모두 거절돼도 첫 덮개는 허락(true), 같은 실행의 두 번째는 거절(메모리 `shownDay`), 앱을 다시 켜면(새 큐) 또 하나 — 의도(영영 막지 않음)대로이며 주석·테스트로 고정. 다만 이 테스트는 수정 전 코드에서도 통과하는 특성 고정(결함 재현 아님).
- **StrictMode**: `asked` ref 를 없애 effect 가 다시 돌면 다시 청함(같은 id 가 이미 떠 있으면 `active===id` 로 true). 이중 effect 에서 첫 요청이 버려져도 두 번째 요청이 보임을 만든다.
- **B7 목록 추가분**: 연결 단계 `rate_limited` 패널(뒤로 바·Dock 모두 '번호 쓰기로' = 중복), 확인 단계 `rate_limited`(뒤로 바 '처음으로'·Dock '번호 쓰기로' = **중복 아님** 확인), P13 설정(둘 다 '오늘 코스로' = 중복) — 앞선 #144·#149 리뷰의 항목과 일치, 세 테스트 통과. `beforeAll(warmAppRoot)` 도 적용(#149 L2).
