## L4 단언 분리 — 새 단언이 중복 가족을 잡는가
- **이전 단언이 늘 통과한 이유**: `(select count(*) … where created_by = 자녀) + (create_family() ->> 'family_id' is not null)::int = 2` 는 한 문장이라 count 부분집합의 스냅샷이 문장 시작 시점에 고정되어 같은 문장 안 `create_family()` 가 새로 넣은 가족이 보이지 않았다. 기준 가족 1 + 불리언 1 = 2 가 중복 여부와 무관하게 성립.
- **새 단언**: `select ok((create_family() ->> 'family_id') is not null)` 다음 **별도 문장**에서 `count(*) … created_by = 'd0…c1'` 가 `1` 이어야 통과. 호출이 가족을 하나 더 만들면(예: 재시도 분기가 빠져 families insert 만 하고 기존 프로필 때문에 값을 돌려주는 변형) 다음 문장의 스냅샷에 보여 `2` 로 실패 → 이제 중복을 잡는다. 예외가 나는 옛 동작(0003 의 `already_has_profile`)도 첫 문장이 오류로 실패. plan 14→15 는 문장 1개가 2개로 늘어난 것과 일치.
- **L1(증거)** PR 본문에는 "15/15 ok"만 있고 **고친 단언이 실제로 실패하는 것을 보인 증거(변형 실행)는 없다**. 위 논리로 타당하나 이 PR 의 목적이 '헛통과 수정'이므로, 재시도 분기를 임시로 `families` insert 만 하도록 바꿔 새 단언이 실패하는 로그 한 줄을 PR 본문에 남기면 완결(롤백 트랜잭션에서 가능).
